# Issue 738 WebUI regression repair plan

**Goal:** Satisfy all 17 requirements in https://github.com/Sakura520222/Sakura-AI/issues/738 on a feature branch based on develop.

**Architecture:** Retain the existing typed API, authenticated user scopes, configuration revision/runtime reconciliation, Activity artifact authorization and updater lifecycle. Repair each subsystem independently, with behavior regressions before fixes and combined frontend/backend verification afterwards. No new dependencies or schema migration is planned.

**Spec:** Issue #738 and its acceptance checklist; existing repository AGENTS.md contracts apply.

## Independent implementation units

- [x] P0: Test A/B GitHub identity, installation and repository isolation and ordinary-user community management denial. Scope authorization query keys by authenticated user, cancel/clear data on session changes. Expose `pr_number` and construct PR links only from valid repository identity and number, preserving `pr_id`.
- [x] P1 AI: Exercise saved binding changes through the existing runtime/client cache, account disable/delete and fallback ordering. Make next-call configuration current, explicit ordering authoritative and candidate limits visible without silently truncating the default chain. Add fallback drag reorder with keyboard controls; replace manual model identity inputs with enabled account/model selection, retaining provider/model capability identity and dirty-state protection.
- [x] P1 Activity: Render authorized normal messages immediately. Include and pair tool calls/results, use bounded JSON/Markdown/code presentation with short content visible, long content expandable/copyable and explicit permission/missing/error states. Keep protected artifact fetches behind the current backend ACL.
- [x] P2 Settings/community: Show every permitted group and advanced field continuously with search and dirty/save/reset behavior intact. Separate community discovery, personal repository dialog and administrator management; remove business-page global toggle, add management totals/search/filter/sort/pagination and responsive cards with expandable summaries.
- [x] P2 Versions/navigation: Share update check cache/in-flight work and preserve last-known-good on failure; expose last/next check and errors. Test lifecycle in supported deployment modes. Default version browser to running build channel, inline release notes, display complete running build provenance, current version/update state in admin header, discoverable existing restart action, distinct Star icon.
- [x] Integration: Synchronize zh-CN/en catalogs and generated API contracts, document behavior and acceptance evidence. Run Python regressions, frontend unit tests, TypeScript/production build, browser suite, Ruff, translation checks and diff whitespace checks; inspect changed pages at desktop/mobile sizes. Review against all acceptance items and repair any gaps.

## Verification strategy

For each behavioral boundary: add a failing regression, confirm the expected failure, implement the root fix, then run the relevant existing suite. Use mocked providers/gateways and browser API fixtures; never production credentials or recipients. Review cross-module changes (configuration/runtime, bootstrap/header, auth/cache and schemas/generated types) centrally. Keep work in reviewable subsystem groups and do not publish or merge without an explicit request.
