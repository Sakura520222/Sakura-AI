# 审查检查清单

## 1. 基础检查（必须完成）
- [ ] **错误处理检查**：所有`except Exception`必须记录日志
- [ ] **配置检查**：新增配置字段必须与settings.py默认值对比
- [ ] **安全检查**：所有JSON API端点必须使用CSRF依赖
- [ ] **i18n检查**：所有用户可见字符串必须使用翻译键
- [ ] **数据库检查**：新增DB模型的datetime字段必须使用datetime.now(timezone.utc)

## 2. 配置管理检查
- [ ] **配置默认值唯一性**：检查是否在config.py中唯一声明
- [ ] **配置范围校验**：整数配置必须同时校验类型+范围+物理上限
- [ ] **配置迁移完整性**：输出迁移完整性检查表
- [ ] **配置缓存失效**：配置更新操作必须触发缓存失效验证
- [ ] **配置对称性**：新增API端点必须同步检查动态配置的写入路径、缓存失效和默认值兼容性

## 3. 代码质量检查
- [ ] **路径规范化**：禁止使用lstrip/rstrip移除前缀，必须使用removeprefix
- [ ] **重复逻辑检测**：扫描两个及以上文件中>10行相同的逻辑
- [ ] **函数副作用标注**：函数修改外部状态时必须在docstring中用⚠️标注
- [ ] **公共函数docstring**：新增公共函数必须包含docstring说明输入输出边界

## 4. 异步与并发检查
- [ ] **异步调用统一性**：同一模块内禁止混合create_task与await
- [ ] **后台任务生命周期**：asyncio.create_task创建的后台任务必须在服务shutdown时有机会完成
- [ ] **线程安全性**：同步函数中使用get_running_loop().create_task时必须评估线程安全性

## 5. 前端与模板检查
- [ ] **JS上下文转义**：强制使用|tojson进行JS上下文转义
- [ ] **SVG可访问性**：内联SVG装饰图标必须添加aria-hidden="true" + focusable="false"
- [ ] **WebUI四一致**：侧边栏链接、表单action、JS fetch、重定向URL与路由前缀一致
- [ ] **fetch响应状态检查**：所有fetch必须检查!resp.ok

## 6. 审查流程检查
- [ ] **历史问题追踪**：未修复历史问题必须关联issue号
- [ ] **增量审查输出**：必须输出已检查的规则清单、历史未解决问题清单、未直接测试但依赖的调用链
- [ ] **连续未修复升温**：连续3轮未根治问题自动升温为major→critical

## 7. 测试检查
- [ ] **缓存清理测试**：测试中修改全局缓存必须使用fixture或finally确保清理
- [ ] **Fallback路径测试**：新增的fallback路径必须有集成测试验证
- [ ] **测试断言常量化**：测试断言必须引用生产常量，禁止硬编码数值

## 8. 日志与可观测性检查
- [ ] **异常日志记录**：新增异常处理器必须记录warn级别日志
- [ ] **配置降级日志**：配置降级路径必须有warning日志
- [ ] **日志风格规范**：使用{}占位符风格，禁止f-string

## 9. 安全检查
- [ ] **敏感字段加密**：明文敏感字段存储必须加密
- [ ] **Shell命令白名单**：禁止前缀匹配，必须精确匹配
- [ ] **CSRF检查**：所有JSON API端点（除公开只读）必须显式使用CSRF

## 10. 性能检查
- [ ] **N+1查询评估**：批量操作需评估N+1查询在实际数据量下的表现
- [ ] **热路径配置查询**：在循环或高频调用的位置查询用户配置时，必须评估DB查询频率

## 11. 增量审查专项检查
- [ ] **全链路扫描清单**：配置保存→缓存失效→读取路径
- [ ] **PR描述完整性**：必须包含配置迁移完整性检查表
- [ ] **变更文件一致性**：PR描述与变更文件必须一致
- [ ] **模板影响范围**：变更模板文件时，输出该模板被哪些路由/端点使用的清单

## 12. 重大问题升级机制
- [ ] **连续未修复处理**：第1轮未修复评估降级，第2轮强制降级，第3轮强制归档
- [ ] **major问题关联issue**：未修复的major问题必须关联issue编号，否则阻断合并
- [ ] **critical问题自动生成issue**：第4轮未修复自动生成issue

## 13. 大型重构PR审查
- [ ] **删除完整性验证**：必须验证所有被删除公共符号在非测试代码中已无引用
- [ ] **配置同步清理**：验证相关配置（如UI、i18n键）已同步清理
- [ ] **死代码扫描**：重构PR合并前必须通过工具扫描确保未引入新死代码
- [ ] **重构后"残留"审查**：从"新增了什么"转向"删除得是否干净"

## 14. 增量审查深度策略
- [ ] **全链路扫描清单**：配置保存→缓存失效→读取路径
- [ ] **关联扫描重要性**：检查配置与现有其他策略配置的交互影响
- [ ] **增量审查专项输出**：已检查的规则清单、历史未解决问题清单、未直接测试但依赖的调用链

## 15. 上下文感知的严重性判断
- [ ] **问题影响评估原则**：评估问题影响时需紧密结PR的上下文
- [ ] **历史遗留问题风险再评估**：涉及数据一致性的问题必须评估现实风险
- [ ] **严重程度一致性**：同一问题在报告各处的严重程度标记必须一致

## 16. 防御性代码审查
- [ ] **镜像一致性原则**：对称结构的防御逻辑必须镜像检查边界条件
- [ ] **资源清理时序分析**：模拟异常抛出时try/finally的执行顺序
- [ ] **大小写归一化的"贯穿性"原则**：追踪归一化变量的所有使用点
