# 代码审查流程经验教训

## 1. 警惕自动化工具的"高分盲区"
- **高分≠完美**：高评分的审查结论极易导致审查者放松警惕
- **主动寻找盲区**：必须将"9/10 评分"本身视为一个需要警惕的信号，主动去寻找自动化工具可能未覆盖的盲区（如架构、安全、可维护性）

## 2. 大范围变更的"全局-局部"审查节奏
- **先建立全局认知**：面对全量审查，应首先快速理解变更的**整体意图和架构影响**
- **再深入细节**：然后再深入检查具体实现细节
- **避免陷入 diff 汪洋**：避免一开始就陷入 diff 的汪洋，忽略了变更的整体图景

## 3. 性能建议需与架构决策结合
- **探讨契合度**：在提出性能优化建议（如缓存）时，可以简要探讨该建议与现有架构（如热更新机制）的契合度
