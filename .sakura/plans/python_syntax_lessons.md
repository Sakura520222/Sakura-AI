# Python 语法一致性经验教训

## 核心问题模式

### 基础语法错误的放射性影响
- **现象**：`except Exception, e:` 语法错误阻断整个模块导入链
- **根因**：复制粘贴代码时带入 Python 2 语法
- **影响**：核心 AI 功能完全不可用

### 新引入代码中的废弃语法
- **问题**：新代码中出现 `print` 语句、`xrange` 等 Python 2 语法
- **严重程度**：Critical
- **根因**：开发者对 Python 3 语法不够熟悉

### 测试通过不等于代码正确
- **问题**：语法错误导致测试框架无法加载被测模块
- **误解**：测试通过被认为证明代码正确
- **根因**：测试环境与代码质量判断混淆

## 强制规则

### 语法检查
- **禁止 Python 2 语法**：
  - `print` 语句 → 必须使用 `print()` 函数
  - `except Exception, e:` → 必须使用 `as`
  - 旧式字符串格式化 → 使用 f-string 或 `.format()`
  - `xrange` → 使用 `range()`
  - `raw_input` → 使用 `input()`

### 导入链验证
- **基础模块验证**：基础模块必须能被正常导入
- **依赖验证**：1-2 个直接依赖模块必须能正常导入
- **循环导入**：检查是否存在循环导入

### 测试有效性
- **环境一致性**：测试环境 Python 版本与生产环境一致
- **模块加载**：验证测试是否真的加载了被测模块
- **语法错误隔离**：语法错误不应导致测试框架失败

## 审查优先级

**基础语法正确性优先于业务逻辑审查**

基础语法错误的严重程度高于业务逻辑错误，因为前者会导致代码完全无法运行。

## 经验总结

1. **简单语法错误可能阻断整个系统**：基础模块的语法错误会产生放射性影响
2. **新引入代码需要额外警惕**：容易带入旧代码片段的语法问题
3. **测试环境验证很重要**：语法错误可能让测试框架本身失败
4. **自动化检查需要人工复核**：依赖项目自动修复工具时必须人工复核
