# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈

Sakura AI Reviewer 是一款基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。

- **后端语言**：Python 3.11+
- **Web 框架**：FastAPI
- **前端界面**：HTML（自包含 WebUI）、Alpine.js、HTMX
- **数据库**：MySQL、Redis
- **AI 与检索**：LLM API、RAG 向量检索
- **基础设施**：Docker、Docker Compose
- **代码规范**：Ruff
- **集成渠道**：GitHub App、Telegram Bot

## 2. 架构设计与关键决策

- **分层架构**：API 层、服务层、数据访问层分离，路由层禁止直接操作数据库
- **集中式结果解析器**：AI 输出清洗收敛于 `result_parser.py`
- **配置三层穿透**：Settings → yaml_config → 硬编码默认值
- **动态配置系统**：`get_dynamic_config` 统一接口，处理 None/非法值降级并记录 warn
- **工具插件化架构**：统一工具注册与调用
- **全局异常处理器不得引用业务依赖**
- **i18n 门面模式**：`render_template` 统一注入 `_()` 和 `lang`
- **服务层自治事务模式**：服务方法内部自行 commit
- **幂等共享信号模式**：取消任务时多排队任务共享 asyncio.Event
- **批量操作 savepoint 模式**：循环中使用 `begin_nested()` 替代全局 rollback
- **权限策略单一真实源**：所有角色判断调用策略函数
- **内存回退字典必须实现大小/TTL 限制**
- **安全操作必须记录审计日志**
- **外部可见链接必须通过统一链接服务生成**（major）
- **显式标记优于路径推断**：使用 `mark_webui_request` + `request.state.is_webui` 替代排除法分类

## 3. 已知问题和注意事项

- **错误处理不统一**：新代码应倾向显式错误传播
- **`except Exception` 无日志视为静默失败**（major）
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **版本号多源硬编码**：main.py、auth.py、init.sql 三处独立
- **i18n 翻译覆盖不完整**：toast 消息、API 错误响应易硬编码
- **中文 Token 估算缺陷**：`len(content)//4` 是近似值
- **字符串前缀移除禁止使用 `lstrip`**：必须使用 `removeprefix`
- **整数配置必须同时校验类型 + 范围，且上限不超过消费方物理上限**（major）
- **动态配置读取调用方须处理 None/非法值并记录 warning**（major）
- **配置迁移必须输出“迁移完整性检查表”及“消费方隐式上限验证结果”**
- **禁止路由层裸写 `int(request.form.get(...))`**
- **配置默认值必须唯一声明于 `config.py`**（major）
- **Shell 命令白名单匹配禁止使用前缀匹配**（major）
- **BackgroundTasks 不适合长时间运行任务**（major）
- **事务外的外部写入必须支持补偿或异步**（major）
- **新增公共功能模块必须至少有一处调用路径**（major）
- **敏感字段禁止传递到模板上下文**（major）
- **fetch 响应状态检查**：所有 `fetch` 必须检查 `!resp.ok`（连续出现升 major）
- **批量保存配置必须事务回滚**（major）
- **惰性资源重建函数（如 `reset_xxx_semaphore`）必须实现幂等性和并发安全性**（major）
- **启动阶段依赖动态配置的模块必须声明配置已加载标志或重试机制**（major）
- **模板JS插值安全规范**：强制使用`|tojson`进行JS上下文转义，禁止仅用`|e`
- **批量操作返回值规范**：必须返回结构化结果（如`{"success": int, "skipped": List[str]}`），禁止仅返回计数
- **服务层异常处理规范**：静默异常必须记录debug日志，并向调用方返回失败详情
- **配置对称性检查**：新增API端点必须同步检查动态配置的写入路径、缓存失效和默认值兼容性

## 4. 审查中发现的重要模式

- **微小变更审查价值**：行数少 ≠ 风险低
- **增量隧道视野**：对新增字段完整生命周期缺乏追踪
- **“删除优于修复”模式**：冗余功能删除比修补安全
- **连续 3 轮未根治问题自动升温**：升级为 major→critical，第 4 轮自动生成 issue
- **配置与消费的对称性审查**：每看到一个新增配置字段，强制扫描其唯一读取位置
- **配置迁移的“对称性三件套”**：写入路径 → 缓存失效 → 默认值对比
- **CSRF + JSON API 组合**：成为固定审查项
- **“双防线”依赖惯性**：前后端同时校验易在重构中被部分删除
- **配置解析函数必须记录 warning 日志**
- **测试中修改全局缓存必须使用 fixture 或 finally 确保清理**（major）
- **双路径不一致**：API 与 WebUI 新增功能必须对比限流/CSRF/错误处理
- **操作顺序审查优先级提高**：Redis + DB 操作必须检查补偿逻辑
- **异步调用方式必须统一**：同一模块内禁止混合 `create_task` 与 `await`
- **函数副作用必须在 docstring 中用 `⚠️` 标注**
- **模板中内联 SVG 装饰图标必须添加 `aria-hidden="true"` + `focusable="false"`
- **路径重构必须输出所有 URL 字符串的位置清单**
- **禁止使用排除法分类请求路径**
- **新增 WebUI 模块必须检查“四一致”**：侧边栏链接、表单 action、JS fetch、重定向 URL
- **`or` 语义替换必须评估该字段的业务空值语义**（空字符串、0、false）
- **审查中的“观察点”必须关联 issue 号**
- **批量操作必须验证部分失败处理**：尤其是涉及数据库删除/更新的操作
- **模板安全审查需系统化**：JS上下文转义是常见漏洞，应作为固定检查项
- **服务层契约必须明确**：返回值语义变更时，强制扫描所有调用方
- **性能影响评估**：批量操作需评估N+1查询在实际数据量下的表现，即使当前数据量小
- **XSS防护**：`|tojson` + 单引号HTML属性是安全组合，应推广为标准实践
- **异常处理**：静默吞没异常是技术债源头，必须记录日志并反馈调用方
- **配置对称性**：新增功能时，配置系统的写入/读取/失效必须同步检查，避免幽灵配置
- **侧边栏“四一致”检查扩展**：除链接、action、fetch、重定向外，增加“active_page 标识符唯一性”检查
- **模板变量命名规范**：统一 active_page 前缀（如 `billing_admin_*`）
- **路由与模板的 active_page 值必须通过常量定义**，避免硬编码字符串分散在多处

## 5. 团队约定和规范

### 审查硬规则（major/critical）
- 三问法：major 须内联“用户影响/利用条件/现有缓解”
- `except Exception` 必须记录日志
- i18n 扫描完整性：全覆盖，禁止硬编码
- 所有用户输入验证端点必须有速率限制
- 所有 JSON API 端点（除公开只读）必须显式使用 CSRF
- 整数配置必须同时校验类型 + 范围 + 消费方物理上限
- 动态配置读取调用方须处理 None/非法值并记录 warn
- Shell 命令白名单精确匹配
- BackgroundTasks 长任务风险评估
- 测试缓存清理必须异常安全
- **未修复历史问题必须关联 issue 号**
- **配置保存端点必须原子化**（major）
- **新增配置 key 必须与 settings.py 默认值对比**（major）
- **新增配置写入/读取/测试连接端点必须有集成测试**（major）
- **增量审查必须扫描 tests/ 目录中的旧符号引用**（major）
- **路由级依赖与异常处理器的 state 字段契约必须在 PR 中明确**（major）

### suggestion 疲劳归档协议
第 1 轮未修复：评估降级 | 第 2 轮未修复：强制降级 | 第 3 轮未修复：强制归档

### 增量审查补充规范
- 必须输出“已检查的规则清单”（最少 10 条）
- 必须输出“历史未解决问题清单并升温”
- 必须输出“未直接测试但依赖的调用链”
- 配置迁移 PR 必须输出“迁移完整性检查表”及“消费方隐式上限验证”
- 新增配置字段检查表：唯一性、默认值兼容性、所有读取路径的 None 处理、写入路径与缓存失效成对
- 测试断言必须引用生产常量，禁止硬编码
- 变更模板文件时，必须输出该模板被哪些路由/端点使用的清单
- **公共函数从私有升级时必须补充 docstring**（minor）
- **增量审查必须输出旧逻辑约束清单与新逻辑保留情况对比表**

### 常量与配置规范
- 常量定义位置与语义保持一致
- 配置更新操作必须触发缓存失效验证
- 工具函数必须位于约定公共模块（utils/、core/）

### 日志与可观测性
- 新增异常处理器必须记录 warn 级别日志
- 配置降级路径必须有 warning 日志
