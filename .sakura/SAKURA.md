# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈

Sakura AI Reviewer 是一款基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。

- **后端语言**：Python 3.11+
- **Web 框架**：FastAPI
- **前端界面**：HTML（自包含 WebUI）、Alpine.js、HTMX
- **数据库**：MySQL、Redis
- **AI 与检索**：LLM API、RAG 向量检索
- **基础设施**：Docker、Docker Compose

## 2. 架构设计与关键决策

- **分层架构**：API 层、服务层、数据访问层分离
- **配置三层穿透**：Settings → yaml_config → 硬编码默认值
- **动态配置系统**：统一接口处理 None/非法值降级并记录 warn
- **工具插件化架构**：统一工具注册与调用
- **i18n 门面模式**：统一注入 `_()` 和 `lang`
- **服务层自治事务模式**：服务方法内部自行 commit

## 3. 已知问题和注意事项

- **错误处理不统一**：新代码应倾向显式错误传播
- **`except Exception` 无日志视为静默失败**（major）
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **整数配置必须同时校验类型 + 范围**（major）
- **未修复历史问题必须关联 issue 号**

## 4. 审查中发现的重要模式

- **微小变更审查价值**：行数少 ≠ 风险低
- **"删除优于修复"模式**：冗余功能删除比修补安全
- **连续 3 轮未根治问题自动升温**：升级为 major→critical，第 4 轮自动生成 issue
- **包装函数调用一致性检查**：生产代码必须通过包装函数调用测试替换函数
- **异步路由中的同步I/O阻塞**：async 路由中同步调用必须使用 `asyncio.to_thread()` 包装
- **i18n 键完整性**：新增 UI 元素必须同步更新翻译文件
- **全量重审价值**：功能重构后全量审查能发现系统性、跨文件问题

## 5. 团队约定和规范

### 审查硬规则（major/critical）
- **未修复历史问题必须关联 issue 号**
- **包装函数调用一致性**：生产代码必须通过包装函数调用
- **异步路由同步I/O阻塞**：async 路由中同步调用必须包装
- **i18n 键完整性检查**：新增 UI 元素必须同步更新翻译文件

### 增量审查补充规范
- 必须输出"已检查的规则清单"（最少 10 条）
- 必须输出"历史未解决问题清单并升温"

### 代码结构规范
- **静态方法调用风格统一**：纯函数应使用`ClassName.method()`
- **公共工具函数抽取强制化**：相同逻辑在≥2个文件中出现且行数>10时必须抽取
