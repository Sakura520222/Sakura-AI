# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈
基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人，具备跨文件依赖理解、全仓库扫描和项目记忆能力。
- **技术栈**：Python 3.11+ / FastAPI / MySQL & Redis / LLM & RAG / Docker / GitHub App & Telegram Bot

## 2. 架构设计与关键决策
采用后端分层架构，前后端同仓：
- `backend/api/`：路由；`core/`：配置与依赖注入；`models/`：数据结构
- `backend/services/`：核心业务（AI审查、记忆系统、RAG等）
- `backend/workers/`：异步任务；`telegram/`：Bot交互；`webui/`：前端
- `config/`：外部化配置（YAML）
- **关键决策**：业务规则 YAML 外部化热更新；耗时任务 Worker 隔离；容器化交付。

## 3. 已知问题与注意事项
### PR190 遗留缺陷（未闭环）

- **`github_write_service.py:28-31`**：单例实现线程安全问题

- **截断安全网移除**：移除硬兜底改靠 Prompt 约束，属防御层静默退化

### 安全敏感点
- 路径处理禁用字符串检查（如 `if "../" in path`）、禁用 `PurePosixPath`（不解析符号链接），必须用 `pathlib.Path.resolve()` + 前缀验证，建议升级为 AST 硬性拦截
- 写操作服务必须审查权限边界与异常链路，安全/并发相关问题禁止降级为 suggestion

## 4. 审查发现的重要模式
- **数据契约不严格**：跨模块混用 `dict` 与对象，缺类型注解，易致 `AttributeError`
- **Prompt 防御性编码**：将 `{xxx}` 占位符转为自然语言指令，消除 LLM 对元字符歧义
- **对称结构一致性缺失**：A/B 对称逻辑边界条件不对等（正则 lookahead 不对称、`lower()` 归一化未贯穿）
- **防御性编程表面化**：用高级 API 但不理解底层，产生虚假安全感
- **LLM 信任钟摆**：在"不信任"（三层正则兜底）与"过度信任"（全靠 Prompt）间摆动，正确位置在中间
- **净减代码蜜糖效应**：减少代码触发质量提升直觉，需区分减少的是业务逻辑（好）还是防御代码（危险）
- **双服务脆弱性叠加**：上游部分成功 + 下游非原子提交 = 数据不一致最短路径，增量单文件视野无法捕捉
- **`asyncio.gather` 暗礁**：默认任一异常取消全部，与"并行=独立"直觉相悖；重构为并行时必须审查失败模式是否劣化
- **增量审查陷阱**：隧道视野、零评论高分走过场、上下文浪费、quick 退化为风格检查器、创可贴式修复、凑数拔高严重度

## 5. 团队约定与规范
### 代码规范
- 跨模块复杂数据禁止裸 `dict`，必须用 `Pydantic`/`dataclass`/`TypedDict`
- 文件路径操作必须使用 `pathlib`，安全场景严格禁止 `Pure` 系列路径
- 同一语义数值字面量≥2次必须提取为常量（`constants.py`），禁止魔法数字
- 延迟导入只有确认无循环导入且无性能意图时才可标记为问题
- 双数据源必须标注过渡期和收敛计划
- 移除防御性代码（截断/校验/兜底）必须有等价替代或显式风险声明（`# SAFETY: ...`）

### 审查规则（按优先级）
| 规则 | 级别 | 触发条件 |
|------|------|----------|
| PR级阻断表强制 | P0 | 遗留 critical 每次必须出现，状态只可更新不可删除 |
| quick approve 检查 | P0 | approve 前必须确认遗留 critical 为 0，否则自动降级 |
| 历史阻断机制 | P0 | 未闭环 error/critical 时增量审查禁止 approve |
| 强制拦截词 | P0 | PR 含"非原子性/线程安全/KeyError"时锁定 approve 权限 |
| 遗留降级禁令 | P0 | 禁止 Critical/Error 降级为 Suggestion |
| 评分评论支撑 | P0 | 评分必须有评论，9分以上需说明优点 |
| PR规模策略校验 | P0 | 文件>10 禁止 quick 策略 |
| 严重度三问法 | P1 | 标记 major 前：①实际bug？②运行时错误？③安全风险？全否降级 |
| 并行化失败审查 | P1 | 串行改 `gather` 必须检查 `return_exceptions`、部分成功处理、失败模式对比 |
| 防御代码移除审查 | P1 | 移除截断/校验/兜底需确认等价替代或风险声明 |
| 跨服务链路推演 | P1 | 变更输出是已知问题服务输入时，必须端到端失败推演 |
| 路径安全硬拦截 | P1 | 涉及路径拼接且无 `.resolve()` 直接 error |
| 增量上下文引用 | P1 | PR 含历史审查上下文时必须输出问题状态更新表 |
