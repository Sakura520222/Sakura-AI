# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈

Sakura AI Reviewer 是一款基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。

- **后端语言**：Python 3.11+
- **Web 框架**：FastAPI
- **前端界面**：HTML（自包含 WebUI）、Alpine.js、HTMX
- **数据库**：MySQL、Redis
- **AI 与检索**：LLM API、RAG 向量检索
- **基础设施**：Docker、Docker Compose
- **代码规范**：Ruff
- **集成渠道**：GitHub App、Telegram Bot

## 2. 架构设计与关键决策

- **分层架构**：API 层、服务层、数据访问层分离
- **服务层职责边界**：`comment_service` 为行内评论渲染唯一入口
- **集中式结果解析器**：AI 输出清洗收敛于 `result_parser.py`
- **配置三层穿透**：Settings → yaml_config → 硬编码默认值
- **降级标志传递模式**：布尔标志沿调用链传递失败语义
- **fallback 链路统一**：空字符串 → settings → yaml → 硬编码
- **fire-and-forget 范式**：`create_task` + `add_done_callback(discard)`
- **工具插件化架构**：统一工具注册与调用
- **全局异常处理器不得引用业务依赖**：不解析 token、不查数据库
- **版本号多源硬编码**：main.py、auth.py、init.sql 三处独立，无双向同步
- **配置全链路模式**：新增配置字段须在各层同步添加
- **服务层薄化演进**：逐步移除配置读取逻辑
- **i18n 门面模式**：`render_template` 统一注入 `_()` 和 `lang`
- **配置热更新双接口**：`get_config()` (异步) + `get_cached_config()` (同步)
- **翻译键前缀约定**：`toast.*`、`settings.*`、`register.*` 语义清晰
- **工具循环复用**：`_run_tool_loop` 消除重复代码
- **降级链路闭环**：`BadRequestError` → 移除 diff → 按需工具获取 → 对话压缩
- **降级梯度设计**：首次超长 → 精简模式（移除 diff + 按需工具）；多轮超长 → 压缩历史

## 3. 已知问题和注意事项

- **错误处理不统一**：新代码应倾向显式错误传播
- **静默降级缺乏可见性**：降级路径须产生 warning 日志
- **`except Exception` 无日志视为静默失败**
- **轮询缺少强制失败出口**：启动循环须超时检查 + exit≠0
- **外部依赖失败必须显式降级**：返回 None 或抛异常，禁止空列表
- **配置解析红线**：禁止 `.replace().split()` 解析标签列表
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **双重格式化陷阱**：下游再次调用 format 会破坏结构
- **测试隐式全局状态**：须显式 mock
- **版本号漂移风险**：Python + SQL 多语言硬编码
- **CHANGELOG 文化缺失**：minor/major 升级建议强制起草条目
- **可变单例并发安全**：`@lru_cache` + `setattr` 修改须加锁或上下文管理器
- **配置开关与既有数据库兼容性**：新增字段后旧记录的默认行为须显式处理
- **死代码保留无注释**：未调用的条件分支须注释预期调用者
- **跨模块导入删除风险**：删除导入前必须全仓库引用搜索
- **动画性能风险**：大量飘落花瓣可能导致低端设备重绘问题
- **无障碍一致性传播遗漏**：`prefers-reduced-motion` 须同步所有页面
- **毛玻璃深色模式对比度风险**：`bg-white/70` 在深色模式下文字对比度可能不足
- **响应式窄屏布局溢出**：新增大内边距可能导致横向滚动
- **PR 描述与变更内容严重不符**：须作为 critical 阻断合并
- **i18n 翻译覆盖不完整**：toast 消息、API 错误响应、JS 动态文本易硬编码
- **重复工具函数散落**：`_t()` 在多个服务中重复
- **`document.write` 用于动态内容注入**：应改用 `x-text`
- **翻译键语义错误**：键名与显示内容不匹配
- **样式副本漂移风险**：多处 `.glass` 须标注源位置
- **临时选择器无到期标注**：须注明预期移除版本
- **异常消息透传风险**：直接向用户展示 `str(e)` 前须评估
- **动态配置读取失败无可观测性**：`get_cached_config` 返回 `None` 时须记录日志
- **i18n 增量审查盲区**：PR 声明 i18n 时必须扫描 JS 和 `toast_redirect` 调用点
- **异常类缺少 user-facing message 属性**：自定义异常必须调用 i18n 函数，禁止硬编码字符串
- **延迟导入滥用**：函数体内导入未注释循环引用原因
- **空审查结果不得通过**：主要评论为空且变更文件数 ≥5 时自动拒绝
- **启发式逻辑代码嗅探**：形如 `if condition and heuristic` 须注释输入边界和 fallback
- **模板标点硬编码惯性**：句号、冒号等须纳入翻译值
- **降级后二次超长风险**：单文件 diff 仍可能超长，须有二次降级策略
- **实例级可变状态并发污染**：请求级数据不应存储为实例属性；使用 `set_*` 方法须实现上下文管理器或每次新建
- **中文 Token 估算缺陷**：`len(content)//4` 是近似值，建议引入 tiktoken
- **工具循环副作用未标注**：修改传入列表/字典的公共方法须在 docstring 中用 `⚠️ 副作用` 明确标注

## 4. 审查中发现的重要模式

- **微小变更审查价值**：行数少 ≠ 风险低
- **增量隧道视野**：对新增字段完整生命周期缺乏追踪
- **suggestion 疲劳归档机制**：第 2 轮未修复降级，第 3 轮强制归档
- **增量审查两重责任**：追踪历史修复 + 覆盖本次意图
- **“删除优于修复”模式**：冗余功能删除比修补安全
- **幽灵 PR 模式**：描述与提交内容严重不符须阻塞
- **LLM 输出解析的不信任原则**：主动引入变异追问
- **增量审查全文检索原则**：数行变更也须检索全仓库同名函数
- **防御式导入反模式**：API 从 webui 层导入预示分层腐化
- **修复 + 新功能混合 PR 风险**：新代码单独列清单审查
- **配置三重归属模式**：字段定义、UI分组、UI标签三者易不同步
- **消费点散落**：同一配置开关在多条路径中分别检查
- **渐进式代码清理**：多次“删除未使用导入”的小步提交
- **Tailwind 硬编码覆盖脆弱模式**：基于工具类名的选择器极易失效
- **Jinja2 样式重复阈值**：第三处必须提取为宏
- **i18n 重复定义阈值**：≥2 次必须提取到共享模块
- **常量字典重复阈值**：≥2 次必须集中管理
- **连续 3 轮未根治问题自动升温**：升级为 major→critical
- **渐进式重构顺序**：先修复调用点，再提取公共函数
- **翻译键命名规范**：`toast.<action>_<outcome>` 风格统一
- **异常处理分层不清**：业务异常未与展示层解耦
- **“委托式重构”残留**：保留旧方法形成技术债务
- **walrus operator 滥用**：三处以上重复逻辑必须提取函数
- **首次全量审查强制深度**：变更文件 ≥5 时须输出至少 5 条具体评论
- **异常类型判断禁止字符串比较**：须用 `isinstance` 或显式导入
- **白名单替换启发式模式**：显式前缀列表优于隐式模式匹配
- **降级链路端到端验证缺失**：须验证降级后仍能完成审查
- **工具调用幂等性缺失**：`_run_tool_loop` 不支持重试回滚，建议引入快照-重放
- **finally 路径覆盖检查**：存在 try-except-else-finally 时须画执行路径图
- **函数多出口返回值类型一致性**：所有 return 分支必须返回相同类型或明确 None 语义

## 5. 团队约定和规范

### 审查硬规则

- **三问法**：major 须内联“用户影响/利用条件/现有缓解”
- **纯可读性封顶**：最多 suggestion
- **自评矛盾降级**：出现“风险可控”降一级
- **根因修复验证**：须回溯核心要求
- **配置默认值变更强制风险评估**
- **新功能闭环校验（major）**：新增字段须追踪完整生命周期
- **格式化/转换函数重复调用检查（critical）**
- **日志可观测性三件套**：语义一致、不可信用 warning
- **布尔标志控制流完整性检查**
- **外部依赖失败显式降级（major）**：禁止返回空列表
- **配置解析红线（major）**：禁止 `replace().split()` 解析标签
- **全局异常处理器不得引用业务依赖（major）**
- **`except Exception` 必须记录日志（major）**
- **版本号升级检查清单（major）**：全仓库搜索并验证 CHANGELOG
- **新增 SQL 字段须检查迁移脚本（major）**
- **降级标志必须单一事实来源（major）**
- **配置热更新验证（major）**
- **PR 描述与变更内容一致性检查（critical）**：差异超过20%标记 critical
- **PR 描述视觉特性验证（critical）**
- **新增纯视觉动画性能评估（major）**
- **深色模式毛玻璃对比度验证（major）**
- **删除导入前全仓库引用搜索（minor）**
- **i18n 扫描完整性（major）**：扫描模板、toast、JS、API 错误、data-confirm、HTMX、x-text
- **`document.write` 禁止用于动态内容注入（major）**
- **toast 消息必须使用 i18n 函数（major）**
- **异常消息透传审计（major）**
- **翻译键语义完整性（major）**：覆盖所有业务分支
- **i18n PR 必须验证 YAML 翻译文件是否同时更新（major）**
- **异常类必须提供 user-facing message 属性且调用 i18n 函数（major）**
- **i18n 修复验证必须包含翻译键存在性检查（major）**
- **新增工具函数后原 wrapper 方法必须完全移除或标记 `@deprecated`（major）**
- **模板中标点符号禁止出现在 `{{ _('key') }}` 外部（major）**
- **增量审查必须扫描变更文件内 JS/模板中的 alert/confirm（major）**
- **新增工具必须评估其返回数据是否可能触发二次超长（major）**
- **实例级可变状态用于请求级数据时必须使用上下文管理器或克隆（major）**
- **新增降级路径必须有对应的单元测试验证（minor）**
- **异常类型判断禁止使用字符串比较（major）**
- **连续 2 轮未修复的历史问题应生成追踪 issue（suggestion）**
- **toast_redirect 自动翻译兜底分支必须记录警告日志（minor）**
- **同一异常处理模式出现 ≥3 次须提取公共函数（minor）**
- **跨语言版本漂移标注（suggestion）**
- **测试必须验证异常路径被真正触发（minor）**
- **可变单例须注释并发安全策略（minor）**
- **重复工具函数提取阈值（minor）**：≥2 次提取到 `shared/utils`
- **常量字典提取阈值（minor）**：≥2 次集中定义
- **延迟导入必须注释循环引用原因（minor）**
- **增量审查必须输出“本轮未涉及但历史未修复问题清单”（major）**：连续≥2 轮标记未修的问题须标注
- **空审查结果阻断规则（critical）**
- **连续 3 轮未根治的问题自动升级严重度（major→critical）**
- **共享函数设计时必须明确是否需要请求上下文（major）**
- **白名单降级分支必须记录警告日志（major）**
- **工具循环副作用必须在 docstring 中标注（major）**
- **except Exception 重新抛出前必须记录原始堆栈（major）**
- **增量审查增加“模式嗅探”步骤**：发现常量提取时扫描其他模块是否存在同类硬编码（minor）

### suggestion 疲劳归档协议

- 第 1 轮未修复：评估降级
- 第 2 轮未修复：强制降级
- 第 3 轮未修复：强制归档并从主评论移除

### 版本管理补充规范

- 版本号变更须搜索正则防止动态拼接遗漏
- 版本号升级 PR 必须验证 `__version__` 单一真实源
- 版本号升级 PR 必须附带 CHANGELOG 草案
- 数据库默认值变更必须评估已有数据迁移

### 增量审查补充规范

- 增量审查必须扫描 PR 描述中的所有提及文件
- 任何 import 删除必须触发全仓库引用扫描
- i18n 增量审查须扫描所有 JS、`toast_redirect` 调用点和 `data-confirm` 属性
- 增量审查必须抽样验证修复点的完整调用链
- 增量审查中必须输出“已检查的规则清单”（最少 10 条）
- 增量审查必须执行“PR 描述声称功能验证清单”
- 修改被多处调用的函数时，必须列出所有调用位置并验证兼容性（major）

### 评分补充规范

- 评分中加入“未解决的历史 major 问题数量”作为扣分项
- 连续 3 轮评分相同且问题类型未改变，自动标记“技术债务接受”并生成追踪 issue
