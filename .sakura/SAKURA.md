# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈

Sakura AI Reviewer 是一款基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。

- **后端语言**：Python 3.11+
- **Web 框架**：FastAPI
- **前端界面**：HTML（自包含 WebUI）、Alpine.js、HTMX
- **数据库**：MySQL、Redis
- **AI 与检索**：LLM API、RAG 向量检索
- **基础设施**：Docker、Docker Compose
- **代码规范**：Ruff
- **集成渠道**：GitHub App、Telegram Bot

## 2. 架构设计与关键决策

- **分层架构**：API 层、服务层、数据访问层分离，路由层禁止直接操作数据库
- **服务层职责边界**：`comment_service` 为行内评论渲染唯一入口
- **集中式结果解析器**：AI 输出清洗收敛于 `result_parser.py`
- **配置三层穿透**：Settings → yaml_config → 硬编码默认值
- **降级标志传递模式**：布尔标志沿调用链传递失败语义
- **fallback 链路统一**：空字符串 → settings → yaml → 硬编码
- **fire-and-forget 范式**：`create_task` + `add_done_callback(discard)`
- **工具插件化架构**：统一工具注册与调用
- **全局异常处理器不得引用业务依赖**：不解析 token、不查数据库
- **版本号多源硬编码**：main.py、auth.py、init.sql 三处独立，建议单一真实源
- **配置全链路模式**：新增配置字段须在各层同步添加
- **服务层薄化演进**：逐步移除配置读取逻辑
- **i18n 门面模式**：`render_template` 统一注入 `_()` 和 `lang`
- **配置热更新双接口**：`get_config()` (异步) + `get_cached_config()` (同步)
- **翻译键前缀约定**：`toast.*`、`settings.*`、`register.*` 语义清晰
- **工具循环复用**：`_run_tool_loop` 消除重复代码
- **降级链路闭环**：`BadRequestError` → 移除 diff → 按需工具获取 → 对话压缩
- **降级梯度设计**：首次超长 → 精简模式；多轮超长 → 压缩历史
- **服务层自治事务模式**：服务方法内部自行 commit，调用方无需额外提交
- **尽力而为删除策略**：循环中逐项删除，单项失败不阻断整体
- **前置 + 兜底设计**：webhook 即时处理 + worker 全量保留
- **幂等共享信号模式**：取消任务时多排队任务共享同一个 asyncio.Event
- **检查点渐进状态模式**：取消检查点在无 DB 记录和有 DB 记录阶段行为不同
- **返回值语义分离**：`task_key`（业务标识）与 `task_id`（日志追踪 UUID）解耦
- **惰性重置配额模式**：在读取路径重置过期配额，但需确保所有入口调用
- **批量操作 savepoint 模式**：循环中使用 `begin_nested()` 替代全局 rollback
- **静态分析降级模式**：正则提取 import + 路径别名解析，必须记录失败日志
- **委托模式重构规范**：重构为委托后须注释行为等价性，调用方变量名须与语义匹配
- **批量返回值语义强化**：批量重置函数返回 `ResetResult` 对象而非 `rowcount` 累加
- **副作用函数命名必须明确**：若函数在特定参数下会修改状态，函数名或参数名必须显式提示
- **外部写入失败后须记录可恢复警告**：DB 已提交但外部文件写入失败时，必须记录 error 日志并说明不一致风险
- **并发触发配额重置必须加锁或幂等**：多个请求同时调用重置函数可能导致重复更新，应使用分布式锁或行锁
- **批量 UPDATE 必须在一个事务中原子执行**：循环执行多条 UPDATE 必须使用 `begin_nested()` 或单条 CASE WHEN 语句
- **公共工具函数必须处理 None/空值边界**：即使注释声称“调用方不会传 None”，也须增加防御性检查
- **公共函数必须包含 docstring 说明边界行为**：如 `None → ""`、`"//api" → "/api"` 等
- **限流配置必须从统一配置读取**：禁止硬编码 `"10/minute"`，应从 `settings.RATE_LIMIT_*` 读取
- **异步 session 异常后必须显式 rollback 或重建**：捕获异常后 session 可能进入 invalid 状态
- **API 返回结构必须统一**：建议使用 `{success, data, message}` 格式
- **配置降级必须记录 warning 日志**：使用默认值替代用户/环境配置时须输出日志
- **明文敏感字段存储必须加密**：新增 DB 列存储 api_key/secret/token 时强制加密

## 3. 已知问题和注意事项

- **错误处理不统一**：新代码应倾向显式错误传播
- **静默降级缺乏可见性**：降级路径须产生 warning 日志
- **`except Exception` 无日志视为静默失败**
- **轮询缺少强制失败出口**：启动循环须超时检查 + exit≠0
- **外部依赖失败必须显式降级**：返回 None 或抛异常，禁止空列表
- **配置解析红线**：禁止 `.replace().split()` 解析标签列表
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **双重格式化陷阱**：下游再次调用 format 会破坏结构
- **测试隐式全局状态**：须显式 mock
- **版本号漂移风险**：Python + SQL 多语言硬编码，建议单一真实源
- **CHANGELOG 文化缺失**：minor/major 升级建议强制起草条目
- **可变单例并发安全**：`@lru_cache` + `setattr` 修改须加锁或上下文管理器
- **配置开关与既有数据库兼容性**：新增字段后旧记录的默认行为须显式处理
- **死代码保留无注释**：未调用的条件分支须注释预期调用者
- **跨模块导入删除风险**：删除导入前必须全仓库引用搜索
- **动画性能风险**：大量飘落花瓣可能导致低端设备重绘问题
- **无障碍一致性传播遗漏**：`prefers-reduced-motion` 须同步所有页面
- **毛玻璃深色模式对比度风险**：`bg-white/70` 在深色模式下文字对比度可能不足
- **响应式窄屏布局溢出**：新增大内边距可能导致横向滚动
- **PR 描述与变更内容严重不符**：须作为 critical 阻断合并
- **i18n 翻译覆盖不完整**：toast 消息、API 错误响应、JS 动态文本易硬编码
- **重复工具函数散落**：`_t()` 在多个服务中重复
- **`document.write` 用于动态内容注入**：应改用 `x-text`
- **翻译键语义错误**：键名与显示内容不匹配
- **样式副本漂移风险**：多处 `.glass` 须标注源位置
- **临时选择器无到期标注**：须注明预期移除版本
- **异常消息透传风险**：直接向用户展示 `str(e)` 前须评估
- **动态配置读取失败无可观测性**：`get_cached_config` 返回 `None` 时须记录日志
- **i18n 增量审查盲区**：PR 声明 i18n 时必须扫描 JS 和 `toast_redirect` 调用点
- **异常类缺少 user-facing message 属性**：自定义异常必须调用 i18n 函数
- **延迟导入滥用**：函数体内导入未注释循环引用原因
- **空审查结果不得通过**：主要评论为空且变更文件数 ≥5 时自动拒绝
- **启发式逻辑代码嗅探**：形如 `if condition and heuristic` 须注释边界和 fallback
- **模板标点硬编码惯性**：句号、冒号等须纳入翻译值
- **降级后二次超长风险**：单文件 diff 仍可能超长，须有二次降级策略
- **实例级可变状态并发污染**：请求级数据不应存储为实例属性
- **中文 Token 估算缺陷**：`len(content)//4` 是近似值，建议引入 tiktoken
- **工具循环副作用未标注**：修改传入列表/字典的公共方法须在 docstring 中用 `⚠️ 副作用` 标注
- **正则编译必须提升到模块级别**：禁止在方法体内每次调用重新编译
- **通用异常（`raise Exception`）禁止使用**：必须使用自定义异常
- **降级路径的测试必须在 PR 中体现**：新增降级分支须同步新增测试
- **幂等性强制注释**：公共方法若设计为可重复调用，须标注“幂等: 是/否”
- **调用方必须处理“假阴性”返回值**：返回 0 表示“无操作”时，调用方须能区分失败
- **内部信号异常必须注释上层转换点**
- **property 返回值 falsy 语义一致性**：替换私有属性时须验证原访问点的 falsy 语义
- **并发调用风险评估**：同一 worker 可能被多个事件并发执行时，须评估竞态条件
- **SQLAlchemy 异步 session 行为误判风险**：`async with session:` 不自动 commit
- **异常后 session 状态污染**：捕获 DB 异常后 session 可能进入 inactive
- **取消路径资源清理不一致**：多处取消检查点必须抽取公共清理函数
- **状态枚举变更的兼容性审查**：须检查数据库、API、前端过滤器、SSE 接收端
- **清理函数的 None 安全性**：接收可能 None 的对象时须检查内部处理
- **rollback 后必须验证 session 可用性**：若无 `expunge_all()` 或 `begin()`，标记 warning
- **配额重置遗漏读取路径**：惰性重置逻辑必须在所有展示入口调用
- **字符串前缀移除禁止使用 `lstrip`**：必须使用 `removeprefix` 或 `startswith` + 切片
- **Mermaid 图表生成必须转义所有特殊字符**：`&<>{}[]()#%|` 全部转义
- **路径别名解析须显式声明映射假设**：使用 `@/` 时若无 tsconfig 映射，须注释说明降级策略
- **定时任务注册必须验证启动钩子**：新增 `scheduler.add_job` 须确认在 `startup_event` 或 `lifespan` 中调用
- **批量重置函数返回语义须明确**：返回 `ResetResult(affected_users, affected_fields)` 而非 `rowcount` 累加
- **列表页 N+1 量化阈值**：用户量 <500 且操作轻量可允许，但须注释性能假设
- **只读接口中禁止嵌入写操作**：包括批量写，例外需注释用户量上限和操作开销评估

## 4. 审查中发现的重要模式

- **微小变更审查价值**：行数少 ≠ 风险低
- **增量隧道视野**：对新增字段完整生命周期缺乏追踪
- **suggestion 疲劳归档机制**：第 2 轮未修复降级，第 3 轮强制归档
- **增量审查两重责任**：追踪历史修复 + 覆盖本次意图
- **“删除优于修复”模式**：冗余功能删除比修补安全
- **幽灵 PR 模式**：描述与提交内容严重不符须阻塞
- **LLM 输出解析的不信任原则**：主动引入变异追问
- **增量审查全文检索原则**：数行变更也须检索全仓库同名函数
- **防御式导入反模式**：API 从 webui 层导入预示分层腐化
- **修复 + 新功能混合 PR 风险**：新代码单独列清单审查
- **配置三重归属模式**：字段定义、UI分组、UI标签三者易不同步
- **消费点散落**：同一配置开关在多条路径中分别检查
- **渐进式代码清理**：多次“删除未使用导入”的小步提交
- **Tailwind 硬编码覆盖脆弱模式**：基于工具类名的选择器极易失效
- **Jinja2 样式重复阈值**：第三处必须提取为宏
- **i18n 重复定义阈值**：≥2 次必须提取到共享模块
- **常量字典重复阈值**：≥2 次必须集中管理
- **连续 3 轮未根治问题自动升温**：升级为 major→critical
- **渐进式重构顺序**：先修复调用点，再提取公共函数
- **翻译键命名规范**：`toast.<action>_<outcome>` 风格统一
- **异常处理分层不清**：业务异常未与展示层解耦
- **“委托式重构”残留**：保留旧方法形成技术债务
- **walrus operator 滥用**：三处以上重复逻辑必须提取函数
- **首次全量审查强制深度**：变更文件 ≥5 时须输出至少 5 条具体评论
- **异常类型判断禁止字符串比较**：须用 `isinstance`
- **白名单替换启发式模式**：显式前缀列表优于隐式模式匹配
- **降级链路端到端验证缺失**：须验证降级后仍能完成审查
- **工具调用幂等性缺失**：`_run_tool_loop` 不支持重试回滚
- **finally 路径覆盖检查**：存在 try-except-else-finally 时须画执行路径图
- **函数多出口返回值类型一致性**：所有 return 分支必须返回相同类型
- **临时实例的并发陷阱**：即使每次新建对象，若仍写入共享实例属性，风险未根除
- **“修复”与“重构”边界模糊**：功能修复应避免混合代码重构
- **SQLAlchemy 表达式 truthy 陷阱**：`if filter:` 可能触发 `__bool__` 警告
- **历史债务“降温”现象**：同一问题多轮未修时审查者可能降低感知
- **注释与代码距离漂移**：代码移动后注释未同步更新
- **统一入口模式的反模式**：多条防御合并到入口可能导致中间失败后整体中断
- **日志冗余合并检查**：同一逻辑分支内两条 info 日志应合并
- **if/else 对称日志输出**：if 有 info 时 else 应至少输出 debug
- **`_safe_xxx` 包装函数模式**：统一处理 DB 异常，返回语义化整型
- **bool 是 int 子类的类型检查陷阱**：`isinstance(v, int)` 会匹配 bool
- **批量删除函数输出信息不足**：应返回成功/失败计数及首个错误类型
- **webhook 并发去重评估**：串行逻辑前置到 webhook 时须评估重复事件影响
- **共享取消信号的排队场景**：多任务排队时共享 event 需显式文档化
- **返回值语义变更的调用方变量名检查**：须检查变量名是否仍保持语义一致
- **批量 UPDATE 返回值语义必须明确**：若返回 `rowcount` 累加值，必须在函数名或 docstring 中说明
- **列表页禁止逐个调用写操作**：除非有明确性能评估
- **新增调度器时区须与项目默认时区对齐或注释差异原因**
- **惰性重置的所有读取入口须统一审查**：WebUI、API、Telegram 命令、内部服务
- **降级路径的一致性**：静态分析失败时应暴露降级状态（如响应头 `X-Analysis-Fallback`）
- **事务与外部写入顺序**：先提交数据库再写 YAML 作为常见反模式优先检查

## 5. 团队约定和规范

### 审查硬规则

- **三问法**：major 须内联“用户影响/利用条件/现有缓解”
- **纯可读性封顶**：最多 suggestion
- **自评矛盾降级**：出现“风险可控”降一级
- **根因修复验证**：须回溯核心要求
- **配置默认值变更强制风险评估**
- **新功能闭环校验（major）**：新增字段须追踪完整生命周期
- **格式化/转换函数重复调用检查（critical）**
- **日志可观测性三件套**：语义一致、不可信用 warning
- **布尔标志控制流完整性检查**
- **外部依赖失败显式降级（major）**：禁止返回空列表
- **配置解析红线（major）**：禁止 `replace().split()` 解析标签
- **全局异常处理器不得引用业务依赖（major）**
- **`except Exception` 必须记录日志（major）**
- **版本号升级检查清单（major）**：全仓库搜索并验证单一真实源
- **新增 SQL 字段须检查迁移脚本（major）**
- **降级标志必须单一事实来源（major）**
- **配置热更新验证（major）**
- **PR 描述与变更内容一致性检查（critical）**
- **PR 描述视觉特性验证（critical）**
- **新增纯视觉动画性能评估（major）**
- **深色模式毛玻璃对比度验证（major）**
- **删除导入前全仓库引用搜索（minor）**
- **i18n 扫描完整性（major）**：扫描模板、toast、JS、API 错误等
- **`document.write` 禁止用于动态内容注入（major）**
- **toast 消息必须使用 i18n 函数（major）**
- **异常消息透传审计（major）**
- **翻译键语义完整性（major）**

- **实例级可变状态用于请求级数据时必须使用上下文管理器（major）**
- **新增降级路径必须有对应的单元测试验证（major）**
- **异常类型判断禁止使用字符串比较（major）**

- **同一异常处理模式出现 ≥3 次须提取公共函数（minor）**
