# Sakura AI Reviewer 项目概述

## 1. 项目简介
基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。

**技术栈**：Python 3.11+、FastAPI、MySQL、Redis、Docker、GitHub App、Telegram Bot

## 2. 架构设计
- 分层架构：API 层、服务层、数据访问层分离
- 配置三层穿透：Settings → yaml_config → 硬编码默认值
- 动态配置系统：统一接口处理 None/非法值降级并记录 warn
- 工具插件化架构：统一工具注册与调用

## 3. 审查核心模式
- **微小变更审查价值**：行数少 ≠ 风险低
- **"删除优于修复"模式**：冗余功能删除比修补安全
- **连续 3 轮未根治问题自动升温**：升级为 major→critical
- **增量审查必须检查关联文件**：避免功能碎片化；支付类 PR 必须触发全量审查以识别系统性风险
- **测试文件深度验证**：强制检查测试用例与新增逻辑的匹配度
- **异步编程审查优先级**：同步 I/O 阻塞是异步系统的常见风险，必须强制检查并包装

## 4. 审查硬规则（major/critical）
1. **未修复历史问题必须关联 issue 号**
2. **延迟导入必须注释原因**：函数体内 import 若无注释说明循环引用原因，阻断合并
3. **异步路由同步调用包装强制化**：所有 async 路由中的同步 I/O 必须使用 asyncio.to_thread() 包装
4. **配置废弃全链路清理**：配置字段废弃时必须从代码、UI配置页面、动态配置键列表中全链路清理
5. **SSE 异常日志强制记录**：所有 SSE 发布必须记录异常日志，禁止静默失败
6. **工具安全边界审查**：新增工具必须检查命令链绕过风险，标记为 major
7. **新增状态枚举的全链路审查**：新增枚举值必须检查 DB ENUM/迁移、历史数据回填、API返回等
8. **测试函数命名规范强制检查**：所有测试函数必须以 `test_` 前缀命名
9. **增量审查全链路检查**：高频修改文件必须强制检查关联文件，避免功能碎片化
10. **数据库迁移完整性检查表**：强制PR输出迁移脚本覆盖范围

- **PR描述与变更一致性验证**：审查前必须核对文件清单与PR描述，避免无效审查
- **测试断言完整性强制检查**：新增测试必须验证所有关键字段，提供失败描述消息
- **并发安全性评估规则**：对新增公共方法需评估并发场景下的线程安全

## 7. 最新审查经验教训（基于 PR #352–#360 反思）
- **增量审查的局限性**：对于大型版本发布PR，需主动执行全量扫描，避免局部优化
- **支付系统安全持续关注**：金额验证绕过、货币不匹配等历史问题需定期复审
- **测试覆盖深度**：纯函数边界情况需直接单元测试，避免依赖间接覆盖
- **历史问题持续跟踪**：即使PR已approve，仍需记录未彻底解决的问题
- **支付事务原子性评估**：支付状态变更必须与关联操作绑定同一事务或补偿机制
- **PR描述与代码一致性**：审查前必须验证文件清单，避免因信息错位导致无效审查
- **测试文件职责强制检查**：新增测试必须放置在与其测试功能匹配的文件中
- **常量定义检查规则**：新增功能时必须验证引用的常量正确定义且文档化

## 9. 新增审查规则（基于 PR #357–#360 反思）
- **PR描述与变更一致性强制验证**：审查前必须核对文件清单与PR描述，若不匹配需立即中止并标记为"信息不一致"
- **依赖版本变更审查清单**：对于版本约束修改，必须检查功能影响、安全漏洞、API兼容性、锁文件更新
- **测试断言完整性强制检查**：新增测试必须验证所有关键字段，提供失败描述消息，标为major
- **并发安全性评估规则**：对新增公共方法（如`add_tokens()`）需评估并发场景下的线程安全，标为major
- **注释与代码一致性验证**：注释更新后需验证其描述是否与当前代码逻辑完全匹配，避免误导，标为minor
- **跨文件重复逻辑扩展检查**：识别跨文件重复时，应使用代码搜索工具扫描全仓库，确保重复逻辑未在其他模块隐匿存在
- **统计聚合逻辑抽象强制规则**：对于新增聚合查询逻辑，强制要求提取到共享服务层，并检查是否与现有统计功能复用
- **测试文件职责强制检查**：新增测试必须放置在与其测试功能匹配的文件中，否则标记为major
- **常量定义检查规则**：新增测试或功能时，必须验证引用的常量在项目中正确定义且文档化
- **支付金额语义明确化规则**：强制要求金额解析函数返回`Optional[int]`，`None`表示解析失败，避免0的歧义
