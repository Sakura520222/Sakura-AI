# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈

Sakura AI Reviewer 是一款基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。

- **后端语言**：Python 3.11+
- **Web 框架**：FastAPI
- **前端界面**：HTML（自包含 WebUI）、Alpine.js、HTMX
- **数据库**：MySQL、Redis
- **AI 与检索**：LLM API、RAG 向量检索
- **基础设施**：Docker、Docker Compose
- **代码规范**：Ruff
- **集成渠道**：GitHub App、Telegram Bot

## 2. 架构设计与关键决策

- **分层架构**：API 层、服务层、数据访问层分离，路由层禁止直接操作数据库
- **集中式结果解析器**：AI 输出清洗收敛于 `result_parser.py`
- **配置三层穿透**：Settings → yaml_config → 硬编码默认值
- **动态配置系统**：`get_dynamic_config` 统一接口，但需处理 None/非法值降级
- **工具插件化架构**：统一工具注册与调用
- **全局异常处理器不得引用业务依赖**
- **i18n 门面模式**：`render_template` 统一注入 `_()` 和 `lang`；前端映射禁止硬编码
- **服务层自治事务模式**：服务方法内部自行 commit
- **幂等共享信号模式**：取消任务时多排队任务共享同一个 asyncio.Event
- **批量操作 savepoint 模式**：循环中使用 `begin_nested()` 替代全局 rollback
- **权限策略单一真实源**：所有角色判断调用策略函数，禁止硬编码
- **内存回退字典必须实现大小/TTL 限制**
- **安全操作必须记录审计日志**
- **Redis 命令版本依赖必须检测或文档化**

## 3. 已知问题和注意事项

- **错误处理不统一**：新代码应倾向显式错误传播
- **`except Exception` 无日志视为静默失败**（major）
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **版本号多源硬编码**：main.py、auth.py、init.sql 三处独立
- **死代码保留无注释**：未调用的条件分支须注释预期调用者
- **i18n 翻译覆盖不完整**：toast 消息、API 错误响应易硬编码
- **中文 Token 估算缺陷**：`len(content)//4` 是近似值
- **字符串前缀移除禁止使用 `lstrip`**：必须使用 `removeprefix`
- **权限重构必须全量覆盖**：API + WebUI + CLI + 后台任务
- **敏感 secret 不得通过前端表单往返**
- **配置项必须被使用或删除**：死配置在审查中标记
- **所有 JSON API 端点（除公开只读）必须显式使用 CSRF 依赖**
- **新增 DB 模型的 datetime 字段必须使用 `datetime.now(timezone.utc)`**
- **整数配置必须同时校验类型 + 范围**（major）
- **动态配置读取调用方须处理 None/非法值**（major）
- **配置迁移 PR 必须输出“迁移完整性检查表”**（minor）

## 4. 审查中发现的重要模式

- **微小变更审查价值**：行数少 ≠ 风险低
- **增量隧道视野**：对新增字段完整生命周期缺乏追踪
- **“删除优于修复”模式**：冗余功能删除比修补安全
- **防御式导入反模式**：API 从 webui 层导入预示分层腐化
- **渐进式重构顺序**：先修复调用点，再提取公共函数
- **连续 3 轮未根治问题自动升温**：升级为 major→critical
- **策略函数模式**：纯函数无副作用，但须校验输入有效性
- **回退字典是“静默失败”的重灾区**：必须监控+过期+上限
- **配置与消费的对称性审查**：每看到一个新增配置字段，强制扫描其唯一读取位置
- **CSRF + JSON API 组合**：成为固定审查项
- **原子操作审查**：`GET + DELETE` 等必须优先改成 `GETDEL`、Lua 或事务
- **配置迁移中的“隐性删除”**：重构简化时须逐行比对旧逻辑的边界条件

## 5. 团队约定和规范

### 审查硬规则（major/critical）
- **三问法**：major 须内联“用户影响/利用条件/现有缓解”
- **`except Exception` 必须记录日志**
- **PR 描述与变更内容一致性检查（critical）**
- **i18n 扫描完整性**：全覆盖；限流/异常响应中禁止硬编码用户可见字符串
- **新增降级路径必须有对应单元测试**
- **权限重构必须全量覆盖所有调用方**
- **行为变更必须标注在 PR 描述中**
- **字符串前缀移除禁止使用 `lstrip`**
- **内存回退字典必须实现大小/TTL 限制**（major）
- **安全操作失败必须记录审计日志**（major）
- **所有用户输入验证端点必须有速率限制**（major）
- **新增配置项若涉及行为变更，必须同步消费逻辑**（major）
- **所有 JSON API 端点（除公开只读）必须显式使用 CSRF**（major）
- **整数配置必须同时校验类型 + 范围**（major）
- **动态配置读取调用方须处理 None/非法值**（major）

### suggestion 疲劳归档协议
第 1 轮未修复：评估降级 | 第 2 轮未修复：强制降级 | 第 3 轮未修复：强制归档

### 增量审查补充规范
- 增量审查必须输出“已检查的规则清单”（最少 10 条）
- 增量审查必须输出“历史未解决问题清单并升温”
- 增量审查必须输出“未直接测试但依赖的调用链”
- **配置迁移 PR 必须输出“迁移完整性检查表”**（minor）
- **“分阶段实现”PR 必须列出未完成项并创建后续 issue**

### 常量与配置规范
- **常量定义位置与语义保持一致**
- **路径后缀判断集合必须定义为常量**

### 日志与可观测性
- **新增异常处理器必须记录 warn 级别日志**（minor）

### 前端 i18n 规范
- **前端 i18n 映射函数必须使用对象映射**，禁止硬编码 `if key === ...`
