# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈

Sakura AI Reviewer 是一款基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。

- **后端语言**：Python 3.11+
- **Web 框架**：FastAPI
- **前端界面**：HTML（自包含 WebUI）、Alpine.js、HTMX
- **数据库**：MySQL、Redis
- **AI 与检索**：LLM API、RAG 向量检索
- **基础设施**：Docker、Docker Compose
- **代码规范**：Ruff
- **集成渠道**：GitHub App、Telegram Bot

## 2. 架构设计与关键决策

- **分层架构**：API 层、服务层、数据访问层分离，路由层禁止直接操作数据库
- **集中式结果解析器**：AI 输出清洗收敛于 `result_parser.py`
- **配置三层穿透**：Settings → yaml_config → 硬编码默认值
- **动态配置系统**：`get_dynamic_config` 统一接口，需处理 None/非法值降级并记录 warn
- **工具插件化架构**：统一工具注册与调用
- **全局异常处理器不得引用业务依赖**
- **i18n 门面模式**：`render_template` 统一注入 `_()` 和 `lang`
- **服务层自治事务模式**：服务方法内部自行 commit
- **幂等共享信号模式**：取消任务时多排队任务共享同一个 asyncio.Event
- **批量操作 savepoint 模式**：循环中使用 `begin_nested()` 替代全局 rollback
- **权限策略单一真实源**：所有角色判断调用策略函数
- **安全操作必须记录审计日志**
- **配置系统“四对称性”检查表**：定义、测试、路由校验、写入校验必须一致

## 3. 已知问题和注意事项

- **错误处理不统一**：新代码应倾向显式错误传播
- **`except Exception` 无日志视为静默失败**（major）
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **版本号多源硬编码**：main.py、auth.py、init.sql 三处独立
- **中文 Token 估算缺陷**：`len(content)//4` 是近似值
- **字符串前缀移除禁止使用 `lstrip`**：必须使用 `removeprefix`
- **敏感 secret 不得通过前端表单往返**
- **整数配置必须同时校验类型 + 范围**（major）
- **动态配置读取调用方须处理 None/非法值，并记录 warning**（major）
- **Shell 命令白名单匹配禁止使用前缀匹配**（major）
- **BackgroundTasks 不适合长时间运行任务**（major）
- **测试中修改全局缓存必须使用 fixture 或 finally 确保清理**（major）
- **配置范围修改必须同步更新所有测试断言**（major）
- **配置常量变更必须触发缓存失效检查**（major）
- **`finally` 中的清理函数必须有独立的异常处理**（major）

## 4. 审查中发现的重要模式

- **微小变更审查价值**：行数少 ≠ 风险低
- **增量隧道视野**：对新增字段完整生命周期缺乏追踪
- **“删除优于修复”模式**：冗余功能删除比修补安全
- **连续 3 轮未根治问题自动升温**：升级为 major→critical，第 4 轮自动生成 issue
- **配置与消费的对称性审查**：每看到一个新增配置字段，强制扫描其唯一读取位置
- **“点状修复”陷阱**：只改断言不改来源导致未来再次漂移
- **配置系统双校验反模式**：`DYNAMIC_CONFIG_RANGES` + 内联 int 校验并存
- **测试脆弱断言**：硬编码范围值而非引用常量
- **int/float 类型校验语义差异**：截断 vs 保留小数须明确标注
- **双路径实现等价性要求**：系统工具与回退实现行为必须完全一致

## 5. 团队约定和规范

### 审查硬规则（major/critical）
- **三问法**：major 须内联“用户影响/利用条件/现有缓解”
- **`except Exception` 必须记录日志**
- **i18n 扫描完整性**：全覆盖；禁止硬编码
- **权限重构必须全量覆盖所有调用方**
- **整数配置必须同时校验类型 + 范围**
- **动态配置读取调用方须处理 None/非法值并记录 warn**
- **Shell 命令白名单精确匹配**（major）
- **配置范围修改强制扫描所有测试断言**（major）
- **配置常量变更触发缓存失效检查**（major）
- **测试中的范围断言必须引用生产常量**（连续两次升 major）
- **连续 3 轮未修复问题自动生成 issue**（流程规则）

### 增量审查补充规范
- 增量审查必须输出“已检查的规则清单”（最少 10 条）
- 增量审查必须输出“历史未解决问题清单并升温”
- 增量审查必须输出“本应检查但因范围限制未覆盖的项”
- **配置迁移 PR 必须输出“迁移完整性检查表”**
- **新增配置字段检查表**：唯一性、默认值兼容性、所有读取路径的 None 处理、写入路径与缓存失效成对

### 常量与配置规范
- **配置默认值唯一声明于 `config.py`**（major）
- **docstring 中描述的白名单必须与代码常量一致**（major）
- **配置更新操作必须触发缓存失效验证**
