# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈

Sakura AI Reviewer 是一款基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。

- **后端语言**：Python 3.11+
- **Web 框架**：FastAPI
- **前端界面**：HTML（自包含 WebUI）、Alpine.js、HTMX
- **数据库**：MySQL、Redis
- **AI 与检索**：LLM API、RAG 向量检索
- **基础设施**：Docker、Docker Compose
- **代码规范**：Ruff
- **集成渠道**：GitHub App、Telegram Bot

## 2. 架构设计与关键决策

- **分层架构**：API 层、服务层、数据访问层分离，路由层禁止直接操作数据库
- **集中式结果解析器**：AI 输出清洗收敛于 `result_parser.py`
- **配置三层穿透**：Settings → yaml_config → 硬编码默认值
- **降级标志传递模式**：布尔标志沿调用链传递失败语义
- **工具插件化架构**：统一工具注册与调用
- **全局异常处理器不得引用业务依赖**
- **i18n 门面模式**：`render_template` 统一注入 `_()` 和 `lang`；前端映射禁止硬编码 `if key === ...`，必须使用对象映射
- **服务层自治事务模式**：服务方法内部自行 commit
- **幂等共享信号模式**：取消任务时多排队任务共享同一个 asyncio.Event
- **批量操作 savepoint 模式**：循环中使用 `begin_nested()` 替代全局 rollback
- **权限策略单一真实源**：所有角色判断调用策略函数，禁止硬编码
- **内存回退字典必须实现大小/TTL 限制**（参照 OAuth state 的 `_MAX_FALLBACK_*`）
- **安全操作必须记录审计日志**（2FA 验证/绑定/重置失败等）
- **Redis 命令版本依赖必须检测或文档化**：新增命令（如 `GETDEL`）须标注最低版本或启动时检测降级

## 3. 已知问题和注意事项

- **错误处理不统一**：新代码应倾向显式错误传播
- **`except Exception` 无日志视为静默失败**（major 级规范）
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **版本号多源硬编码**：main.py、auth.py、init.sql 三处独立
- **死代码保留无注释**：未调用的条件分支须注释预期调用者
- **i18n 翻译覆盖不完整**：toast 消息、API 错误响应易硬编码；限流/异常响应中禁止硬编码用户可见字符串
- **中文 Token 估算缺陷**：`len(content)//4` 是近似值
- **字符串前缀移除禁止使用 `lstrip`**：必须使用 `removeprefix`
- **权限重构必须全量覆盖**：API + WebUI + CLI + 后台任务
- **敏感 secret 不得通过前端表单往返**：TOTP secret、恢复码必须服务端暂存
- **配置项必须被使用或删除**：死配置在审查中标记；新增配置项若涉及行为变更，必须同步消费逻辑或注释为“预留”
- **所有 JSON API 端点（除公开只读）必须显式使用 CSRF 依赖或头校验**
- **新增 DB 模型的 datetime 字段必须使用 `datetime.now(timezone.utc)`**，禁止 `datetime.utcnow`
- **模块级可变字典作为 fallback 必须注释线程/协程安全假设**
- **使用 `X-Forwarded-For` 必须同时说明受信代理假设**
- **降级路径（如内存 fallback）必须记录 warning 日志**
- **新增联合类型时必须扫描所有序列化/反序列化边界**

## 4. 审查中发现的重要模式

- **微小变更审查价值**：行数少 ≠ 风险低
- **增量隧道视野**：对新增字段完整生命周期缺乏追踪
- **suggestion 疲劳归档机制**：第 2 轮未修复降级，第 3 轮强制归档
- **“删除优于修复”模式**：冗余功能删除比修补安全
- **防御式导入反模式**：API 从 webui 层导入预示分层腐化
- **渐进式重构顺序**：先修复调用点，再提取公共函数
- **连续 3 轮未根治问题自动升温**：升级为 major→critical
- **策略函数模式**：纯函数无副作用，但须校验输入有效性
- **三态缓存设计**（`"1"`, `"0"`, `"unknown"`）处理不确定状态
- **列表收集+末尾输出日志模式**：优于循环内多次打印
- **回退字典是“静默失败”的重灾区**：必须监控+过期+上限
- **一次性 secret 设计需明确用户体验边界**
- **配置与消费的对称性审查**：每看到一个新增配置字段，强制扫描其唯一读取位置
- **CSRF + JSON API 组合**：成为固定审查项，尤其 WebUI 路由下
- **原子操作审查**：`GET + DELETE`、`GET + SET` 等必须优先改成 `GETDEL`、Lua 或事务
- **内存 fallback 的可恢复性**：审查时主动询问“重启会丢失什么状态”
- **i18n 前端映射的扩展性陷阱**：应一开始就使用对象映射或映射函数
- **全局异常处理器中的前端逻辑**：限流返回需要前后端约定 message 语义
- **Jinja2 模板中的 JS 片段去重**：公共 JS 函数必须抽取到共享模板
- **限流 suffix 集合与路由定义的一致性**：建议 CI 扫描
- **版本检测 + fallback + 集成测试**：作为原子操作类 PR 的固定审查三件套

## 5. 团队约定和规范

### 审查硬规则（major/critical）

- **三问法**：major 须内联“用户影响/利用条件/现有缓解”
- **`except Exception` 必须记录日志**
- **PR 描述与变更内容一致性检查（critical）**
- **i18n 扫描完整性**：模板、toast、JS、API 错误全覆盖；限流/异常响应中禁止硬编码用户可见字符串
- **新增降级路径必须有对应单元测试**
- **公共工具函数必须处理 None/空值边界**
- **权限重构必须全量覆盖所有调用方**
- **行为变更必须标注在 PR 描述中**
- **策略函数必须检查输入有效性**
- **新增常量必须立即使用或删除**
- **批量 UPDATE 必须在一个事务中原子执行**
- **只读接口中禁止嵌入写操作**
- **字符串前缀移除禁止使用 `lstrip`**
- **明文敏感字段存储加密（critical）**
- **内存回退字典必须实现大小/TTL 限制**（major）
- **安全操作失败必须记录审计日志**（major）
- **所有用户输入验证端点必须有速率限制**（major）
- **新增配置项若涉及行为变更，必须同步消费逻辑或注释为“预留”**（major）
- **所有 JSON API 端点（除公开只读）必须显式使用 CSRF 依赖或头校验**（major）
- **新增 DB 模型的 datetime 字段必须使用 `datetime.now(timezone.utc)`**（major）
- **公共 JS 函数必须抽取到共享模板**（两个及以上模板出现相同定义时，major）
- **非 429 错误 fallback 字符串必须国际化**（major）
- **新增环境变量时必须明确其与现有 flag 的语义关系**（major）
- **独立公共函数必须具有直接单元测试，不依赖间接覆盖**（minor）
- **“仅警告不阻断”的兼容性检测，必须在 PR 描述中列出受影响的下游调用及 fallback 状态**（major）

### suggestion 疲劳归档协议
- 第 1 轮未修复：评估降级 | 第 2 轮未修复：强制降级 | 第 3 轮未修复：强制归档

### 增量审查补充规范
- 增量审查必须扫描 PR 描述中的所有提及文件
- 任何 import 删除必须触发全仓库引用扫描
- 修改被多处调用的函数时，必须列出所有调用位置
- 增量审查必须输出“已检查的规则清单”（最少 10 条）
- 增量审查必须检查测试是否同步更新
- 增量审查必须评估并发调用风险
- 新增枚举值必须同步前后端模板、过滤器、i18n
- 新增回退/降级机制必须对照已有实现并输出对比表
- 增量审查必须输出“历史未解决问题清单并升温”
- 增量审查必须明确标注“本次未处理的建议问题”
- **“分阶段实现”PR 必须列出未完成项并创建后续 issue**，否则视为不完整
- **增量审查必须输出“未直接测试但依赖的调用链”**

### 常量与配置规范
- **常量定义位置与语义保持一致**：模块级常量不得定义在函数内部（如 `lifespan` 内）
- **路径后缀判断集合必须定义为常量**，禁止魔法列表内联
- **新增限流保护端点时须同步更新判断逻辑**（作为 PR 检查清单项）

### 日志与可观测性
- **新增异常处理器必须记录 warn 级别日志**（minor，便于统计限流触发频率）

### 前端 i18n 规范
- **前端 i18n 映射函数必须支持动态翻译表**：禁止使用 `if key === 'toast.xxx' return translation` 硬编码扩展，应使用对象映射（如 `i18nMap[key] || key`）
