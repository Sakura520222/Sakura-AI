# Sakura AI Reviewer 项目概述

## 1. 项目简介与技术栈
Sakura AI Reviewer 是基于大语言模型的智能 GitHub 代码审查与 Issue 分析机器人。
- **后端**：Python 3.11+ + FastAPI
- **前端**：HTML + Alpine.js + HTMX
- **数据库**：MySQL + Redis
- **AI**：LLM API + RAG 向量检索
- **基础设施**：Docker + Docker Compose

## 2. 架构设计与关键决策
- **分层架构**：API 层、服务层、数据访问层分离
- **配置三层穿透**：Settings → yaml_config → 硬编码默认值
- **动态配置系统**：统一接口处理 None/非法值降级并记录 warn
- **工具插件化架构**：统一工具注册与调用
- **服务层自治事务模式**：服务方法内部自行 commit

## 3. 已知问题和注意事项
- **错误处理不统一**：新代码应倾向显式错误传播
- **`except Exception` 无日志视为静默失败**（major）
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **整数配置必须同时校验类型 + 范围**（major）
- **未修复历史问题必须关联 issue 号**

## 4. 审查中发现的重要模式
- **微小变更审查价值**：行数少 ≠ 风险低
- **"删除优于修复"模式**：冗余功能删除比修补安全
- **连续 3 轮未根治问题自动升温**：升级为 major→critical
- **异步路由中的同步I/O阻塞**：必须使用 `asyncio.to_thread()` 包装
- **增量审查必须检查关联文件**：避免功能碎片化
- **高频修改文件全链路审查**：对 `submission_context.py` 等强制全链路审查
- **异常日志级别统一规范**：确保异常可见性，避免静默错误
- **跨流程数据一致性验证**：涉及多流程变更必须检查核心数据一致性
- **延迟导入注释强制化**：函数体内延迟导入必须附带注释说明原因

## 5. 团队约定和规范
### 审查硬规则（major/critical）
- **未修复历史问题必须关联 issue 号**
- **配置保存端点必须原子化**（major）
- **新增状态枚举的全链路审查**（major）
- **延迟导入必须注释原因**（major）
- **异步路由同步调用包装强制化**
- **配置废弃全链路清理**
- **SSE 异常日志强制记录**
- **工具安全边界审查**（major）
- **高频修改文件全链路审查**（major）
- **异常日志级别统一规范**（major）
