# 知识库维护规范（PR#455教训）

## 核心原则

### 增量追加优先
知识库（`.sakura/`）的更新应遵循"增量追加"或"精确修改"原则，**禁止整体覆盖式重写**。覆盖合并是导致核心经验丢失的主要原因。

### 元数据一致性
- 任何涉及版本号、次数、日期等元数据的修改，必须提供计算依据
- 反思次数、审查轮次等累计数据只能递增，出现倒退说明发生了覆盖式更新

### 变更审查化
对 `.sakura/` 核心文件（如 `SAKURA.md`、`rules/` 下的硬规则）的重大修改（如删除多条规则），应被视为与代码变更同等重要的审查项，需要逐项说明理由。

## 知识库作为审查资产

### 审查知识库变更的方法
1. **对比历史状态**：增量审查中对知识库文件的修改，应提供修改前后的关键内容对比，不仅仅是行数变更
2. **检查规则完整性**：对比核心规则文件（如 `review_hard_rules.md`）的规则条目数，确保未发生意外缩减
3. **版本控制意识**：项目将审查经验视为与代码同等重要的"知识资产"，并对其进行版本控制，这是优势（可追溯），但也带来了审查挑战

### 知识负债风险
- 无序或粗心的更新会直接导致"知识负债"
- 过去积累的经验在无形中丢失，审查标准退化
- **审查知识库变更必须像审查核心业务逻辑一样严谨**

## 文件组织与大小约束
- 每个知识文件不超过 5000 字符（含标点和空格）
- 优先提取最有价值的内容，宁缺毋滥
- 使用清晰的 Markdown 格式
- 按主题组织：`rules/`（审查规则）、`docs/`（架构文档）、`plans/`（经验教训）

## 来源
- PR#455（webauthn 升级 + .sakura/ 更新）：在沉淀经验的操作中伴随核心经验丢失，反思次数倒退
- 知识库退化导致审查标准不一致，后续审查效率下降
