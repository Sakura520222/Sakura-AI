## 重要规范摘要

### 配置管理
- 配置默认值必须唯一声明于`config.py`
- 整数配置必须同时校验类型+范围+物理上限
- 动态配置读取调用方须处理None/非法值并记录warn
- 配置迁移必须输出"迁移完整性检查表"

### 错误处理
- `except Exception`必须记录日志
- 静默异常必须记录debug日志
- 全局异常处理器不得引用业务依赖

### 安全规范
- 所有JSON API端点必须使用CSRF依赖
- 明文敏感字段存储必须加密
- Shell命令白名单禁止前缀匹配

### 异步编程
- 异步调用方式必须统一
- asyncio.create_task创建的后台任务必须在服务shutdown时有机会完成
- 同步函数中使用get_running_loop().create_task时必须评估线程安全性

### 前端规范
- 模板JS插件安全规范：强制使用`|tojson`进行JS上下文转义
- SVG装饰图标必须添加`aria-hidden="true"` + `focusable="false"`
- 新增WebUI模块必须检查"四一致"

## 审查流程

### 增量审查必须输出
1. 已检查的规则清单（最少10条）
2. 历史未解决问题清单并升温
3. 未直接测试但依赖的调用链

### 重大问题升级机制
- 第1轮未修复：评估降级
- 第2轮未修复：强制降级
- 第3轮未修复：强制归档
- 第4轮未修复：自动生成issue

## 369次审查关键知识

### 新增规则分类
- **资源操作安全规则**：配额消耗类操作纳入强制检查，与支付安全同等级别
- **增量审查优化规则**：强制关联扫描清单，版本发布PR强制全量审查
- **测试审查强化规则**：安全校验边界测试强制要求，支付事务原子性检查
- **配置管理强化规则**：常量定义检查，路径解析健壮性，支付金额语义明确化

### 新增架构决策
- **资源操作闭环验证**：必须追踪从"预留/消耗"到"最终释放/结算"的完整生命周期
- **事务边界审查强化**：优先建议在同一个事务中完成，或明确设计补偿/回滚逻辑
- **增量审查覆盖度下降风险**：对支付类PR强制执行全量重审或关联扫描清单

### 新增经验教训
- **修复的"副作用"比问题本身更隐蔽**：审查修复性PR时必须系统性评估变更对数据流和状态机的影响
- **"资源安全"审查应提升至与"支付安全"同等级别**：配额、积分等虚拟资源的安全同等重要
- **增量审查的"深度"挑战**：通过关联检查和逻辑推演识别跨越多个函数和步骤的逻辑缺陷

## 最新反思关键知识（ISSUE #422~#432）

### Issue 分析增强规则
- **"重写/统一"不等于纯重构**：必须同步检查新协议支持、UI、数据结构、兼容旧配置与分阶段落地可行性
- **配置类 Issue 要看"配置源"和"配置流"**：配置写入 DB/env/文件、运行时读取来源、多源冲突、迁移与回退
- **AI Provider 支持不能只看接口名**：需拆成协议适配、认证差异、消息格式、推理参数、错误码、streaming 一致性
- **大而全的 enhancement 须按子模块拆分**：协议层、配置层、UI 向导层、运行时调用层，避免单一"高复杂度"总评
- **Setup Wizard 是高影响入口**：初始体验、引导逻辑、回退路径、默认值、失败提示须整体评估

### 部署/配置类 Issue 分析模式
- **必须提供阶梯式排查清单并按概率排序**：首项为最可能根因，附"最快验证命令"
- **高优先级与用户自助的平衡**：high 不意味代码修改，须标注"预期用户可自行修复"
- **必须检查 GitHub App 安装权限与 Webhook Secret 配置**
- **分析输出应结构化分步骤**：请按顺序检查：1... 2... 3...

### 并发竞态分析模式
- **单例模式在 asyncio 并发中的状态污染陷阱**：优先检查共享可变对象生命周期与任务隔离
- **webhook 重试与 Issue edited 频繁触发导致级联竞态**：须加去重或限流
- **缓存并发安全须用 asyncio.Lock**
- **并发正确性问题应使用 concurrency/race-condition 标签，非 performance**

### 元 bug/自引用分析规范
- **系统分析自身 Issue 时须做递归防护**：设置全局递归深度限制
- **所有降级输出须附带唯一错误码**，严禁硬编码静态字符串伪装正常结果
- **automated 标签须明确语义**：区分用户手动提交 vs 自动化流程
- **重复检测须附证据链**：{被引Issue标题} + {相似点} + {差异点} + {判断结论}
- **标题改写不可缺失**：单次标题（如"bug"）须强制改写
- **AI 输出不稳定须指数退避重试（≥2次）**，保存完整载荷用于离线调优
- **协议解析器须平衡严格性与容错性**：对特定字段做内容净化而非直接拒绝

### 认证/API Key 问题分析模式
- **API 认证错误（401/403）应特殊处理**：立即捕获 AuthenticationError 避免无意义重试
- **用户侧配置问题与代码缺陷须清晰区分边界**
- **错误信息遵循最小泄露原则**：request id 等内部标识符应记录在日志而非返回前端
