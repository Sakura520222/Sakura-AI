# 常见问题模式与经验教训

## 配置管理问题
- **配置假值陷阱**：须用 `is not None` 而非 Truthy 检查
- **版本号多源硬编码**：main.py、auth.py、init.sql 三处独立
- **配置默认值必须唯一声明于 `config.py`**：禁止双源默认值
- **配置上限必须与消费方物理上限对齐**：评估单任务最大耗时、模型调用成本

## 异步任务问题
- **BackgroundTasks 不适合长时间运行任务**：应说明理由
- **asyncio.create_task 创建的任务可能在服务 shutdown 时丢失**
- **同步函数中使用 get_running_loop().create_task 可能在无运行循环的线程中调用**

## 错误处理问题
- **except Exception 无日志视为静默失败**：必须记录日志
- **session异常后状态污染**：捕获 DB 异常后 session 可能 inactive，必须显式 rollback() 或 close()
- **静默吞没异常是技术债源头**：必须记录日志并反馈调用方

## 路径处理问题
- **字符串前缀移除禁止使用 `lstrip`**：必须使用 `removeprefix`
- **路径重构必须输出所有 URL 字符串的位置清单**
- **禁止使用排除法分类请求路径**

## 测试问题
- **测试中修改全局缓存必须使用 fixture 或 finally 确保清理**
- **测试断言必须引用生产常量，禁止硬编码数值**
- **Mock 方法若接收但忽略参数，应添加断言验证关键参数值**

## 审查质量问题
- **增量隧道视野**：对新增字段完整生命周期缺乏追踪
- **连续 3 轮未根治问题自动升温**：升级为 major→critical，第 4 轮自动生成 issue
- **历史未修复问题必须关联 issue 号**

## 前端与模板问题
- **模板中内联 SVG 装饰图标必须添加 `aria-hidden="true"` + `focusable="false"`**
- **JS 上下文转义是常见漏洞**：应作为固定检查项
- **模板变量命名规范**：统一 active_page 前缀

## 数据库与事务问题
- **批量操作必须验证部分失败处理**：尤其是涉及数据库删除/更新的操作
- **事务外的外部写入必须支持补偿或异步**
- **新增 DB 模型的 datetime 字段必须使用 `datetime.now(timezone.utc)`**

## 经验教训总结
1. **配置变更的连锁反应**：配置上限调整需评估对历史数据和现有流程的影响
2. **错误处理的精确性**：失败状态处理应区分"可恢复"与"不可恢复"错误
3. **增量审查的上下文理解**：需更主动地查看 PR 整体描述，即使只审查增量部分
4. **异步任务的可见性**：create_task 创建的任务若未保存到变量，在 traceback 或日志中难以关联
5. **fallback 路径的测试盲区**：同步 fallback 中的异步分支很难被单元测试覆盖
