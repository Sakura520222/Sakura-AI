# Sakura AI Reviewer 知识库摘要

## 概述
本知识库基于项目审查反思提取的结构化知识，包含规则、文档和计划三个主要分类。

## 目录结构

### Rules（规则）
- **review_rules.md**: 代码审查规则，包括 Major/Critical 规则、Minor/Suggestion 规则、审查流程规范

### Docs（文档）
- **architecture_patterns.md**: 架构模式与设计决策
- **technical_patterns.md**: 技术模式与实现细节

### Plans（计划）
- **common_issues.md**: 常见问题模式与经验教训
- **review_patterns.md**: 审查模式与最佳实践
- **review_quality.md**: 审查质量评估模式

## 核心规则摘要

### Major/Critical 规则
1. **配置管理**：默认值唯一声明、整数配置校验、动态配置处理
2. **异步任务**：任务生命周期管理、线程安全性、调用方式统一
3. **错误处理**：异常必须记录日志、静默异常必须记录 debug 日志
4. **路径处理**：禁止使用 lstrip/rstrip 移除前缀、必须使用 removeprefix
5. **安全权限**：JSON API 必须使用 CSRF、敏感字段禁止传递到模板

### Minor/Suggestion 规则
1. **代码质量**：新增公共函数必须包含 docstring、函数副作用必须标注
2. **增量审查**：必须输出规则清单、历史问题清单、调用链清单
3. **配置相关**：配置迁移必须对比新旧默认值、动态配置必须显式声明默认值

## 关键架构模式

### 分层架构
- API 层、服务层、数据访问层分离
- 路由层禁止直接操作数据库
- 服务层自治事务模式

### 配置管理
- 三层穿透：Settings → yaml_config → 硬编码默认值
- 动态配置系统统一接口
- 配置默认值唯一声明

### 异步处理
- 幂等共享信号模式
- 批量操作 savepoint 模式
- 异步任务调用方式统一

## 常见问题模式

### 配置管理问题
- 配置假值陷阱：须用 `is not None` 而非 Truthy 检查
- 版本号多源硬编码
- 配置上限必须与消费方物理上限对齐

### 异步任务问题
- BackgroundTasks 不适合长时间运行任务
- asyncio.create_task 创建的任务可能在服务 shutdown 时丢失
- 同步函数中使用 get_running_loop().create_task 的线程安全性

### 错误处理问题
- except Exception 无日志视为静默失败
- session 异常后状态污染
- 静默吞没异常是技术债源头

## 使用指南

### 对于开发者
1. **提交 PR 前**：检查是否符合所有 Major 规则
2. **配置变更**：确保配置对称性检查完整
3. **异步任务**：确保任务生命周期管理正确

### 对于审查者
1. **增量审查**：必须输出规则清单、历史问题清单、调用链清单
2. **历史问题**：未修复问题必须关联 issue 号
3. **质量评估**：按覆盖度、准确度、完整性三个维度评估

### 对于项目维护者
1. **规则更新**：定期从反思中提取新规则
2. **知识库维护**：确保知识库与项目实践同步
3. **审查培训**：使用知识库进行审查质量培训

## 更新机制

### 从反思中提取知识
1. **定期阅读反思文件**：提取新规则、模式、问题
2. **分类整理**：按 rules、docs、plans 分类
3. **更新知识库**：使用 write_file 或 edit_file 更新文件

### 知识库维护
1. **定期审查**：检查知识库是否过时
2. **合并重复**：避免规则重复
3. **保持简洁**：每个文件不超过 5000 字符
