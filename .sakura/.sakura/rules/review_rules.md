# 代码审查规则

## Major/Critical 规则

### 配置管理
- **配置默认值必须唯一声明于 `config.py`**：禁止双源默认值
- **整数配置必须同时校验类型 + 范围 + 消费方物理上限**
- **动态配置读取调用方须处理 None/非法值并记录 warning**
- **配置更新操作必须触发缓存失效验证**
- **配置迁移 PR 必须输出"迁移完整性检查表"**
- **配置范围的"四对称性检查"**：范围定义、测试断言、路由校验、写入路径四者必须一致

### 异步任务处理
- **asyncio.create_task 创建的后台任务必须在服务 shutdown 时有机会完成**
- **同步函数中使用 get_running_loop().create_task 时，必须评估是否可能在无运行循环的线程中调用**
- **异步任务调用方式必须统一**：同一模块中 fire-and-forget 所有位置必须使用 create_task
- **asyncio.get_event_loop() 禁止使用**：一律改为 asyncio.get_running_loop()

### 错误处理
- **except Exception 必须记录日志**：禁止静默失败
- **配置降级必须记录日志**：使用默认值替代用户/环境配置时必须记录 warning 日志
- **静默异常必须记录 debug 日志**，并向调用方返回失败详情

### 路径处理
- **路径规范化禁止使用 lstrip/rstrip 移除前缀**：必须使用 removeprefix
- **跨平台路径处理函数必须包含单元测试**
- **路径前缀重构须全量扫描非路由文件**

### 安全与权限
- **所有 JSON API 端点（除公开只读）必须显式使用 CSRF 依赖或头校验**
- **敏感字段禁止传递到模板上下文**
- **Shell 命令白名单禁止前缀匹配**：必须解析第一个 token 精确匹配

### 测试规范
- **测试中修改全局缓存必须使用 fixture 或 finally 确保清理**
- **测试中的范围断言必须引用生产常量，禁止硬编码数值**
- **新增的 fallback 路径必须有集成测试验证**

## Minor/Suggestion 规则

### 代码质量
- **新增公共函数必须包含 docstring**：说明输入输出边界行为
- **函数副作用必须在 docstring 中明确**：若函数修改外部状态，必须在 docstring 首部用 ⚠️ 标注
- **冗余导入视为代码异味**：文件顶部已导入某模块，函数内再次导入且未使用别名或延迟必要性的，应要求合并或删除

### 增量审查
- **增量审查必须输出"已检查的规则清单"**（最少 10 条）
- **增量审查必须输出"历史未解决问题清单并升温"**
- **增量审查必须输出"未直接测试但依赖的调用链"**
- **增量审查必须扫描 tests/ 目录中的旧函数/常量引用**

### 配置相关
- **配置迁移 PR 必须对比新旧默认值**
- **动态配置读取必须显式声明默认值或处理 None**

## 审查流程规范

### 三问法
Major 问题须内联回答：
1. 用户影响是什么？
2. 利用条件是什么？
3. 现有缓解措施是什么？

### 升温机制
- 连续 3 轮未根治问题自动升温：major→critical
- 第 4 轮自动生成 issue
- suggestion 疲劳归档协议：第 1 轮未修复评估降级，第 2 轮强制降级，第 3 轮强制归档

### 增量审查补充规范
- 必须输出"已检查的规则清单"（最少 10 条）
- 必须输出"历史未解决问题清单并升温"
- 必须输出"未直接测试但依赖的调用链"
- 配置迁移 PR 必须输出"迁移完整性检查表"及"消费方隐式上限验证"
