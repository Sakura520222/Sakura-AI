# 项目记忆

## 常见代码问题和审查要点

- **路径规范化禁止使用lstrip/rstrip移除前缀**：必须用removeprefix，标major
- **内存回退字典必须实现大小/TTL限制**（参照OAuth state），标major
- **敏感secret不得通过前端表单往返**：必须服务端暂存（session/Redis），标blocking
- **安全操作失败必须记录审计日志**：2FA验证/绑定/重置失败必须记录security_audit_service，标major
- **所有用户输入验证端点必须有速率限制**：TOTP/passkey/恢复码验证均需@limiter，标major
- **策略模块中角色集合必须从VALID_USER_ROLES派生**，禁止独立硬编码，标major
- **所有策略函数必须复用公共守卫函数**（如_is_valid_role），禁止各自实现，标major
- **公共函数必须处理None/空值边界**，即使注释声称不会传None，标major
- **配置项必须被使用或删除**：死配置（如two_factor_verify_rate_limit无引用）标记，标minor→major（连续2轮升级）
- **测试必须覆盖降级路径**（Redis不可用时的回退行为），标minor
- **限流+超时成对检查后，必须检查降级路径是否同样有限流**，标major
- **GET+DELETE操作若有TOCTOU风险，必须注释说明并评估是否需要原子命令**，标minor

## 近期审查模式总结

- **连续未修问题升温**：同一问题连续2轮从suggestion升major，连续3轮阻断合并并自动生成issue
- **增量审查必须输出历史未解决问题清单并升温**，标注本次是否处理
- **回退字典类模式须全局一致性检查**：每次添加新的回退/降级机制，强制要求对照已有实现并输出对比表
- **行为等价性验证不能代替PR描述义务**：即使逻辑等价，权限语义变化仍应说明；若等价则不扣分
- **增量审查的“观察点”应附带行动项**（如“创建issue跟踪统一清理”）
- **审查前强制对照项目记忆前10条major规则**，逐条检查新代码是否违反
- **异步方法必须同步提供异步测试用例**，否则阻断合并

## 规范建议和经验教训

- **回退字典是“静默失败”的重灾区**：无监控、无过期、无上限会导致内存泄漏，必须统一抽取为TTLDict或RedisFallbackCache
- **“一次性secret”设计需明确用户体验边界**：验证失败即丢失，应在前端明确提示
- **配置服务抽象**：引入ConfigService统一封装配置降级逻辑，避免重复判断
- **模板JS函数复用**：禁止在两个以上模板中重复定义相同JS函数，应提取到静态文件
- **延迟导入滥用**：函数体内import若无注释说明循环引用原因，阻断合并
- **单一真实源强制执行**：有常量但未使用，审查时连续出现应升级为major

## 需要特别关注的领域

- **Redis不可用时的行为**：必须检查是否记录告警日志、回退是否有限制、恢复后能否无缝切回
- **WebAuthn审查清单**：挑战值存储（Redis）+超时+origin校验+防止重放+用户验证策略
- **TOTP集成审查清单**：secret生成（服务端）→展示→验证（暂存secret）→绑定→恢复码哈希存储
- **双重速率限制策略**：API层和WebUI层必须统一，不能一个有限制一个没有
- **权限策略单一真实源**：禁止新写内联角色判断，所有if user.role比较都应改为调用策略函数
- **路由层禁止直接操作数据库**：所有写操作下沉到Service层，标major
