# 项目记忆

## 审查模式与教训
- 规则与实际冲突须回溯适用性；分析否定须降级
- 路径安全证明须构造具体攻击路径；resolve()位置决定安全语义
- “部分修复”比“未修复”更危险；修复有效性须推演执行流，杜绝仅文档化假修复
- except ImportError是降级信号；回退链异常禁止NotImplementedError
- 增量审查陷阱：隧道视野、零评论高分、打勾陷阱、全局阻塞遗漏；幽灵变更须强制PR描述与审查覆盖一致性校验，遗漏即标[blocker]并降级；历史未闭环major/blocker必须作为前置检查项
- 评分决策解耦：未闭环critical时decision降级；硬规则major多轮未闭环至少降级为comment，quick下须显式列出开放阻塞项
- 防御代码隐形流失；遗留“存而不查”是假记忆
- 公开接口强制契约、错误处理、返回值语义三维度
- TOCTOU显式评估：“先查后操作”须评估并发；安全TOCTOU为系统性弱点，应推荐绑定操作消除窗
- 评论去重与合并：主评论禁复制摘要；suggestion禁粘贴表格/摘要片段
- 静默降级须声明注释并伴生监控/日志告警，缺失应提示silent-failure；当识别静默降级致功能完全失效，须主动打silent-failure标签，形成“现象→规则→标签”闭环；suggestion疲劳归档：第2轮未修复降级，第3轮强制归档
- 微小增量精简：quick下纯修复≤200字，不得遗漏实质性风险；若PR引用Issue须注明“可见范围内无法验证是否完全解决”，缺失则评分≤8且加[missing-statement]
- 历史问题消失检测：每轮清点上轮所有open项去向；空评论+高分组合信号
- 配置默认值变更强制评估攻击面/成本/兼容性，标major以上；硬规则major多轮未闭环应阻塞审查，第2轮仍未修复强制降级，连续N轮未修复须创建技术债Issue
- 生命周期方法（reset_/init_/close_）无调用点即为major
- 配置假值陷阱：统一用is not None，避免0/空合法值失效
- 已文档化风险不能标“已修复”，须归档为技术债务防假闭环
- 异步改造须考察取消与超时：run_in_executor无感知asyncio取消可能任务泄漏
- 假实现识别须回溯配置层；跨层截断为固有风险
- 微小增量同类调用扫描：用户输入交互API须全文扫描关键字符；涉及URL拼接/API路径的修复强制git grep扫描同类字面量，未扫描即approve视为流程违规
- 模式复制焦点转移：已验证一致转向“适配性”，显式列出差异点
- 容器/服务就绪轮询模式：任何轮询等待必须含超时检查和失败退出（exit≠0），缺失为major
- 增量审查若本次变更与阻塞项无关，仍不能直接approve，防止拆PR绕开把控
- API URL拼接陷阱：禁止base_url尾部带路径细节；HTTP客户端应全局启用重定向跟随或显式告警3xx非透明失败；修复须确认follow_redirects设置，优先检查重定向策略而非只修URL；配置base_url禁止包含API路径段，应拆分为base_url与api_path，历史遗留须声明注释并归档技术债
- 重复检测必须输出候选Issue标题/摘要并量化相似度，防止模糊“可能”导致假闭环；已关闭Issue再现应识别为regression，不可简单当重复；修复退化同样打regression标签
- 安全扫描类Issue强制打security标签；默认secret/key、API token经query参数传为高危必检；Setup免认证仅前端守卫属反模式，须强制网络层隔离或二次认证
- 文档归类类Issue须深挖文件扫描过滤逻辑、RAG索引等关键依赖，避免破坏现有功能
- 低置信度不相关标签应滤除以保持分析可信度
- 零评论高分是审查陷阱信号，approve也应留下简评记录已知未验证项
- 修复的局限性应主动归档为技术债Issue，避免经验流失与问题扩散
- HTTP客户端集成审查：必须确认是否启用重定向跟随（follow_redirects），否则至少标记suggestion，若可能致静默功能退化则升级major
- **强制一致性校验（major级别）**：审查前必须比对PR描述与diff内容，类型不符标[blocker]并阻塞；描述范围超出提交要求澄清
- **版本升级专项检查**：须确认pyproject.toml同步、CHANGELOG.md更新需求；patch版本需说明修复问题，否则标记suggestion
- **异步懒加载并发安全**：异步上下文懒加载须评估竞态条件，无锁保护应提示asyncio.Lock或future缓存
- **关键路径外部依赖错误隔离**：核心操作调第三方API必须捕获所有异常并记录日志，缺失标major；外部调用兜底若无异常捕获，视为假兜底
- **删除式修复验证规则**：通过完全删除代码修复问题时，须扫描被删元素的所有引用点（返回值字段、异常类型、日志标识符等），确认无遗留消费
- **增量审查回归风险评估**：须回答“是否存在因本次变更新增的未处理异常路径？”未回答时评分上限8分并留记录

## 代码高危区
- 路径安全：resolve()跟随symlink；三层防护范式
- 适配器接口契约；回退链异常语义；参数静默忽略
- 动态类型反模式；接口实现删除；结构化数据解析
- 降级链隔离；str.find()切片陷阱；无契约鸭子类型
- 去重key反模式；布尔参控制行为；错误处理策略分裂
- 双路径对称性；花括号注入
- SSRF防护：DNS重绑定、IP限制健壮性；TOCTOU窗口；Docker host网络、fetch_url策略为攻击面
- 配置双源同步一致性（内存与持久化）；配置默认值泄露
- 工具分组语义与权限开关的意外行为
- 服务/容器启动轮询无失败出口导致误导诊断
- API客户端URL拼接斜杠；HTTP 3xx非透明失败；缺失follow_redirects导致重定向丢失；配置隐式契约：base_url内嵌路径致调用方误用
- 文件扫描过滤逻辑与新增目录冲突；文档暗示支持但无对应逻辑的矛盾
- **异步懒加载+缓存并发**：实例属性缓存无锁保护导致竞态
- **版本号分散管理**：多文件硬编码版本号缺少单一来源，数据库脚本与代码耦合过紧
- **身份推断下沉**：依赖外部API自动推断身份须确认行为符合预期，避免下游系统匹配失败

## 严重程度判定
- 三问法强制绑定：[major]前内联答案；任一“无”自动降级
- 自评矛盾自动降级；纯可读性封顶suggestion
- 安全类禁止降级，且必须附security标签；评论格式硬校验：[major]/[critical]含文件:行号+问题+影响
- 分区标签解耦；quick噪声过滤（纯改善性建议不提）
- **幽灵变更升级**：PR描述与diff不一致标记[blocker]级别，非仅[missing]
- **假兜底升级**：外部调用兜底若无异常捕获，视为假兜底标major
