# 项目记忆

## 核心审查教训与模式

- **PR描述逐条可追溯**：增量审查必须将PR描述每条声称功能与变更文件逐一对应，缺失阻断合并，标critical
- **对称日志的全局嗅探**：修复某分支日志缺失时须扫描同一文件/模块的其他条件分支，避免点修复面遗漏，标minor
- **日志调用频率预判**：debug日志可能高频调用时审查建议评估采样或条件限制，标suggestion
- **前置+兜底设计模式**：webhook即时处理+worker全量保留，实现尽力而为且可降级，提炼为异常安全设计模式
- **并发去重评估**：原worker队列串行逻辑前置到webhook时须评估短时间重复事件对API配额影响，建议增加短期分布式锁，标suggestion
- **防御性函数假阴性审查**：函数返回0表示无操作时调用方须区分真无操作与调用失败，函数命名应明确，标major
- **bool是int子类的审查陷阱**：isinstance(v,int)过滤时若值域检查能排除False则安全，否则须改为type(v)is int并注释
- **上下文管理器退出行为验证**：async with session不自动commit，审查须确认具体实现文档
- **历史误判重新评估通道**：审查应保留重新评估能力，避免累积错误债务
- **session异常后状态污染**：捕获DB异常后session可能进入inactive，若后续使用须rollback或close重建，标major
- **批量删除函数须输出成功/失败计数及首个错误类型**，标minor
- **公共删除函数须注释是否在同一事务中**，标major

## 近期审查模式总结

- **连续未修问题升温**：历史已存在2轮的相同问题，下一轮从suggestion升为major
- **PR评分趋势分析**：连续多轮评分相同须说明为何未进步或债务被接受
- **增量审查必须输出历史未解决问题清单**并标注本次是否处理
- **模式嗅探**：发现常量提取时快速扫描其他.py文件是否存在同类硬编码
- **实例属性并发写入评估**：追踪所有写入实例属性的地方，评估实例是否被复用
- **幂等性日志的可观测平衡**：高频场景下跳过幂等性检查的日志改为条件变化时输出
- **防御性调用的假阴性审查**：函数声明异常时返回0时必须检查调用方是否真能容忍
- **webhook幂等性保护**：对于可能重复投递的事件，handler应实现基于pr_id+event_type的去重

## 需特别关注的领域

- **并发竞态**：webhook多次触发、worker队列去重丢失、短期重复事件
- **dismiss_bot_reviews假阴性风险**：网络超时返回0时无法区分真无操作与调用失败
- **SQLAlchemy异步session事务边界**：commit/flush/close/上下文管理器退出行为
- **返回值0的二义性**：0同时表示无操作和操作失败时调用方必须能区分
- **跨服务边界操作一致性声明**：同时操作DB和外部系统时标注原子/最终一致/尽力而为
- **异常日志敏感信息检查**：拼接str(e)时评估是否泄露表名、SQL片段
- **get_cached_config返回None的fallback**：所有调用点须记录警告日志
- **连续未修历史债务**：同一问题连续2轮标记后自动生成issue，连续3轮阻断合并
- **增量审查空洞批准预防**：首次全量审查至少5条评论
- **工具循环复用中的副作用注释**：公共方法修改传入列表须用⚠️副作用标注
