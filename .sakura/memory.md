# 项目记忆

## 核心审查教训与模式

- **双重处理陷阱**：同一格式化函数在调用链重复执行，扫描数据全路径同名调用，标critical
- **服务层职责模糊**：comment_service为评论渲染唯一入口，禁止上游预渲染；违反标critical
- **历史问题闭环验证**：声称修复须列出所有调用位置、冲突消除证据，缺失触发missing-statement
- **增量审查陷阱**：隧道视野致配置假开关、数据流断裂；必须扫描受改动字段影响的下游模块；发现新字段须追踪全生命周期，缺环节标major
- **降级标志全生命周期追踪**：引入布尔降级标志时，必须检查所有赋值点、重置点、使用点，确保无路径绕过；缺失标major。扩展规则：必须覆盖SQL迁移、UI配置映射、热更新兼容性、测试覆盖共7个消费点
- **异常处理器顺序敏感性**：多个@app.exception_handler注册顺序决定优先级，标major
- **跨层导入强制注释**：API模块从WebUI层导入依赖时，必须注释理由，否则标minor
- **全局异常处理器禁止引用业务依赖**：不得解析token、查数据库、调用get_settings()，违反标major
- **重复代码提取权衡性能**：高频场景6次以上独立调用需批量聚合，标suggestion
- **静默异常禁止**：所有`except Exception`必须记录日志（顶级循环除外），违反标major
- **可变单例并发安全**：@lru_cache返回的对象若被setattr修改，须注释并发安全策略，标minor
- **语义版本验证**：版本号升级时须检查变更幅度与PR描述是否对齐，缺失标suggestion
- **配置热更新验证**：新增动态配置字段必须说明是否支持运行时热更新，缺失标major
- **注释与UI分组一致性**：字段声明的注释分组必须与UI分组实际归属一致，标minor

## 代码高危区
- 降级标志相关代码路径（微小但影响全局）
- 批量冲突检测中的动态集合维护
- PyGithub的get_contents()多态返回处理
- 配置解析中的隐式split拆分
- 混合认证场景（API与WebUI共用依赖注入）
- Telegram Update对象的message/callback_query多态访问
- 全局异常处理器中的业务依赖调用
- 多语言版本号硬编码点（Python + SQL）

## 近期审查模式总结
- **配置全链路追踪**：新增配置字段须验证定义→分组→标签→SQL初始化（含迁移脚本）→所有消费点→热更新→测试覆盖，缺一环节标major
- **增量审查必须扫描PR描述中的所有提及文件**：即使提交列表不含某文件，若PR描述提到（如SQL、UI），必须确认是否已存在或被遗漏，否则标major
- **重复逻辑阈值判断**：两处重复可容忍但须加注释标记未来重构点；出现第三处必须提取共享函数
- **开关可观测性强制**：新增降级/功能开关必须在关键路径记录info日志（含开关状态），高频路径用debug级别
- **死代码保留须注释**：保留未调用的条件分支时，必须注释预期调用者或未来用途，否则标minor
- **SQL字段默认值安全**：新增布尔开关默认True保持旧行为，INSERT须用IGNORE或ON DUPLICATE KEY UPDATE确保幂等

## 需特别关注的领域
- **跨语言版本同步**：Python main.py/auth.py + SQL init.sql + 迁移脚本必须构建时注入，防漂移
- **增量审查的风险升温检测**：历史问题在新功能上线后可能升级严重度
- **测试真实性验证**：mock必须匹配实际异常类型，断言异常路径被真正触发
- **并发竞态**：update_settings_field的setattr操作在异步环境需加锁评估
- **配置字段全生命周期清单**：定义→分组→标签→SQL初始化（含迁移）→所有消费点→热更新→单元测试
