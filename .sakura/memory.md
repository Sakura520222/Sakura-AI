## 常见代码问题和审查要点

- **命令扩展类 Issue 审查规范**：新增命令需强制检查权限跳过逻辑的注释规范（标major），并评估异步路由中的同步 I/O 阻塞风险
- **配置语义变更审查规范**：配置语义变更需强制要求输出"配置迁移完整性检查表"，验证全链路对齐
- **数据库 schema 变更审查规范**：需强调迁移脚本的向后兼容性测试，包括已有部署的 ALTER TABLE 语句
- **支付类 Issue 安全审查规范**：支付功能需重点关注安全配置（密钥加密）、回调幂等性、退款流程
- **PR 描述一致性检查**：强制要求 PR 描述与实际变更文件列表一致，避免审查资源浪费
- **JSON解析安全规范**：明确解析不完整JSON时的容错策略，标major
- **公共函数调用点全量检查**：增量审查中必须列出并验证所有调用点，避免功能碎片化，标major
- **异步路由中的同步I/O阻塞**：必须使用 `asyncio.to_thread()` 包装，标major
- **i18n 键完整性**：新增 UI 元素必须同步更新翻译文件，缺失则阻断合并，标major
- **路径规范化规则细化**：禁止使用`lstrip/rstrip`移除前缀/后缀，必须使用`removeprefix/removesuffix`，标major
- **公共工具函数必须处理None/空值边界**：必须增加防御性检查，标major
- **session异常后状态污染**：捕获DB异常后必须显式rollback()或close()，标major
- **明文敏感字段存储必须加密**：新增DB列存储api_key/secret/token时必须使用加密，标阻断
- **新增状态枚举的全链路审查**：必须检查DB ENUM/迁移、历史数据回填、API返回、WebUI模板/i18n/过滤器等，标major
- **延迟导入必须注释原因**：函数体内import若无注释说明循环引用原因，阻断合并，标major
- **配置变更的"迁移完整性检查表"**：验证所有读取/写入位置是否对齐，标major
- **动态配置降级处理**：新增配置读取必须检查None/非法值场景，提供降级逻辑，标major

## 架构与模式审查要点

- **JSON解析场景需特别关注**：转义顺序、边界条件，建议引入单元测试
- **函数提取重构后必须检查**：是否所有调用点均使用新函数
- **全量重审价值**：功能重构后强制执行全量审查，识别系统性问题
- **配置体系扩展应优先复用动态配置体系**：避免硬编码，标major
- **延迟导入的并发安全性**：项目使用异步路由，需评估延迟导入在多线程/协程下的竞态条件

## 审查流程与质量控制

- **Issue 分类准确性检查**：对 `question` 类 Issue，优先检查代码/文档是否已覆盖，避免过度标记为缺陷
- **PR 描述与变更一致性验证**：强制要求 PR 描述与实际变更文件列表一致，审查前首先验证文件清单
- **增量审查必须检查关联文件**：强制检查相关翻译文件、路由配置和i18n键完整性
- **全量审查触发条件**：功能重构或新增模块后强制执行全量审查
- **历史问题修复验证**：必须结合测试用例验证功能完整性
- **大型PR强制拆分审查**：大型PR必须强制拆分审查，避免单次审查覆盖度不足

## 经验教训与最佳实践

### Issue 分析与管理
- **命令扩展类 Issue 分析**：需强制检查权限跳过逻辑的注释规范，并评估异步路由中的同步 I/O 阻塞风险
- **配置语义变更分析**：需强制要求输出"配置迁移完整性检查表"，验证全链路对齐
- **支付类 Issue 分析**：需重点关注安全配置、回调幂等性、退款流程，避免遗漏关键风险
- **Question 类 Issue 处理**：优先检查代码/文档是否已覆盖，避免过度标记为缺陷

### 延迟导入与循环依赖
- **延迟导入注释规范**：必须严格执行注释规范，避免因注释缺失导致循环依赖问题被忽略，标major
- **延迟导入的并发安全性**：项目使用异步路由，需评估延迟导入在多线程/协程下的竞态条件

### 配置管理
- **配置清洗抽象**：配置清洗逻辑应统一为工具函数，并在保存和读取时强制调用，避免分散实现
- **配置清洗完整性检查**：配置变更 PR 必须验证所有读取/写入位置是否对齐清洗逻辑

### 安全审查
- **Shell 工具安全**：Shell 工具是安全关键组件，审查热点集中于此，需定期添加单元测试覆盖边缘案例
- **工具安全边界**：新增工具必须检查命令链绕过风险，标记为 major

### 异常处理
- **SSE 异常静默风险**：SSE 体系异常静默是高风险模式，会导致问题难以排查，必须强制日志记录
- **异常日志级别统一规范**：明确 `except Exception` 后的日志级别标准，强制审查
