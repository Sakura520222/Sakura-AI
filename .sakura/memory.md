# 项目记忆

## 常见代码问题和审查要点

- **路径规范化禁止使用lstrip/rstrip移除前缀**：移除固定前缀必须使用`removeprefix`，禁止使用`lstrip`(字符集语义)，标major
- **Mermaid标签必须完整转义**：生成图表标签时必须转义`& < > { } [ ] ( ) # % |`所有特殊字符，或使用Base64编码，标major
- **清理函数入参None安全性**：公共清理函数接收可能为None的DB对象时，必须检查内部是否安全处理None，标major
- **返回值语义变更须同步调用方**：函数返回值语义变更时检查调用方变量名是否保持语义一致，跨文件超过3处升级为major
- **取消路径必须抽取公共清理函数**：凡有2个及以上取消/中断检查点，必须复用同一清理函数，标major
- **新增状态枚举的全链路审查**：新增枚举值必须检查DB ENUM/迁移、历史数据回填、API返回、WebUI模板/i18n/过滤器、SSE事件发送与前端接收，标major
- **延迟导入必须注释原因**：函数体内import若无注释说明循环引用原因，阻断合并，标major
- **session异常后状态污染**：捕获DB异常后session可能inactive，必须显式rollback()或close()，禁止仅注释声称“自动恢复”，标major
- **惰性重置遗漏读取路径**：所有读取用户配额/限流/统计类字段的路径必须调用重置/刷新函数，标major
- **批量UPDATE返回值语义必须明确**：若返回`rowcount`累加值，必须在函数名或docstring中明确说明语义；推荐返回`ResetResult`结构体，标major
- **列表页禁止逐个或批量嵌入写操作**：除非有明确性能评估(用户量<500且操作轻量，须注释假设)，否则列表分页内不应触发配额重置等写操作，标major
- **新增调度器时区须对齐项目默认时区**，且必须验证启动钩子(startup_event/lifespan)中正确注册，标major
- **正则提取import必须记录失败日志**：静态分析中正则提取失败时至少`logger.warning`，并明确回退路径，标major
- **正则编译必须提升到模块级别**：禁止在函数/方法内重复编译正则表达式，标major
- **批量UPDATE必须在一个事务中原子执行**：若循环执行多条UPDATE，必须使用`begin_nested()`或单条CASE WHEN语句，避免部分成功，标major
- **只读接口中禁止嵌入写操作**：包括批量写，例外需注释用户量上限、操作开销评估，标major
- **动态配置的持久化必须唯一真实源**：禁止同时写入YAML和DB作为平等源，应明确主从关系，标major
- **惰性重置函数必须幂等**：通过`last_reset_at`或条件`WHERE quota > 0`避免重复置零，标major
- **使用`setattr`修改ORM字段前必须校验字段存在性**：建议使用`hasattr`或改用字典更新，标minor
- **副作用函数命名必须明确**：若函数在特定参数下会修改状态，函数名或参数名必须显式提示，docstring中用`⚠️`标注，标major
- **外部写入失败后须记录可恢复警告**：当DB已提交但外部文件写入失败时，必须记录`error`级别日志并说明不一致风险，标major
- **用户级配置项接入时必须扫描所有入口**：新增配置项时必须列出所有可能获取user_id的入口（webhook、定时任务、WebUI、API、bot），标major
- **热路径配置查询必须评估性能影响**：在循环或高频调用的位置查询用户配置时，必须评估DB查询频率和缓存命中率，标major
- **配置降级必须记录日志**：当无法获取user_id导致使用默认配置时，必须记录warning日志，标minor

## 近期审查模式总结

- **连续未修问题升温**：同一问题连续2轮从suggestion升major，连续3轮阻断合并并自动生成issue
- **增量审查必须输出历史未解决问题清单并升温**：标注本次是否处理，未处理须说明理由；同时输出来自未修改文件的受影响调用方列表
- **公共函数副作用须用⚠️标注**：修改传入列表或对象状态时必须在docstring中标注
- **返回值语义变更的强制扫描**：返回值类型/含义变化时，必须扫描所有调用方(含跨仓库)
- **调用方扫描强制执行**：修改变更文件时须扫描导入该模块的所有调用方，增量审查不得遗漏
- **静态分析降级路径一致性**：失败时必须明确记录日志并对外暴露降级状态(如响应头)，审查时优先检查
- **事务与外部写入顺序检查**：先提交DB再写外部文件是常见反模式，审查时优先检查顺序
- **全量审查价值**：对于涉及全局行为变更(配额、调度器、配置穿透)的PR，即使增量审查已完成，也建议合并前进行一次聚焦该特性的全量审查
- **跨语言常量漂移检查**：当Python侧定义`__version__`时，必须检查SQL脚本、YAML、docker-compose中的版本/镜像标签；无法同步的位置须添加注释关联源文件

## 规范建议和经验教训

- **复合返回值的风险**：字符串拼接返回值不易扩展且调用方难以类型安全使用，优先使用结构化类型(NamedTuple/dataclass)
- **状态变更全链路清单标准化**：建议创建固定检查表(DB ENUM→模型枚举→API序列化→WebUI模板→i18n→SSE事件→状态转换矩阵)
- **SQLAlchemy异步session陷阱**：捕获异常后session进入inactive，仅rollback()可恢复但会丢弃未提交变更；优先使用`async with session.begin()`模式
- **配额类问题分析模板**：定位所有写入/消耗路径+所有读取路径(是否调用重置)，重点检查WebUI、API、定时报表、管理员面板、Telegram命令
- **静态分析降级方案**：对import提取等正确率约80-90%的正则方案，必须明确失败降级策略(回退到AI模式或显示错误)
- **Python相对导入规范化**：区分Python点式导入与JS/TS路径导入，拆分为独立函数处理
- **Mermaid标签编码**：可考虑Base64编码整个标签内容彻底避免语法冲突，但会降低可读性
- **lstrip的双重面孔**：禁止用于前缀移除，但允许用于字符集语义，审查需区分场景
- **批量重置操作阈值**：若用户量<500且操作轻量可允许N+1，但注释中必须写明性能假设和预估用户数
- **配置服务抽象**：建议引入ConfigService类统一封装配置降级逻辑，避免重复判断代码

## 需特别关注的领域

- **取消/中断检查点的一致性**：所有取消路径的资源清理必须统一，避免遗留状态
- **asyncio并发竞态**：webhook多次触发、配额重置并发幂等性、Event注册/注销配对
- **SQLAlchemy异步session事务边界**：取消路径中检查session有效性，异常后重建；禁止在非独占session的库函数中调用rollback()
- **返回值0的二义性**：函数返回0无法区分真无操作与调用失败，建议返回tuple或自定义结果对象
- **SSE事件发送与接收**：新增状态时必须检查所有发送SSE事件的点是否覆盖该状态
- **状态机完整性**：引入新状态时必须审查所有状态转换路径、回退是否允许
- **WebUI直接读库绕过业务逻辑**：审查所有展示配额/使用量的SQL/ORM查询，判断是否绕过了重置/刷新函数
- **路由层禁止直接操作数据库**：所有写操作必须下沉到Service层，标major
- **配置动态刷新统一性**：避免手动调用`invalidate_xxx_cache`的零散方式，应封装为配置服务的统一方法
- **委托模式审查清单**：行为等价性、调用链循环依赖、异常传播一致性、纯函数无副作用
- **正则提取import边界情况**：多行import、f-string内假import、注释中语句，须要求提供反例测试
