## 常见代码问题和审查要点

- **全量审查在功能重构后必要**：增量审查可能遗漏系统性、跨文件问题，功能重构或新增模块后应强制执行全量审查，标major
- **异步路由中的同步I/O阻塞**：在 async 路由中直接调用同步 API 是常见反模式，必须使用 `asyncio.to_thread()` 或 `run_in_executor()` 包装，标major
- **i18n 键完整性**：新增 UI 元素必须同步更新翻译文件，缺失则阻断合并，标major
- **CSRF 策略文档化**：JSON API 与表单 CSRF 差异需在代码注释或文档中说明，避免混淆，标minor
- **路径规范化禁止使用lstrip/rstrip移除前缀**：移除固定前缀必须使用`removeprefix`，禁止使用`lstrip`(字符集语义)，标major
- **公共工具函数必须处理None/空值边界**：即使注释声称"调用方不会传None"，也必须增加防御性检查，标major
- **新增公共函数必须包含docstring**：说明输入输出边界行为（如None→""），标minor
- **Mermaid标签必须完整转义**：生成图表标签时必须转义特殊字符或使用Base64编码，标major
- **清理函数入参None安全性**：公共清理函数接收可能为None的DB对象时，必须检查内部是否安全处理None，标major
- **返回值语义变更须同步调用方**：函数返回值语义变更时检查调用方变量名是否保持语义一致，跨文件超过3处升级为major
- **新增状态枚举的全链路审查**：新增枚举值必须检查DB ENUM/迁移、历史数据回填、API返回、WebUI模板/i18n/过滤器、SSE事件发送与前端接收，标major
- **延迟导入必须注释原因**：函数体内import若无注释说明循环引用原因，阻断合并，标major
- **session异常后状态污染**：捕获DB异常后session可能inactive，必须显式rollback()或close()，禁止仅注释声称"自动恢复"，标major
- **明文敏感字段存储必须加密**：新增DB列存储api_key/secret/token时必须使用加密，标阻断
- **API返回结构必须统一**：新增端点应返回{success,data,message}结构，标major
- **新增配置体系扩展应优先复用动态配置体系**：避免硬编码，标major
- **新功能请求应明确操作范围和权限边界**：避免过度暴露敏感功能，标major
- **涉及 UI 和权限的功能需优先检查现有模板和路由模式**：评估可行性时参考现有架构，标major
- **重复检测需谨慎核对历史 Issue**：避免误判重复，需手动核实历史 Issue 内容，标minor
- **新增功能涉及 UI 修改时应补充标签**：如 `webui` 标签，提升可检索性，标minor
- **配置迁移完整性检查**：对于配置体系变更 PR，强制输出"迁移完整性检查表"，列出旧配置到新读取方式的替换路径，并验证所有读取/写入位置是否对齐，标minor
- **动态配置降级处理**：新增配置读取时必须检查 `get_dynamic_config` 返回 None 或类型不匹配的场景，并提供降级逻辑或显式报错，标major
- **WebUI前后端一致性**：新增 WebUI 配置项需检查前端表单字段与后端元数据分组是否匹配，避免用户困惑，标minor
- **增量审查必须检查关联文件**：当变更涉及 UI 模板时，强制检查相关翻译文件、路由配置和 i18n 键完整性，避免功能碎片化，标major
- **全量审查触发条件**：功能重构或新增模块后，强制执行全量审查（标记为Major），避免增量审查遗漏系统性问题

## 架构与模式审查要点

- **异步框架中同步库混用风险**：技术模式审查需优先检查事件循环阻塞点
- **全量重审价值**：功能重构后强制执行全量审查，识别系统性、跨文件问题
- **ChromaDB 操作封装**：将同步 I/O 抽取为独立线程池服务，统一管理事件循环阻塞风险
- **Alpine.js 作用域安全**：模板中动态数据绑定需使用 `@submit.prevent` 或数据属性，避免原生 JS 与响应式数据冲突
- **异步路由同步I/O检测**：在CI中集成静态检查，自动标记async路由中的同步调用（如ChromaDB直接调用）
- **参数传递一致性检查**：对公共函数（如`detect_language()`）新增参数审计规则，确保所有调用点传参一致
- **修复-回归循环防范**：对反复出现的问题（如参数缺失），需在审查中明确要求开发者提供全局修复证据

## 配置管理审查要点

- **配置体系扩展应优先复用动态配置体系**：避免硬编码，标major
- **配置迁移PR必须输出"迁移完整性检查表"**：列出旧配置名称→新读取方式→所有读取位置是否替换→写入位置是否对齐，标minor
- **动态配置读取调用方须处理None/非法值**：`get_dynamic_config`返回None或类型不匹配时，必须有降级或显式报错，标major
- **配置变更PR应优先检查跨文件配置同步问题**：尤其是Setup Wizard与服务层逻辑的一致性，标major
- **复用配置字段需明确文档化**：管理员Issue配额复用PR配额的设计需添加注释说明意图，避免未来误改

## 审查流程与质量控制

- **增量审查必须检查关联文件**：当变更涉及 UI 模板时，强制检查相关翻译文件、路由配置和 i18n 键完整性，避免功能碎片化
- **全量审查触发条件**：功能重构或新增模块后，强制执行全量审查，避免增量审查遗漏系统性问题
- **审查覆盖度下降风险防范**：增量审查未检查i18n键完整性，建议在CI中增加自动化检查
- **历史问题追踪**：对反复出现的问题，需在审查中明确要求开发者提供全局修复证据
