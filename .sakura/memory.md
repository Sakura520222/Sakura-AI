# 项目记忆

## 常见代码问题和审查要点

- **清理函数入参None安全性**：公共清理函数接收可能为None的DB对象时，必须检查内部是否安全处理None，标major
- **UUID截断必须注释**：任何将UUID截断（如[:8]）用于标识的代码，必须注释说明用途、碰撞概率、不用于持久化唯一键，标minor
- **返回值语义变更须同步调用方变量名**：函数返回值语义变更时检查调用方变量名是否保持语义一致，标suggestion
- **取消路径必须抽取公共清理函数**：凡有2个及以上取消/中断检查点，必须复用同一清理函数，标major
- **新增状态枚举的全链路审查**：新增枚举值必须检查数据库ENUM、历史数据回填、API返回、WebUI模板/过滤器/i18n、SSE事件，标major
- **并发模型注释强制**：实例级可变状态用于async单例时，必须注释依赖asyncio单线程或无竞态，标minor
- **延迟导入必须注释原因**：函数体内import若无注释说明循环引用原因，阻断合并，标major
- **bool是int子类的审查陷阱**：isinstance(v,int)过滤时若值域检查能排除False则安全，否则改为type(v)is int并注释
- **session异常后状态污染**：捕获DB异常后session可能inactive，若后续使用须rollback或close重建，标major

## 近期审查模式总结

- **连续未修问题升温**：同一问题连续2轮从suggestion升major，连续3轮阻断合并并自动生成issue
- **增量审查必须输出历史未解决问题清单**：标注本次是否处理，未处理须说明理由
- **公共函数副作用须用⚠️标注**：修改传入列表或对象状态时必须在docstring中标注
- **幂等性日志平衡**：高频场景跳过检查的日志改为条件变化时输出
- **多检查点行为收敛**：多阶段长任务取消检查点行为差异须在方法注释中说明

## 规范建议和经验教训

- **返回值语义分离**：task_key（业务标识）与task_id（日志追踪）解耦是良好关注点分离
- **asyncio Event取消模式**：Event仅信号不支持取消原因，如需传递改用Queue或Future
- **复合返回值的风险**：字符串拼接返回值不易扩展且调用方难以类型安全使用，优先使用结构化类型
- **增量审查的调用方检查**：修改变更文件时须扫描导入该模块的所有调用方
- **注释vs结构决策**：若设计缺陷用注释而非代码修复，审查应追问未来修改者是否可能忽略注释
- **连续多轮major集中模块**：应建议暂停新功能专门重构该模块

## 需特别关注的领域

- **取消/中断检查点的一致性**：所有取消路径的资源清理必须统一，避免遗留状态
- **asyncio并发竞态**：webhook多次触发、Event注册/注销配对、单例跨event loop使用
- **SQLAlchemy异步session事务边界**：取消路径中检查session有效性，异常后重建
- **返回值0的二义性**：dismiss_bot_reviews等函数返回0无法区分真无操作与调用失败
- **SSE事件发送**：新增状态时必须检查所有发送SSE事件的点是否覆盖该状态
- **状态机完整性**：引入新状态时必须审查所有状态转换路径和回退是否允许
