## 常见代码问题和审查要点

- **全量审查在功能重构后必要**：增量审查可能遗漏系统性、跨文件问题，功能重构或新增模块后应强制执行全量审查，标major
- **异步路由中的同步I/O阻塞**：在 async 路由中直接调用同步 API 是常见反模式，必须使用 `asyncio.to_thread()` 包装，标major
- **i18n 键完整性**：新增 UI 元素必须同步更新翻译文件，缺失则阻断合并，标major
- **路径规范化禁止使用lstrip/rstrip移除前缀**：移除固定前缀必须使用`removeprefix`，禁止使用`lstrip`，标major
- **公共工具函数必须处理None/空值边界**：即使注释声称"调用方不会传None"，也必须增加防御性检查，标major
- **新增公共函数必须包含docstring**：说明输入输出边界行为，标minor
- **Mermaid标签必须完整转义**：生成图表标签时必须转义特殊字符或使用Base64编码，标major
- **session异常后状态污染**：捕获DB异常后session可能inactive，必须显式rollback()或close()，标major
- **明文敏感字段存储必须加密**：新增DB列存储api_key/secret/token时必须使用加密，标阻断
- **API返回结构必须统一**：新增端点应返回{success,data,message}结构，标major
- **新增配置体系扩展应优先复用动态配置体系**：避免硬编码，标major
- **新增状态枚举的全链路审查**：新增枚举值必须检查DB ENUM/迁移、历史数据回填、API返回、WebUI模板/i18n/过滤器、SSE事件发送与前端接收，标major
- **延迟导入必须注释原因**：函数体内import若无注释说明循环引用原因，阻断合并，标major
- **配置字段复用需文档化**：管理员 Issue 配额复用 PR 配额的设计需添加注释说明意图，标minor
- **配额计算防护逻辑**：配额计算中的 `max(1, ...)` 防护值得推广，标major
- **增量变更上下文影响检查**：增量审查需检查变更是否影响已缺失的 i18n 键或其他依赖项，标major
- **公共端点依赖风险评估**：对于依赖第三方公开API/端点的变更，强制要求添加注释说明稳定性假设及降级方案（如返回默认头像），标minor
- **辅助函数复用强制检查**：若新增逻辑与现有辅助函数功能重叠，必须复用或重构，避免技术债务累积，标minor
- **认证流程一致性**：明确Passkey与OAuth在头像获取、token构建等环节的统一模式，建议在`auth.py`顶部添加架构说明注释
- **GitHub头像URL规范**：统一使用重定向端点（`avatars.githubusercontent.com/{username}`）而非API端点，以减少认证依赖和延迟
- **配置迁移完整性检查**：对于配置体系变更PR，强制输出"迁移完整性检查表"，验证所有读取/写入位置是否对齐，标minor
- **动态配置降级处理**：新增配置读取时必须检查`get_dynamic_config`返回None或类型不匹配的场景，并提供降级逻辑或显式报错，标major
- **WebUI前后端一致性**：新增WebUI配置项需检查前端表单字段与后端元数据分组是否匹配，避免用户困惑，标minor

## 架构与模式审查要点

- **异步框架中同步库混用风险**：技术模式审查需优先检查事件循环阻塞点
- **全量重审价值**：功能重构后强制执行全量审查，识别系统性、跨文件问题
- **Alpine.js 作用域安全**：模板中动态数据绑定需使用 `@submit.prevent` 或数据属性，避免原生 JS 与响应式数据冲突

## 配置管理审查要点

- **配置体系扩展应优先复用动态配置体系**：避免硬编码，标major
- **配置迁移PR必须输出"迁移完整性检查表"**：列出旧配置名称→新读取方式→所有读取位置是否替换→写入位置是否对齐，标minor
- **动态配置读取调用方须处理None/非法值**：`get_dynamic_config`返回None或类型不匹配时，必须有降级或显式报错，标major
- **配置变更PR应优先检查跨文件配置同步问题**：尤其是Setup Wizard与服务层逻辑的一致性，标major
- **复用配置字段需明确文档化**：管理员Issue配额复用PR配额的设计需添加注释说明意图，避免未来误改
- **WebUI前后端配置一致性**：新增WebUI配置项需检查前端表单字段与后端元数据分组是否匹配，避免用户困惑
- **配置变更跨文件一致性检查**：对于涉及配置分组、字段移动的PR，强制检查所有相关服务层文件中对同一配置字段的引用是否同步更新，并验证注释风格统一

## 审查流程与质量控制

- **增量审查必须检查关联文件**：当变更涉及 UI 模板时，强制检查相关翻译文件、路由配置和 i18n 键完整性，避免功能碎片化
- **全量审查触发条件**：功能重构或新增模块后，强制执行全量审查，避免增量审查遗漏系统性问题
- **审查质量评估框架**：覆盖度、准确度、完整性三个维度评估审查质量
- **增量变更上下文影响**：检查变更是否影响已缺失的 i18n 键或其他依赖项
- **配置变更跨文件同步**：配置变更 PR 应优先检查跨文件配置同步问题
- **配置迁移完整性检查**：对于配置体系变更 PR，强制输出"迁移完整性检查表"，验证所有读取/写入位置是否对齐
- **增量审查关联文件检查清单**：当变更涉及配置、UI模板时，强制列出并检查关联的翻译文件、前端表单、路由配置，避免功能碎片化
- **配置变更的"迁移完整性检查表"**：即使本次PR未涉及旧配置迁移，也应输出检查表，验证所有读取/写入位置是否对齐，这是配置体系变更的major要求

## UI 与模板审查要点

- **i18n 键完整性**：新增 UI 元素必须同步更新翻译文件，缺失则阻断合并，标major
- **CSRF 策略文档化**：JSON API 与表单 CSRF 差异需在代码注释或文档中说明，避免混淆，标minor
- **新增WebUI模块必须检查"四一致"**：侧边栏链接、表单action、JS fetch、重定向URL与路由前缀一致，标major
- **UI引导提示须确认i18n键的渲染安全性**：检查翻译内容是否包含未转义的HTML/JS，标minor
- **Alpine.js安全模式**：禁止在模板中使用原生JS事件处理，强制使用`x-on`指令和数据属性
