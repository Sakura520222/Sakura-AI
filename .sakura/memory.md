# 项目记忆

## 常见代码问题和审查要点

- **路径规范化禁止使用lstrip/rstrip移除前缀**：移除固定前缀(如`./`)必须使用`removeprefix`(Python 3.9+)或`startswith`+切片，禁止使用`lstrip`(字符集语义)，标major
- **Mermaid标签必须完整转义**：生成图表标签时必须转义`& < > { } [ ] ( ) # % |`所有特殊字符，或使用Base64编码，标major
- **路径别名解析须显式声明映射**：使用`@/`等别名时，若未从tsconfig/jsconfig读取真实映射，必须在注释中说明假设条件，避免隐式行为，标major
- **清理函数入参None安全性**：公共清理函数接收可能为None的DB对象时，必须检查内部是否安全处理None，标major
- **UUID截断必须注释**：任何将UUID截断(如[:8])用于标识的代码，必须注释说明用途、碰撞概率、不用于持久化唯一键，标minor
- **返回值语义变更须同步调用方**：函数返回值语义变更时检查调用方变量名是否保持语义一致，标suggestion；跨文件超过3处升级为major
- **取消路径必须抽取公共清理函数**：凡有2个及以上取消/中断检查点，必须复用同一清理函数，标major
- **新增状态枚举的全链路审查**：新增枚举值必须检查DB ENUM/迁移、历史数据回填、API返回、WebUI模板/i18n/过滤器、SSE事件发送与前端接收，标major
- **并发模型注释强制**：实例级可变状态用于async单例时，必须注释依赖asyncio单线程或无竞态，标minor
- **延迟导入必须注释原因**：函数体内import若无注释说明循环引用原因，阻断合并，标major
- **session异常后状态污染**：捕获DB异常后session可能inactive，必须显式rollback()或close()，禁止仅注释声称“自动恢复”，标major
- **批量操作使用savepoint而非全局rollback**：循环中调用含rollback()的函数，建议使用begin_nested()，标suggestion
- **静默覆盖资源必须记录日志**：替换/覆盖Event、Lock、Queue时，必须记录debug日志，标major
- **惰性重置遗漏读取路径**：所有读取用户配额/限流/统计类字段的路径(WebUI、API、管理员面板、Telegram命令)必须调用重置/刷新函数，标major
- **批量UPDATE返回值语义必须明确**：若返回`rowcount`累加值，必须在函数名或docstring中明确说明语义，避免误导，标major
- **列表页禁止逐个调用写操作**：除非有明确性能评估，否则列表分页内不应逐个触发配额重置、更新等操作，标major
- **新增调度器时区须对齐项目默认时区**：防止因时区误解导致业务逻辑错误，标minor
- **正则提取import必须记录失败日志**：静态分析中正则提取失败时至少`logger.warning`，避免静默生成不完整结果，标minor

## 近期审查模式总结

- **连续未修问题升温**：同一问题连续2轮从suggestion升major，连续3轮阻断合并并自动生成issue；实际风险低时可在PR中显式记录决策理由豁免
- **增量审查必须输出历史未解决问题清单并升温**：标注本次是否处理，未处理须说明理由；同时须输出来自未修改文件的受影响调用方列表；按升温规则更新严重度
- **公共函数副作用须用⚠️标注**：修改传入列表或对象状态时必须在docstring中标注
- **幂等性日志平衡**：高频场景跳过检查的日志改为条件变化时输出；幂等性注释必须包含“对不存在的记录”行为
- **返回值语义变更的强制扫描**：返回值类型/含义变化时，必须扫描所有调用方(含跨仓库如Telegram模块)
- **版本号单一真实源**：项目必须定义唯一版本号来源，其他位置通过导入引用
- **调用方扫描强制执行**：修改变更文件时须扫描导入该模块的所有调用方及API响应消费者，增量审查不得遗漏

## 规范建议和经验教训

- **路径别名解析的脆弱性**：`@/components/Header`能否匹配到正确文件取决于别名生成策略的唯一性，嵌套目录可能匹配错误；应要求审查别名生成策略并注释假设
- **复合返回值的风险**：字符串拼接返回值不易扩展且调用方难以类型安全使用，优先使用结构化类型(NamedTuple/dict)
- **注释vs结构决策**：若设计缺陷用注释而非代码修复，审查应追问未来修改者是否可能忽略注释
- **连续多轮major集中模块**：应建议暂停新功能专门重构该模块
- **状态变更全链路清单标准化**：建议创建固定检查表(DB ENUM→模型枚举→API序列化→WebUI模板→i18n→SSE事件→状态转换矩阵→前端JS接收)
- **SQLAlchemy异步session陷阱**：捕获异常后session进入inactive，仅rollback()可恢复但会丢弃未提交变更；优先使用async with session.begin()模式
- **配额类问题分析模板**：定位所有写入/消耗路径(重置逻辑是否触发)+所有读取路径(是否调用重置)，重点检查WebUI、API、定时报表、Webhook、管理员面板、Telegram命令
- **静态分析降级方案**：对import提取等正确率约80-90%的正则方案，必须明确失败降级策略(回退到AI模式或显示错误提示)
- **节点裁剪算法需保证连通性**：简单取前N个节点可能产生孤立子图，优先保留入度/出度高的节点或使用强连通分量算法

## 需特别关注的领域

- **取消/中断检查点的一致性**：所有取消路径的资源清理必须统一，避免遗留状态；取消检查点传递的变量必须与当前实际值一致
- **asyncio并发竞态**：webhook多次触发、Event注册/注销配对、单例跨event loop使用
- **SQLAlchemy异步session事务边界**：取消路径中检查session有效性，异常后重建；禁止在非独占session的库函数中调用rollback()
- **返回值0的二义性**：函数返回0无法区分真无操作与调用失败，建议返回tuple或自定义结果对象
- **SSE事件发送与接收**：新增状态时必须检查所有发送SSE事件的点是否覆盖该状态，以及前端JS/EventSource监听器是否处理该状态
- **状态机完整性**：引入新状态时必须审查所有状态转换路径、回退是否允许
- **API响应字段语义漂移**：字段名变更须评估breaking change风险等级，若有外部依赖须同步更新文档
- **WebUI直接读库绕过业务逻辑**：审查所有展示配额、使用量的SQL/ORM查询，判断是否绕过了重置/刷新函数
- **路由层禁止直接操作数据库**：所有写操作必须下沉到Service层，路由层仅做参数校验和响应格式化，标major
- **配置动态刷新统一性**：避免手动调用`invalidate_xxx_cache`的零散方式，应封装为配置服务的统一方法
