## 核心审查原则

- **PR 描述与 diff 一致性强制校验**：核对 PR 描述、提交信息、文件清单和实际 diff；描述提到但 diff 未体现至少标 minor；安全/DB/依赖变更标 major；描述语义与实际架构影响量级差异时标 major。
- **PR 内提交主题一致性**：新增提交与 PR 描述/历史提交属不同子系统时，必须标注偏离。
- **审查决策与严重程度一致**：`request_changes` 必须对应明确可执行的 blocking/major。
- **历史问题状态需证据**：标记修复必须给出代码位置或扫描依据。
- **提示词/配置文本变更的下游对齐**：修改提示词格式约束时，必须追踪下游解析代码，验证是否存在与旧格式耦合的隐式假设，未验证至少标 minor。
- **小变更文件批量审查**：PR 中 ≥3 个变更量 ≤10 行的已有文件，必须逐文件说明意图和影响，删除行须追溯行为及调用方。

## 增量审查专项

- **完整性验证**：区分"当前增量通过"与"整个PR可合并"；历史阻断问题逐项列明。
- **决策完整性声明**：approve 时若存在历史 major 未覆盖，必须明确说明。
- **双重视角**：微观（增量质量）+宏观（增量在 PR 全局中的位置）。
- **PR 描述-增量差异说明**：摘要中必须声明本轮增量范围与 PR 描述的差异，消除完整性幻觉。
- **回顾性发现**：以新代码为线索重新审视旧代码的完整性。

## 重构类变更审查

- **全仓扫描验证**：模式化替换 PR 需提供全仓静态搜索证据，证明旧模式已清除。
- **数据源替换三层检查**：替换 X→Y 需验证：(1)数据结构兼容；(2)消费方适配（Grep 列出所有调用点）；(3)行为规则迁移——基于 X 的约束/假设对 Y 是否仍成立。第三层最易遗漏。
- **对等迁移双向行为验证**：禁止仅凭"架构风格一致"评价，必须逐项确认可观测行为特征。
- **语义迁移零遗漏**：A 统一迁移为 B，任何残留的 A = blocking。
- **行为契约变更声明**：以"统一行为"为目标的重构，须列出新旧行为差异。
- **辅助函数迁移完整性**：新增辅助函数统一处理逻辑时，列出所有应使用的调用点。

## 代码质量与安全

- **安全修复必须"向前一步"**：检查同类路径是否存在相同模式，建议全仓扫描。
- **固定字符串边界注入逃逸**：用固定字符串作 untrusted data 边界时，须验证 data 包含该字符串时的行为。
- **恒定回退值是阻断信号**：回退值恒为同一值时，必须追问调用方依赖，标 major。
- **字符串匹配关联删除是高危反模式**：应使用显式 ID 绑定。
- **解耦操作须验证下游适配**：移除隐式耦合时，列出所有消费方确认不出错。
- **明文敏感字段存储禁止**：api_key/secret/token 必须加密。
- **Markdown 嵌入注入检查**：外部内容嵌入 GitHub markdown 时须评估 ``` 干扰。
- **防御性取值掩盖字段缺失**：`.get()` 下不同返回路径字段集不一致至少标 minor。
- **静默失败路径升级**：核心链路上失败后无错误/无重试/无告警且数据静默丢失 = major。
- **宽泛异常兜底日志**：`except Exception` 降级日志须含异常对象或 `exc_info=True`。

## 测试与验证

- **"覆盖函数"≠"覆盖行为"**：先问参数/数据能触发哪条代码路径。
- **同源偏差**：同作者编写不能因覆盖全面放松独立验证；审查摘要须显式声明偏差风险。
- **镜像偏差**：测试数与描述修改点精确一致时应警惕。
- **Fake/mock 贴近生产语义**：须模拟过滤/排序/limit/异常/返回结构。
- **AI 输出容错负面验证**：增强容错性时须补充"错误输入不应被解析为有效"的负面测试。
- **大面积测试抽样审查**：单 PR 新增 >3 个测试文件，须至少抽查 1 个关键路径测试。
- **早返回路径字段集一致性**：多早返回路径返回同构字典时，应主动对比各路径字段集。

## 架构与模式

- **核心逻辑调用方扫描**：修改核心决策/公共数据结构时，列出并分析调用方适配。
- **事件驱动闭环**：webhook+worker+DB 重点查状态、重复/乱序、并发更新、唯一约束冲突。
- **状态机逃脱路径**：每个中间状态须提供超时或异常逃脱路径，无逃脱 = major。
- **队列服务审查范式**：必查入队去重/幂等（含 DB 唯一约束）、消费并发、消息确认/重试、死信处理、积压监控、有序性。
- **会话恢复配置刷新**：恢复历史会话须验证 system prompt/tool 定义/运行时参数被当前配置覆盖。
- **新增 DB 表索引审查**：对照同 PR 查询验证索引覆盖。
- **Diff 解析边界**：基于 diff 的功能须覆盖空 diff、二进制、重命名、大文件。
- **模型/成本切换论证**：切到高成本模型须要求成本影响估算。

## 经验教训

- **"正确语义"≠"安全变更"**：修正历史错误行为时，关注是否有代码依赖那个"错误行为"。
- **"纯文本变更"≠零风险**：提示词格式被下游隐式依赖时等同修改接口。
- **"惰性重建安全"不能跳过异常审查**：新调用点须重新评估上下文错误处理。
- **技术债"可接受"须有行动建议**：禁止以"可接受"为终结。
- **过滤操作日志**：除数量外须 debug 级别输出被过滤元素标识。
- **容错增强是双刃剑**：须同时验证"正确输入能被容忍"和"错误输入不会被误判为正确"。
- **跨模块直通数据流是脆弱点**：数据跳过中间层在下游消费时，中间层变更不触发下游适配检查。
- **审查精力按"变更行数×架构关键度"分配**：新文件和大改动文件分配更多精力。
- **高评分应意味着穷尽检查点，而非"没看到大问题"**。
