## 核心审查原则

- **"无评论"≠"无问题"**：空结果可能源于工具故障；每条"无问题"结论须附验证依据（全库搜索命令、CI run 链接）
- **高评分警惕确认偏误**：9-10 分须主动寻找边缘安全与全链路问题；全量重审即便无明显缺陷也应给出 minor 建议
- **结论逻辑自洽**：识别阻断项却批准会损害可信度；"阻断合并"语义必须对应 error/major 标签
- **安全改动强制风险分级**：ReDoS 防护、token 失效漂移、沙箱隔离等即使只有几行代码也须 major/error
- **最简单变更须最严格审查**：删除配置=移除护栏，须全库引用搜索防 KeyError
- **修复≠审查完成**：增量审查须追踪上轮问题，逐条标记 [已修复]/[未修复]/[已过时]
- **Fail-Closed**：宁可误报不可漏报；**文档不可作验证依据**，行为以代码实现为准

## 依赖与 CI

- **外部 CLI 版本声明**：最低版本须写入 PR/注释，CI 打印真实版本；Fake CLI 不能替代真实 runner 验证
- **升级对照 Breaking Changes**：警惕"宽松→严格"默认行为变化对 CI 的冲击；镜像标签与参数版本强绑定
- **workflow 最小权限**：显式声明 permissions；修改模板时同步更新 CI 文档
- **负向路径测试强制**：新增错误分支须断言 returncode!=0 且 stderr 有明确文案；错误码统一前缀便于监控
- **模板硬编码=版本耦合**：外部工具内部实现（如 digest 模板）应封装为统一脚本/常量
- **CI 红灯涉构建/导入失败直接阻断**；跨环境须提供实际 runner 成功运行链接

## 核心模块与并发

- **无界循环须物理硬约束**：LLM Agent 的 while True 必须保留 timeout/max_iterations
- **状态写入检查幂等与并发**：双写（Redis+内存）清理须原子化（Lua/pipeline）；补偿扫描入口须唯一约束/锁，分页+退避防限流，异常上报监控
- **迁移脚本幂等**（IF NOT EXISTS）+ 旧数据回退路径测试；nullable 字段回退分支须有测试
- **配置项须有真实消费点**；跨文件变更须检索所有读取路径；依赖图驱动审查注意增量缓存与 O(N²) 性能
- **变量命名嗅探**：生产代码出现 Fixture 风格命名警惕代码错位

## 安全与错误处理

- **异常脱敏分级**：USER_INPUT_ERROR 可透传，INTERNAL_ERROR 脱敏；禁止裸 except Exception
- **敏感凭证边界规范化**（strip/校验）；多渠道通知日志须确认脱敏实现
- **跨语言链路易遗漏**：UDS 文件权限、容器用户映射、镜像 digest 锁定、--cap-drop 统一声明

## Issue 分析

- **优先级纳入影响范围与恢复成本**：数据永久缺失（webhook 丢失无补偿）类应升 high
- **重复检测仅靠关键字会误/漏报**，建议语义相似度；低置信度标签二次审查
- **AI 审查改进**：高风险场景（部署链、双写、回退、并发、状态机）提示词结构化；adversarial pass 仅高风险文件触发以控成本；基于历史 PR 构建审查回归套件
