# 项目记忆

## 审查模式与教训
- **增量审查三大陷阱**：隧道视野、零评论高分、上下文浪费
- **增量审查边界**：能验证"改动是否正确"，无法评估"改动是否该发生"，膨胀模块需周期性全量审视
- **评分决策解耦**：增量质量高≠PR可合并，未闭环critical时decision必须降级
- **quick策略底线**：必须输出摘要+理由+问题追踪表；易"凑数"将优化拔高为major
- **微小diff欺骗性**：大PR后续小修复往往是补洞，代码干净≠PR可合并
- **创可贴式修复**：连续多轮处理边缘Bug而底层架构腐化未触碰，须识别并阻断
- **风险下移**：一个服务的腐化特征会迁移到关联服务
- **替换mock陷阱**：mock省略的安全验证、参数语义、元数据在替换时必须逐一重新审视，"mock省略了什么"是第一条检查线索
- **防御代码隐形流失**：用真实实现替换mock时，倾向丢弃if/try等防御结构，diff中删除防御结构必须确认等价保护
- **复审vs重复审查**：提交hash未变应直接拒绝，避免对同一代码重复输出完整意见
- **问题积累惩罚**：critical不响应就复审，评分应持续下降直至触发阻断

## 代码高危区与审查要点
- **路径安全**：必须用`pathlib.Path.resolve()`后验证前缀；`PurePosixPath`安全场景禁用
- **防御性编程表面化**：字符串匹配看似加固实则无效，须从OS底层理解攻击向量
- **类型契约**：跨模块混用dict/Object是系统性隐患，修复时必须横向排查
- **适配器接口契约**：实现替换外部依赖时，必须列出被适配对象所有公共方法/属性，逐一确认实现或抛`NotImplementedError`
- **参数静默忽略**：方法签名含参数但实现中完全丢弃，必须抛异常/记warning/文档标注，违反为major
- **双数据源**：主路径+回退须标注过渡期和收敛计划；返回类型必须共享基类或Protocol，否则major
- **上帝服务**：单文件超800行持续膨胀=架构腐化前兆
- **并发与原子性**：单例、跨文件写操作是高危区
- **asyncio.gather**：默认任一异常取消全部，串行改并行必须审查失败模式
- **魔法数字**：同语义数值≥2次必须提取常量
- **DB查询防御**：`if review_id`不够，ID类型/格式校验不能省略
- **入口静默失败**：扫描入口等关键路径的静默回退至少为minor

## 严重程度判定
- **三问法**：major前确认①实际bug？②运行时错误？③安全风险？全否则降级
- **三问法例外**：接口契约违反（调用方会因类型不匹配报错）保持major
- **优化建议≠major**：断言建议、延迟导入属suggestion/minor
- **延迟导入先问原因**：可能为避免循环导入或懒加载，未经确认不标记
- **安全类禁止降级**：路径遍历、写权限强制error，quick不免责
- **功能缺失判定**：先问是否有调用方实际依赖，fallback路径的功能缺失本质是suggestion
