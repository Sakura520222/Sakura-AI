# 项目记忆

## 核心审查教训与模式
- 双重处理陷阱：同一格式化函数在调用链重复执行，扫描数据全路径同名调用，标critical
- 服务层职责模糊：comment_service为评论渲染唯一入口，禁止上游预渲染；违反标critical
- 历史问题闭环验证：声称修复须列出所有调用位置、冲突消除证据，缺失触发missing-statement
- 增量审查陷阱：隧道视野致配置假开关、数据流断裂；必须扫描受改动字段影响的下游模块（即使不在diff范围）；发现新字段须追踪全生命周期，缺环节标major
- PR全局意图保护：AI审查prompt须传递PR meta信息（已有标签、标题、描述摘要），避免仅基于diff误判；标注enhancement/bug类Issue时应审查是否存在标签冲突导致下游自动化误触发
- 日志语义与行为一致性：行为变日志必同步，missing标minor+；AI/外部输入修正、降级操作必须warning级，info触发建议，安全防护场景提升至minor
- LLM输出解析：正则须容错空白、标点变体；清洗规则注释上游模式；脆弱累积可升级技术债
- 语义转换重构：去重→合并等，日志/变量名/注释同步高优先级
- 日志静默传染：发现一处错误吞没，扫描同文件同类场景
- 增量审查回归评估：须回答“是否新增未处理异常路径？”，未答评分≤8
- PR描述与diff一致性校验：类型不符标blocker；范围超出要求澄清
- 防御代码隐形流失；“部分修复”比“未修复”更危险；假兜底升级
- 配置假值陷阱：统一is not None；配置默认值变更强制评估攻击面/成本
- 异步取消与超时：run_in_executor无感知取消可能任务泄漏
- API URL拼接：禁止base_url含路径段；必须确认follow_redirects；缺失标suggestion/升级
- 容器/服务就绪轮询须含超时失败退出
- 安全扫描类强制security标签；默认secret/API token经query传输为高危
- 重复检测须输出Issue标题/相似度；已关闭Issue再现打regression
- 零评论高分是陷阱信号，approve也留简评
- 修复局限性归档为技术债Issue
- 版本升级须同步pyproject.toml与CHANGELOG
- 异步懒加载缓存并发安全：无锁保护提示asyncio.Lock
- 置信度/能力降级全链路追踪：修改置信度或强制置零必须追踪所有消费者（渲染器、API、存储）条件判断，确保0值不被过滤致隐形屏蔽；微小布尔标志沿所有使用点验证状态一致性
- 自动标签冲突检测：标签追加操作须检查已有标签上下文，避免覆盖或矛盾；相关Issue分析应审查同类问题

## 代码高危区
- 路径安全、SSRF、容器host网络、配置双源同步
- 双重格式化调用链：评论body预渲染后又被service格式化
- 解析器职责膨胀：result_parser集去重/合并/清洗易上帝类
- API客户端3xx非透明、缺失重定向
- 版本号多文件硬编码、身份推断下沉风险
- 置信度字段消费者：渲染/日志/存储对其0值处理
- 自动标签流程：无冲突检测即追加

## 严重程度判定
- 三问法强制绑定；安全类禁降级附security标签；幽灵变更标blocker
- 纯可读性封顶suggestion；假兜底无异常捕获标major
- 新功能闭环断链标major；LLM解析脆弱模式标suggestion
- 格式化重复调用标critical（非阻塞则major）
- 置信度零值下游未追踪可标major；标签冲突致误触发可升级
