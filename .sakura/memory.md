# 项目记忆

## 核心审查教训与模式

- **双重处理陷阱**：同一格式化函数在调用链重复执行，扫描数据全路径同名调用，标critical
- **服务层职责模糊**：comment_service为评论渲染唯一入口，禁止上游预渲染；违反标critical
- **历史问题闭环验证**：声称修复须列出所有调用位置、冲突消除证据，缺失触发missing-statement
- **增量审查陷阱**：隧道视野致配置假开关、数据流断裂；必须扫描受改动字段影响的下游模块；发现新字段须追踪全生命周期，缺环节标major；删除导入前全仓库引用搜索
- **降级标志全生命周期追踪**：引入布尔降级标志时，检查所有赋值点、重置点、使用点，确保无路径绕过；缺失标major
- **异常处理器顺序敏感性**：多个@app.exception_handler注册顺序决定优先级，标major
- **跨层导入强制注释**：API模块从WebUI层导入依赖时，必须注释理由，否则标minor
- **全局异常处理器禁止引用业务依赖**：不得解析token、查数据库、调用get_settings()，违反标major
- **重复代码提取权衡性能**：高频场景6次以上独立调用需批量聚合，标suggestion；同一工具函数出现≥2次须提取共享模块，标minor
- **常量字典重复≥2次**：language_names类重复定义必须集中到共享常量文件，标minor
- **静默异常禁止**：所有`except Exception`必须记录日志（顶级循环除外），违反标major
- **可变单例并发安全**：实例级可变状态用于请求级数据时必须使用上下文管理器或每次新建，否则标major
- **语义版本验证**：版本号升级时须检查变更幅度与PR描述是否对齐，缺失标suggestion
- **配置热更新验证**：新增动态配置字段必须说明是否支持运行时热更新，缺失标major
- **注释与UI分组一致性**：字段声明的注释分组必须与UI分组实际归属一致，标minor
- **注释引用符号存在性检查**：注释中的函数/方法名必须在当前代码库中存在且行为一致；引用私有方法须加稳定性风险注释
- **PR描述与变更内容一致性**：描述声称的功能必须能在变更文件列表中找到对应改动，缺失标critical
- **视觉特性真实性验证**：PR描述中的动画、飘落效果、UI组件必须验证DOM元素存在、CSS类已定义，缺失标critical
- **副本同步标记强制包含源位置行号**：复制代码时注释必须标注源文件路径+行号范围，否则标minor
- **document.write禁止用于动态内容注入**：改为x-text、innerText或textContent，违反标major
- **toast消息必须使用i18n函数**：所有toast_redirect调用处必须根据用户语言动态选择字符串，违反标major
- **异常消息透传审计**：直接向用户展示str(e)前必须评估是否包含技术细节或敏感信息，否则标major
- **翻译键语义完整性**：新增翻译键时其值必须与键名语义一致，否则标major
- **i18n函数调用点必须验证fallback**：当_('key')可能返回key本身时须有日志或默认值处理
- **动态配置读取失败的可观测性**：get_cached_config返回None时须记录警告日志，否则标minor
- **跨模块导入私有符号（_）必须通过公共访问函数**，否则视作架构违规标major
- **异常类必须提供user-facing message属性**：user_message必须调用i18n函数，禁止硬编码字符串，标major；内部信号异常可豁免但须注释上层转换点
- **模板翻译键外不得硬编码标点符号**：任何冒号、句号、空格若需本地化必须纳入翻译值，否则标major
- **toast_redirect调用必须显式传递lang参数**：若无法从请求上下文获取则使用fallback，否则标major
- **连续2轮未修复的问题自动生成issue并阻断下一个PR**；连续3轮未修复自动升级为critical，当前PR应阻断合并
- **增量审查必须输出“历史未解决问题清单”**并标注本次是否处理，对连续未修问题升级处理机制
- **同一模块不得同时提供类方法和模块级函数的相同功能**，否则标major
- **延迟导入必须注释循环引用原因**，否则视作可提升至模块级别
- **审查结果完整性验证**：审查输出中“主要评论”为空且变更文件数≥5时，自动拒绝并触发二次审查，标critical
- **首次全量审查必须输出至少5条具体评论**（major或critical），否则视为不通过
- **新增工具函数后原wrapper方法必须在同一PR中完全移除或标记@deprecated+预期移除版本**，否则标major
- **增量审查必须扫描变更文件内的所有.js、.html中的alert、confirm、x-text内字符串**，遗漏标major
- **启发式逻辑代码必须注释输入空间边界条件和失败时的fallback行为**，否则标minor
- **新增工具必须评估其返回数据是否可能触发二次超长**，缺失标major
- **异常类型判断禁止使用字符串比较，必须使用isinstance或显式导入**，违反标major
- **降级路径必须有单元测试验证**，缺失标minor；测试必须覆盖“files为空时的精简模式行为”和“多轮超长时finally清理路径”
- **新增共享函数必须验证是否能感知请求上下文**，否则标major
- **白名单降级分支必须记录警告日志**，否则标major
- **PR描述声称功能逐条验证**：每条声称功能必须在变更文件中可追溯，缺失时阻断合并
- **工具循环中的副作用必须注释**：公共方法若修改传入的列表/字典参数，必须在docstring中用“⚠️ 副作用”明确标注，标major
- **函数多出口路径必须显式检查返回值类型一致性**：所有分支必须返回相同类型，否则标major
- **修复被多处调用的函数时，必须验证所有调用点的兼容性**，缺失标major
- **常量归属检查**：新增常量时验证其归属模块是否与项目常量集中管理规范一致，标minor
- **注释语言一致性**：建议项目约定统一注释语言，审查时扫描新增注释，标minor；中英文混用可接受但需文档化
- **正则编译必须提升到模块级别**：re.compile不允许在方法体内每次调用重新编译，标minor
- **禁止直接访问私有属性（_xxx）**：必须提供公共getter/property，否则视为封装违规，标minor
- **通用异常（raise Exception）禁止使用**：必须使用自定义异常或已有异常体系，标major
- **生命周期管理注释强制**：存在set_xxx()方法的类必须注释实例是否会被复用及并发策略，标minor
- **幂等性强制注释**：公共方法若设计为可重复调用，必须在docstring中用“幂等: 是/否”标注，违反标major
- **静默返回默认值的上游影响审计**：若函数异常时返回默认值（0、None），调用方依赖该值做决策时必须记录警告日志或重试，违反标major
- **日志冗余合并检查**：同一逻辑分支内多条info日志表达同一决策结果时应合并或降级为debug，标suggestion
- **if/else对称日志输出**：if分支有info日志时，else分支应至少输出debug日志，标minor鼓励

## 代码高危区
- 降级标志相关代码路径（微小但影响全局）
- 批量冲突检测中的动态集合维护
- PyGithub的get_contents()多态返回处理
- 配置解析中的隐式split拆分
- 混合认证场景（API与WebUI共用依赖注入）
- Telegram Update对象的message/callback_query多态访问
- 全局异常处理器中的业务依赖调用
- 多语言版本号硬编码点（Python + SQL）
- 多源样式副本（base.html与独立主题CSS未提取为单一真实源）
- toast_redirect调用点（易遗漏i18n和lang参数）
- detect_language()依赖动态配置的fallback路径
- 异常消息透传的str(e)使用点
- 模板中的data-confirm属性（易遗漏i18n包装）
- 模板翻译键外的硬编码标点符号

- 实例级set_xxx()方法注入请求数据（易导致并发污染）
- 单例类存储请求级数据而未标注非线程安全
- GitHub API调用的分页、速率限制降级、网络失败恢复路径
- property替换私有属性时的falsy语义一致性验证点

## 近期审查模式总结
- **配置全链路追踪**：新增配置字段须验证定义→分组→标签→SQL初始化→所有消费点→热更新→测试覆盖
- **增量审查必须扫描PR描述中的所有提及文件**：即使提交列表不含某文件，若PR描述提到，必须确认是否已存在或被遗漏
- **重复逻辑阈值判断**：两处重复可容忍但须加注释标记未来重构点；出现第三处必须提取共享函数
- **开关可观测性强制**：新增降级/功能开关必须在关键路径记录info日志
- **死代码保留须注释**：保留未调用的条件分支时，须注释预期调用者或未来用途
- **SQL字段默认值安全**：新增布尔开关默认True保持旧行为；默认值变更需评估已有数据迁移
- **版本号单一真实源**：版本号升级PR必须验证`__version__`集中定义、其他位置动态读取
- **无障碍一致性传播**：若一个页面有`prefers-reduced-motion`，同类页面必须同步检查
- **动画性能评估**：新增大量绝对定位+无限循环动画时，评估低端设备GPU图层暴涨风险
- **深色模式对比度验证**：毛玻璃效果在深色模式下必须验证文字对比度≥4.5:1
- **脆弱选择器标注**：基于Tailwind工具类名的CSS选择器必须标注“脆弱，仅临时过渡”注释
- **连续未修问题升温**：历史已存在2轮的相同问题，下一轮即使有注释，也从suggestion升为major
- **PR评分趋势分析**：若连续多轮评分相同，审查应说明“为何未进步”或“债务被接受”
- **i18n PR覆盖度嗅探**：快速扫描所有.html、.js、.jsx、toast_、alert调用、API错误消息、data-confirm属性、x-text表达式，检查中文字符串是否遗漏
- **增量审查必须输出“历史未解决问题清单”**并标注本次是否处理，对连续未修问题升级处理机制
- **异常处理模式提取阈值**：同一异常处理模式出现≥3次，须提取为共享函数
- **Alpine.js + i18n检查**：验证x-text="_t('key')"是否有效
- **HTMX片段模板**：单独列出所有_fragment.html文件，极易遗漏i18n
- **PyYAML翻译文件双语对齐**：抽查新增键确认中英文值都不是占位符
- **降级链路端到端验证**：不仅要检查“是否触发了降级”，还要验证降级后是否真的能完成处理
- **异常类型映射的真实错误原因**：解析错误消息中的特征词（如“maximum context length”）后再决定降级策略
- **工具定义与业务模式解耦**：BASE_TOOLS不应包含条件性工具，建议引入CONDITIONAL_TOOLS按需动态添加
- **模式嗅探**：发现常量提取时，快速扫描其他.py文件是否存在同类硬编码；发现`if variable:`模式且变量名含filter/condition时，发出告警
- **实例属性并发写入评估**：审查时需追踪所有写入实例属性的地方，评估实例是否被复用

## 需特别关注的领域
- **跨语言版本同步**：Python + SQL + 迁移脚本必须构建时注入，防漂移
- **增量审查的风险升温检测**：历史问题在新功能上线后可能升级严重度
- **测试真实性验证**：mock必须匹配实际异常类型，断言异常路径被真正触发
- **并发竞态**：update_settings_field的setattr操作在异步环境需加锁评估
- **配置字段全生命周期清单**：定义→分组→标签→SQL初始化→所有消费点→热更新→单元测试
- **版本号升级检查清单**：强制验证单一真实源、CHANGELOG、Issue实现状态、fallback同步
- **动画性能与无障碍**：飘落/无限循环动画必须包含`prefers-reduced-motion`尊重、性能回退方案
- **i18n PR覆盖度嗅探**：快速扫描所有.html、.js、toast_、alert调用、data-confirm属性、x-text表达式
- **Alpine.js + i18n**：检查x-text="_t('key')"是否有效
- **HTMX片段模板**：单独列出所有_fragment.html文件
- **异常消息透传盲区**：str(e)直接展示给用户是常见i18n遗漏点
- **PyYAML翻译文件双语对齐**：抽查新增键确认中英文值都不是占位符
- **get_cached_config返回None的fallback处理**：所有调用点必须评估
- **模板翻译键外硬编码标点**：`{{ _('key') }}`前后的冒号、句号、空格若需本地化必须纳入翻译值
- **连续未修历史债务**：同一问题连续2轮标记后应自动生成issue；连续3轮阻断合并
- **审查结果空洞批准预防**：首次全量审查至少5条评论，增量至少1条
- **i18n双重接口风险**：模块级函数与类方法共存时，调用方可能混用
- **重构残留检测**：当看到“新增模块级函数”+“类方法改为委托”时，必须检查是否删除了原方法
- **标点符号的本地化陷阱**：中文句号与英文句号必须纳入翻译值
- **工具循环复用中的副作用注释**：提取公共方法时务必注释清楚“该方法会修改传入的messages列表”
- **实例生命周期注释**：存在set_xxx()方法的类必须注释实例是否会被复用及生命周期策略
- **工具调用的幂等性**：当前的_run_tool_loop不支持重试，建议未来引入“快照-重放”机制
- **中文环境token估算**：使用len(content)//4有偏差，建议引入tiktoken并缓存编码器
- **SQLAlchemy表达式truthy陷阱**：全项目扫描所有if条件中的SQLAlchemy核心表达式（or_/and_/not_），统一使用is not None判断
