# 项目记忆

## 审查模式与教训
- **增量审查三大陷阱**：隧道视野（只看diff忽略架构缺陷）、零评论高分（走过场）、上下文浪费（无视多轮历史问题）
- **评分决策解耦**：增量质量高≠PR可合并，存在未闭环critical时decision必须降级
- **quick策略底线**：不等于跳过思考，必须输出摘要+理由+问题追踪表；容易"找问题凑数"，将优化建议拔高为major
- **微小diff欺骗性**：大PR后续+几行的修复往往是补洞，代码干净≠PR可合并
- **净减代码蜜糖**：区分减业务逻辑（好）vs减防御代码（危险）

## 代码高危区与审查要点
- **路径安全**：必须用`pathlib.Path.resolve()`后验证前缀；`PurePosixPath`不访问文件系统无法解析符号链接，安全场景禁止使用，推荐时属于"错上加错"
- **类型契约**：跨模块混用dict/Object是系统性隐患，修复时必须横向排查
- **上帝服务**：单文件超800行持续膨胀=架构腐化前兆，需周期性全量审视而非仅看增量
- **并发与原子性**：单例、跨文件写操作是高危区，approve前必须确认状态
- **asyncio.gather**：默认任一异常取消全部，串行改并行必须审查失败模式是否退化
- **魔法数字**：同语义数值≥2次必须提取常量（如截断长度150 vs 200）
- **双数据源**：主路径+回退必须标注过渡期和收敛计划
- **DB查询防御**：新增查询时ID参数的类型/格式校验不能省略，`if review_id`不够

## 严重程度判定
- **三问法**：major前确认有实际bug？运行时错误？安全风险？全否则降级
- **优化建议≠major**：断言建议、延迟导入属suggestion/minor
- **延迟导入先问原因**：可能为避免循环导入或懒加载，未经确认不标记
- **安全类禁止降级**：路径遍历、写权限强制error，quick策略不免责
- **遗留问题禁止降级**：历史Critical/Error不能降为Suggestion放入[遗留]

## 规范演进
- **历史阻断机制**：未解决严重问题→approve权限锁定
- **高危词强制拦截**：PR描述出现"非原子性""线程安全""KeyError"时锁定approve
- **评论分区**：区分[新增问题]/[历史遗留阻断]/[确认修复]，禁止混入未修改文件问题
- **路径安全建议升级为AST拦截**：不依赖LLM记忆执行resolve()规范
