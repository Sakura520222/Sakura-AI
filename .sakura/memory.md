# 项目记忆

## 常见代码问题和审查要点

- **路径规范化禁止使用lstrip/rstrip移除前缀**：移除固定前缀必须使用`removeprefix`，禁止使用`lstrip`(字符集语义)，标major
- **公共工具函数必须处理None/空值边界**：即使注释声称“调用方不会传None”，也必须增加防御性检查，标major
- **新增公共函数必须包含docstring**：说明输入输出边界行为（如None→""），标minor
- **Mermaid标签必须完整转义**：生成图表标签时必须转义特殊字符或使用Base64编码，标major
- **清理函数入参None安全性**：公共清理函数接收可能为None的DB对象时，必须检查内部是否安全处理None，标major
- **返回值语义变更须同步调用方**：函数返回值语义变更时检查调用方变量名是否保持语义一致，跨文件超过3处升级为major
- **取消路径必须抽取公共清理函数**：凡有2个及以上取消/中断检查点，必须复用同一清理函数，标major
- **新增状态枚举的全链路审查**：新增枚举值必须检查DB ENUM/迁移、历史数据回填、API返回、WebUI模板/i18n/过滤器、SSE事件发送与前端接收，标major
- **延迟导入必须注释原因**：函数体内import若无注释说明循环引用原因，阻断合并，标major
- **session异常后状态污染**：捕获DB异常后session可能inactive，必须显式rollback()或close()，禁止仅注释声称“自动恢复”，标major
- **明文敏感字段存储必须加密**：新增DB列存储api_key/secret/token时必须使用加密，标阻断
- **API返回结构必须统一**：新增端点应返回{success,data,message}结构，标major
- **惰性重置遗漏读取路径**：所有读取用户配额/限流/统计类字段的路径必须调用重置/刷新函数，标major
- **批量UPDATE返回值语义必须明确**：若返回rowcount累加值，必须在函数名或docstring中明确说明语义，标major
- **列表页禁止逐个或批量嵌入写操作**：除非有明确性能评估，标major
- **只读接口中禁止嵌入写操作**：包括批量写，例外需注释用户量上限、操作开销评估，标major
- **限流配置必须从统一配置读取**：禁止硬编码如"10/minute"，应从settings读取，标major
- **配置降级必须记录日志**：使用默认值替代用户/环境配置时必须记录warning日志，标minor
- **热路径配置查询必须评估性能影响**：在循环或高频调用的位置查询用户配置时，必须评估DB查询频率，标major
- **权限重构必须全量覆盖**：修改权限检查逻辑时，必须扫描所有API+WebUI+CLI+后台任务中的相同/相似检查点，标major
- **策略函数必须检查输入有效性**：公共权限函数必须验证role是否在有效角色集中，无效输入返回False或抛异常，标major
- **行为变更必须标注在PR描述中**：任何权限收紧/放松、返回值语义变化必须在PR描述中明确说明，否则审查可阻断，标major
- **非关键路径异常必须评估可观测性的生效条件**：使用logger.debug记录异常时，应确认项目在调试环境中已启用debug级别，否则降级为info，标minor
- **返回None表示“跳过/无数据”时，调用方须检查是否导致重复的慢路径**，标major
- **禁止在路由层直接构造Redis key**：应封装到Service/Manager层，标major
- **except Exception:pass必须替换为显式忽略并记录debug日志**，标major
- **新增配置项若涉及行为变更，必须同步消费逻辑或注释为“预留”**：避免幽灵配置，标major
- **所有JSON API端点（除公开只读）必须显式使用CSRF依赖或头校验**：标major
- **新增DB模型的datetime字段必须使用datetime.now(timezone.utc)**：禁止utcnow，标major
- **限流/异常响应中禁止硬编码用户可见字符串**：必须使用翻译键或返回结构化键供前端本地化，标major
- **新增环境变量必须明确与现有flag的语义关系**：避免两个flag通过`or`逻辑重叠，应在文档或注释中说明是独立控制还是聚合控制，标major
- **跨平台路径处理函数必须包含单元测试**：包含相对/绝对路径、Windows/Linux路径分隔符、UNC路径边界，标major
- **开发脚本的默认配置路径必须显式加入.gitignore检查**：脚本启动时检测路径是否在仓库内，若在且未被ignore则打印警告，标major
- **Redis命令版本依赖必须检测或文档化**：新增Redis命令（如GETDEL）时，必须标注最低Redis版本，或启动时检测并降级时记录warning，标major
- **Pydantic schema中禁止dict[str, Any]（除非有充分理由）**：应使用dict[str, Union[基本类型]]或嵌套模型，标minor
- **新增原子命令必须验证异步客户端兼容性**：审查时需确认async版本的客户端支持该命令，标major
- **新增联合类型时必须扫描所有序列化/反序列化边界**：确认所有路径均接受该类型子集，标major
- **独立公共函数必须具有直接单元测试，不依赖间接覆盖**：标minor
- **“仅警告不阻断”的兼容性检测，必须在PR描述中列出受影响的下游调用及fallback状态**：标major

## 近期审查模式总结

- **连续未修问题升温**：同一问题连续2轮从suggestion升major，连续3轮阻断合并并自动生成issue
- **增量审查必须输出历史未解决问题清单并升温**：标注本次是否处理，未处理须说明理由
- **增量审查必须输出新增公共函数的调用方扫描结果**（即使仅在模块内部使用）
- **增量审查必须输出“未直接测试但依赖的调用链”**：例如检测函数未被调用处显式测试
- **审查前强制对照项目记忆前10条major规则**，逐条检查新代码是否违反
- **公共函数副作用须用⚠️标注**：修改传入列表或对象状态时必须在docstring中标注
- **返回值语义变更的强制扫描**：返回值类型/含义变化时，必须扫描所有调用方（含跨仓库）
- **调用方扫描强制执行**：修改变更文件时须扫描导入该模块的所有调用方，增量审查不得遗漏
- **异步方法必须同步提供异步测试用例**：当新增异步函数或装饰器时，必须提供异步测试，否则阻断合并
- **事务与外部写入顺序检查**：先提交DB再写外部文件是常见反模式，审查时优先检查顺序
- **全量审查价值**：对于涉及全局行为变更（配额、调度器、配置穿透）的PR，即使增量审查已完成，也建议合并前进行一次聚焦该特性的全量审查
- **PR描述必须明确列出受影响的API端点**，审查时逐一核对安全、限流、错误处理
- **增量审查必须标注“未验证但值得关注的潜在问题”**，以“⚠️观察点”形式列出，提示后续关注
- **“分阶段实现”PR必须列出未完成项并创建后续issue**：否则视为不完整
- **前端i18n映射函数必须支持动态翻译表**：禁止硬编码if链，使用对象映射或后端返回带前缀的key，标major
- **公共JS函数必须抽取到共享模板**：两个及以上模板出现完全相同定义必须抽取include片段，标major
- **版本检测+fallback+集成测试三件套**：对于原子操作类PR（如GETDEL），必须同时检查版本检测、运行时fallback路径、低版本环境集成测试
- **增量审查必须扫描跨模块契约变更的调用方**：联合类型、返回值语义变更时，强制输出调用方扫描清单

## 规范建议和经验教训

- **复合返回值的风险**：字符串拼接返回值不易扩展，优先使用结构化类型（NamedTuple/dataclass）
- **状态变更全链路清单标准化**：建议创建固定检查表（DB ENUM→模型枚举→API序列化→WebUI模板→i18n→SSE事件→状态转换矩阵）
- **SQLAlchemy异步session陷阱**：捕获异常后session进入inactive，优先使用async with session.begin()模式
- **配额类问题分析模板**：定位所有写入/消耗路径+所有读取路径（是否调用重置）
- **静态分析降级方案**：对正则提取import等方案必须明确失败降级策略
- **lstrip的双重面孔**：禁止用于前缀移除，但允许用于字符集语义，审查需区分场景
- **配置服务抽象**：建议引入ConfigService类统一封装配置降级逻辑，避免重复判断
- **XSS防护扩展**：除innerHTML外，还应检查insertAdjacentHTML、document.write、eval等危险API
- **注册表模式反模式**：当注册表数据需与UI、DB、配置文件三方同步时，改为单一真实源+缓存
- **委托模式审查清单**：行为等价性、调用链循环依赖、异常传播一致性、纯函数无副作用
- **列表收集+末尾输出的日志模式**：相比循环内多次logger.debug，这是更优的模式，可在规范中推荐
- **增量代码必须优于存量代码**：即使与旧风格一致，也必须要求遵守项目记忆规范，或创建后续issue清理
- **三态返回值的UI影响必须明确**：不能在只讨论后端缓存TTL，必须同步前端展示策略
- **内存fallback的可恢复性**：模块级dict作为Redis降级时，必须注释线程安全假设、重启丢失状态的影响，标minor
- **常量定义位置与语义保持一致**：模块级常量不得定义在函数内部（如lifespan），除非有明确生命周期绑定理由，标minor
- **新增异常处理器必须记录warn级别日志**：便于统计限流触发频率和定位问题，标minor
- **多flag组合逻辑审查**：存在两个及以上flag通过`or`/`and`控制同一行为时，审查语义重叠和用户预期清晰度
- **开发辅助脚本的安全性**：注意脚本生成的配置文件是否可能被意外提交（.gitignore + 启动时检测）
- **测试的对称性**：开发模式和生产模式必须形成“正向+反向”测试对

## 需要特别关注的领域

- **取消/中断检查点的一致性**：所有取消路径的资源清理必须统一，避免遗留状态
- **asyncio并发竞态**：webhook多次触发、配额重置并发幂等性、Event注册/注销配对
- **SQLAlchemy异步session事务边界**：取消路径中检查session有效性，异常后重建；禁止在非独占session的库函数中调用rollback()
- **返回值0的二义性**：函数返回0无法区分真无操作与调用失败，建议返回tuple或自定义结果对象
- **SSE事件发送与接收**：新增状态时必须检查所有发送SSE事件的点是否覆盖该状态
- **状态机完整性**：引入新状态时必须审查所有状态转换路径、回退是否允许
- **WebUI直接读库绕过业务逻辑**：审查所有展示配额/使用量的SQL/ORM查询，判断是否绕过了重置/刷新函数
- **路由层禁止直接操作数据库**：所有写操作必须下沉到Service层，标major
- **配置动态刷新统一性**：避免手动调用invalidate_xxx_cache的零散方式，应封装为配置服务的统一方法
- **限流+超时的成对检查**：每看到一个@limiter.limit，必须同时检查该接口内部所有外部IO是否设置了显式超时
- **测试命名与内容一致性**：测试名称必须与实际测试逻辑匹配，禁止名称漂移
- **异步测试强制要求**：新增异步函数必须提供异步测试用例
- **权限策略单一真实源**：禁止新写内联角色判断，所有if user.role比较都应改为调用策略函数
- **WebUI模板强制使用策略**：模板中也应通过上下文变量或过滤器调用策略，避免硬编码角色字符串比较
- **缓存TTL必须与下游恢复时间对齐**：如unknown状态TTL应不低于integration初始化重试间隔
- **个人用户检测的脆弱依赖**：依赖GitHub html_url字符串格式时，需增加变更检测和debug日志
- **CSRF + JSON API组合**：成为固定审查项，尤其WebUI路由下敏感操作
- **原子操作审查**：GET+DELETE、GET+SET等必须优先改成GETDEL、Lua或事务
- **WebAuthn challenge的原子消费**：必须严格一次性，防止重放
- **配置与消费的对称性审查**：每看到一个新增配置字段，强制扫描其唯一读取位置
- **Redis命令兼容性**：GETDEL等低版本不支持命令，要求版本检测+运行时fallback+集成测试三件套
- **增量审查中存量技术债升温机制**：连续多轮未处理的技术债应自动生成issue
