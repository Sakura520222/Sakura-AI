### Issue 分析质量提升
- **分类准确性**：`question` 类 Issue 需检查代码/文档是否已覆盖，避免过度标记为缺陷
- **标签置信度评估**：基于问题明确性评估置信度，避免主观低估（如 `question` 标签置信度应接近 1.0）
- **重复检测上下文验证**：结合项目记忆进行重复检测时，需验证上下文一致性，避免误报

### 支付系统集成经验
- **支付类 Issue 安全重点**：需重点关注安全配置（密钥加密）、回调幂等性、退款流程
- **高优先级功能评估**：明确依赖基础架构，避免低估集成复杂度
- **PR 拆分策略**：支付功能涉及多模块时，拆分为多个 PR 降低审查风险

### 诊断日志重要性
- **静默返回点风险**：功能未触发类 Issue 优先检查静默返回点、配置加载和异常处理
- **启动自检机制**：动态配置和 DB 状态字段需在启动时自检，防止长期静默失效
- **日志输出强制检查**：未来 Issue 分析中应强制检查日志输出，避免诊断困难

### 审查流程优化
- **PR 描述验证**：强制要求 PR 描述与实际变更文件列表一致，避免审查资源浪费
- **WebUI 模板动态变量验证**：模板中动态变量必须在所有路由路径中验证传递一致性，避免 `None` 值导致渲染异常
