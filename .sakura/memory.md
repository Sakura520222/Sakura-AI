## 核心审查原则

- **"无评论"≠"无问题"**：空结果可能源于工具故障；"无问题"结论须附验证依据（搜索命令、CI 链接）
- **高分警惕确认偏误**：高分仍须做负向用例验证；"阻断合并"必须对应 error/major 标签
- **审查策略动态升级**：最简变更也宜 full/medium；批量升级多库或 PR 提交数激增（如 ≥30 commits / >500 行）时 quick 必漏检，须切 full
- **Fail-Closed**：宁可误报不可漏报；文档不可作验证依据
- **报告结构化**：摘要→关键风险→修复建议；阻断项须在摘要阶段可见，勿埋在后续评论（锁文件问题最后一轮才冒出=滞后）

## 依赖与锁文件（高频主题）

- **锁文件同步=阻断项**：改 pyproject/requirements 必须同 PR 更新 uv.lock；漂移须标 error 而非 suggestion/minor——锁文件随发布包分发，低估定级=放行发布缺陷
- **CI 与发布链路一致**：pip install -r vs uv.lock 会"CI 过、发布挂"；统一 uv sync --locked
- **双清单镜像自动校验**：已有自动化测试逐行比对；手动维护成本高，可单一来源+CI 自动导出
- **死依赖检测**：全库零调用≠可删（CI/Dockerfile/迁移脚本间接消费）；手写实现（正则 slug 替代 slugify）致库冗余时可移除
- **升级必附 Release Notes**：核对 Breaking Changes；查库的 Supported Python Versions（如 watchfiles 1.2.0 删 3.9），CI 加版本矩阵
- **默认行为回归**：升级后加 snapshot test 对比关键输入输出；热重载等平台相关行为多 OS 验证
- **工具限制**：大文件（uv.lock）超搜索上限时改分块读取，勿跳过验证

## 核心模块与并发

- **无界循环须物理硬约束**；状态写入幂等+并发防护；迁移脚本幂等+回退路径测试
- **服务脚本幂等**：install/uninstall 在已存在/不存在时返回一致退出码、无重复副作用
- **配置项须有真实消费点**；环境变量（如 UPDATER_STARTUP_TIMEOUT）须在容器镜像/部署模板声明

## 安全与守护进程

- **异常脱敏分级**：USER_INPUT_ERROR 可透传，INTERNAL_ERROR 脱敏；禁止裸 except
- **系统级资源防御式校验**：路径/权限/所有者检查集中到统一抽象（如 safe_path），便于审查定位
- **非 systemd 环境回退**：容器/裸机下须明确报错或 fallback，勿 assert 或留僵尸进程；PIDFile 残留清理须有测试

## 流程与协作

- **增量审查须复查前轮未决项**：前轮阻断问题（如 uv.lock 未同步）每轮重新验证；增量开始前先跑全库依赖一致性检查
- **增量结束后全局回归**：跑全库静态分析，防旧文件回归漏检
- **merge commit 噪声**：增量审查过滤合并提交；引导 rebase/squash 保持线性历史

## Issue 分析

- **优先级纳入影响范围与恢复成本**：数据永久缺失类升 high
- **重复检测仅靠关键字会误/漏报**；低置信度标签二次审查
- **AI 审查改进**：高风险提示词结构化；adversarial pass 仅高风险文件触发；历史 PR 构建回归套件
