# 项目记忆

## 审查模式与教训
- **增量审查三大陷阱**：隧道视野、零评论高分、上下文浪费
- **增量审查边界**：能验证"改动是否正确"，无法评估"改动是否该发生"，膨胀模块需周期性全量审视
- **评分决策解耦**：增量质量高≠PR可合并，未闭环critical时decision必须降级
- **quick策略底线**：必须输出摘要+理由+问题追踪表；易"凑数"将优化拔高为major
- **微小diff欺骗性**：大PR后续小修复往往是补洞，代码干净≠PR可合并
- **创可贴式修复**：连续多轮处理边缘Bug而底层架构腐化（并发、原子性、上帝服务）未触碰，须识别并阻断
- **风险下移**：一个服务的腐化特征会迁移到关联服务，警惕初始化/并发边界共振

## 代码高危区与审查要点
- **路径安全**：必须用`pathlib.Path.resolve()`后验证前缀；`PurePosixPath`不访问文件系统，安全场景禁用
- **防御性编程表面化**：字符串匹配（如`".." in parts`）看似加固实则无效，须从OS底层理解攻击向量
- **类型契约**：跨模块混用dict/Object是系统性隐患，修复时必须横向排查
- **上帝服务**：单文件超800行持续膨胀=架构腐化前兆
- **并发与原子性**：单例、跨文件写操作是高危区，approve前必须确认状态
- **asyncio.gather**：默认任一异常取消全部，串行改并行必须审查失败模式
- **魔法数字**：同语义数值≥2次必须提取常量，截断长度跨场景须一致或说明差异
- **双数据源**：主路径+回退必须标注过渡期和收敛计划
- **DB查询防御**：`if review_id`不够，ID参数类型/格式校验不能省略

## 严重程度判定
- **三问法**：major前确认①实际bug？②运行时错误？③安全风险？全否则降级
- **优化建议≠major**：断言建议、延迟导入属suggestion/minor
- **延迟导入先问原因**：可能为避免循环导入或懒加载，未经确认不标记
- **安全类禁止降级**：路径遍历、写权限强制error，quick不免责
- **遗留问题禁止降级**：历史Critical/Error不能降为Suggestion放入[遗留]

## 规范演进
- **历史阻断机制**：未解决严重问题→approve权限锁定
- **高危词强制拦截**：PR描述出现"非原子性""线程安全""KeyError"时锁定approve
- **评论分区**：区分[新增问题]/[历史遗留阻断]/[确认修复]，禁止混入未修改文件
- **路径安全AST拦截**：不依赖LLM记忆，前置检查未出现.resolve()直接拦截
