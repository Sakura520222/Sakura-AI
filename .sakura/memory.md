# 项目记忆

## 审查模式与教训
- **规则替替判断**：规则与实际分析冲突时须回溯规则适用性
- **分析否定则降级**：分析得出"本身安全""实际不会"时必须降级或移除
- **路径安全证明责任**：须构造具体攻击路径，禁止假设链标记major
- **resolve+前缀检查**已构成symlink完整防御，无需逐分支显式is_symlink()
- **resolve()位置决定安全语义**：前检查拦截所有symlink，后检查只拦截指向仓库外；"先resolve再检查"是坏习惯
- **"部分修复"比"未修复"更危险**：无效修复让开发者误判为已解决
- **修复有效性须推演执行流**：不能"见码即认"，死代码是典型假修复
- **except ImportError是降级信号**：回退链中抛非降级异常几乎都是bug
- **增量审查陷阱**：隧道视野、零评论高分、上下文浪费；正确结果可掩盖错误过程
- **评分决策解耦**：增量质量高≠可合并，未闭环critical时decision必须降级
- **防御代码隐形流失**：diff删除防御结构须确认等价保护
- **好的分析不表达=没分析**

## 代码高危区与审查要点
- **路径安全**：resolve()跟随symlink；三层防护范式（单文件→目录遍历→walk followlinks=False）
- **适配器接口契约**：列出所有公共方法/属性逐一确认；连续补边缘而契约未补齐是创可贴式修复
- **回退链异常语义**：禁止NotImplementedError表示"不支持"
- **死代码意图回溯**：安防意图变死代码时须追溯是否被等价满足
- **参数静默忽略**：违反为major

## 严重程度判定
- **三问法**：major前确认①实际bug？②运行时错误？③安全风险？
- **自检消除矛盾**：扩展至问题状态表与具体评论一致性
- **安全类禁止降级**：例外——分析已证明被防护时允许降级
- **评论格式硬校验**：[major]/[critical]须含文件:行号+问题描述+影响判定
- **分区标签解耦**："建议（可选）"禁止major/critical，安全遗留项禁止降入
