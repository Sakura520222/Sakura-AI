## 1. 审查质量评估

### 覆盖度
- **优点**：覆盖了核心逻辑缺陷（`lstrip` 语义错误、Mermaid 转义不全）、分层架构问题（路由层直接操作 DB）、性能问题（嵌套循环）、测试缺失。

  - **未检查静态模式下的错误处理**：正则提取 import 失败时是否静默跳过？是否记录日志？建议至少 warn 级别日志。
  - **未检查 `max_nodes` 裁剪后的图是否仍保持连通性**：简单取前 N 个节点可能产生孤立子图，用户体验差。应优先保留入度/出度高的节点。
  - **未检查跨操作系统路径分隔符**：`_normalize_path` 中 `path.replace("\\", "/")` 仅处理 Windows 反斜杠，但 Posix 路径不包含 `\`，可接受。但测试未覆盖 Windows 环境。

### 准确度
- **严重度合理**：`lstrip` 问题标记 🟡 正确，因为实际文件路径很少以 `.` 开头且文件名含多个 `.` 时确实会误删（如 `"./config.test.json"` → `"config.test.json"` 正确，但 `"./test."` → `"test"` 错删尾部点）。概率低但语义错误，值得修复。
- **Mermaid 转义不全**：`<`、`>`、`{`、`}` 在文件路径中罕见，但若用户创建如 `src/<template>.ts` 会破坏图。建议升为 🟡 保持现状即可。
- **路由层 DB 操作**：审查者犹豫“如果其他地方也是这样则无需修改”——这是危险信号。应明确：即使已有坏模式，也不应延续。建议要求抽取为服务层方法。

### 完整性
- **理解了变更意图**：静态分析模式作为 AI 的轻量替代，降低 token 消耗。
- **缺少对“静态模式与 AI 模式共存时缓存策略”的审视**：切换模式时，旧图缓存是否失效？`invalidate_dynamic_config_cache` 是否清除了依赖图缓存？未提及。

## 2. 发现的模式

### 代码模式
- **路径规范化重复计算**：`_build_file_aliases` 已计算 `path_aliases`，后续 `_generate_static_mermaid` 又对同一组文件重新 `_normalize_path`。表明函数边界划分过细，缺少中间结果复用。
- **正则提取 import 的脆弱性**：静态分析依赖正则匹配 `from ... import` 和 `import ...`，无法处理多行、括号、注释内的 import。审查未提出这点（可能接受作为设计取舍）。

### 架构观察
- **分层混乱持续**：项目记忆中提到“服务层薄化演进”，但本次 PR 在路由层直接写 `AppConfig`。说明架构约束未在代码审查中强制执行，审查者倾向“保持一致”而非“纠正”。
- **配置缓存失效机制不统一**：`save_strategies_section` 手动调用 `invalidate_dynamic_config_cache`，但其他配置保存点可能遗漏。应封装为配置服务的统一方法。

## 4. 经验教训

### 未来审查关注要点
1. **字符串处理函数语义**：`lstrip`/`rstrip`/`strip` 经常被误用为“去除前缀/后缀”，每次出现都应质疑。
2. **新增“轻量模式”时，必须对比全量模式的行为差异**：静态模式无法处理动态导入、条件导入、`__import__`，是否在文档中说明限制？
3. **分层违规的“一致性陷阱”**：审查者容易接受“与现有代码一致”作为理由，但应坚持“新代码应比旧代码更好”，可单独提 issue 重构旧代码。
4. **测试覆盖率的质量**：本次测试行覆盖率高但场景覆盖不全（缺少 `../` 相对路径、`@/` 别名、转义测试）。建议要求 PR 提供 mutation testing 或至少负面测试用例。

### 技术/模式经验
- **静态分析的正则方案**：对于 import 提取，正确率约 80-90%，适合内部工具但必须明确失败降级策略（如回退到 AI 模式或显示错误提示）。
- **Mermaid 生成的安全性**：任何用户输入（文件名、import 路径）放入图标签前必须转义。建议使用 `json.dumps` 保证字符串安全，而非手工转义表。
- **配置动态刷新**：`invalidate_dynamic_config_cache` 是刀耕火种的方式，易遗漏。应改为配置服务启动时加载、运行时通过信号刷新，或使用 `asyncpg` 的 `NOTIFY`。

## 总结

本次审查质量**中等偏上**，发现了函数语义错误、转义不全、分层违规等实际问题，但遗漏了静态分析模式的失败处理、裁剪算法连通性、前端联动验证。审查者在面对既有坏模式时犹豫，反映出项目缺乏强制的架构质量门禁。
