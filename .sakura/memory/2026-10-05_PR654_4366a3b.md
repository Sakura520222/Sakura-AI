### 2. 发现的模式
* **依赖更新自动化模式**：Dependabot 默认原生仅支持更新 `pyproject.toml` / `requirements.txt`，在以 `uv` 为核心包管理器的项目中，Dependabot 提交的机器人 PR 极易出现 `uv.lock` 失步现象。
* **锁文件约束契约**：`uv sync --locked` 对 `[package.metadata] requires-dist` 的校验是严格的精确匹配（Strict Exact Match），即使实际 locked version 已满足新 range，specifier 不一致仍会被视作 Out-of-sync。

### 3. 规范完善建议

针对当前项目记忆，建议在 **“依赖与锁文件”** 章节补充以下规则：

* **新增“Dependabot PR 特殊处理规则”**：
  * Dependabot 自动生成的依赖提升 PR 默认不包含 `uv.lock` 的更新。审查 Dependabot 提交时，优先检查 `uv.lock` 是否遗漏；
  * 如果仅缺少 `uv.lock` 且 locked version 满足新约束，可指导作者/维护者在本地运行 `uv lock` 或通过自动化 GH Action 触发补全提交，无需全盘否定 PR 的合理性。
* **新增“锁文件校验自动化建议”**：
  * 建议在 CI 前置步骤或 Pre-commit 钩子中引入 `uv lock --check` 校验，在阻断 merge 前提下，输出更友好易读的修复提示信息。

### 4. 经验教训
* **关注依赖管理工具的深度特性**：对于现代化包管理器（如 `uv`、`pdm`、`poetry`），不仅要看版本号锁死（`version = "x.y.z"`），还要关注元数据校验（`requires-dist specifier`）。
* **自动化 Bot PR 审查定性**：对于机器生成的 Dependabot PR，阻断结论要分清是“方向有误/有 Breaking Changes”还是“配套工具链未跟进”。本 PR 属于后者，在报告中给出确切的指令（运行 `uv lock` 并提交）能够极大提升 PR 的闭环效率。
