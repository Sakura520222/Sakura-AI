## 4. 经验教训

### 值得未来关注的要点
1. **新旧系统并存的审查成本很高**：每次增量审查都需要同时理解两条路径的行为差异。
2. **“修复历史问题”的 PR 容易引入新问题**：例如 `asyncio.to_thread` 未处理取消，`__getstate__` 破坏 dataclass 语义。
3. **测试用例与常量不同步**：是典型的跨模块重构引起的“漂移”，需要通过静态分析或常量导入强制约束。
4. **安全校验往往只在“新路径”加强**：旧路径遗留下来成为技术债，需要定期全量扫描。

### 对特定技术/模式的审查经验
- **`asyncio.to_thread`**：不是万能的取消安全解决方案，需配合 `asyncio.wait_for` + 显式清理。
- **dataclass + pickle**：`__getstate__` 会覆盖默认行为，必须成对实现。
- **配置 fallback 链**：多种配置源时，必须输出明确的“优先级文档”，否则审查无法判断是否正确。
