### 3. 规范完善建议

基于本次审查和现有项目记忆，建议新增/强化以下规则：

1. **重定向透明性检查**  
   - 凡涉及 HTTP 客户端 URL 拼接修复，必须确认 `follow_redirects` 设置，并评估是否全局启用。若修复前出现 3xx 异常，审查必须显式判断当前重定向行为是否为预期，不得默认为“已解决”。

2. **PR 引用 Issue 的强制声明**  
   - 当 PR 描述出现 `Fixes #xxx` 时，审查摘要必须包含：“可见范围内该修改是否完全解决所引 Issue 尚存不确定性”或“已验证完全解决”。缺少此声明，评分不得高于 8/10，且需添加 comment 标记 missing-statement。

3. **URL 拼接同类扫描强化**

4. **config 浮点尾部清理的抽象**  
   - 建议项目在配置加载层统一对 URL 做规范化处理（去尾斜杠、确保 scheme），降低各模块自行处理的风险。本次虽修复一点，但应创建低优先级建议，推动基建改进。
