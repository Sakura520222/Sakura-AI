### 6. 经验教训与仓库特定模式

1. **Host 侧运维脚本的安全性与幂等性（结合项目记忆）**：
   - **原子替换**：全局 launcher 安装与更新必须遵循 `os.replace` 或 `mktemp -> mv` 规范，防止写入中断导致 CLI 损坏。
   - **权限与环境兜底**：脚本改动必须支持非 systemd 环境（如纯 Docker 容器内环境）的显式优雅回退，并最小化 root 权限提升范围。
2. **测试驱动的 CLI 变更**：
   - Shell 启动脚本改动极易产生隐蔽回归（如路径切换、环境变量丢失）。此 Issue 在实施前必须先在 `tests/test_start_sh_*.py` 中补充在非 `/opt/sakura-ai` 路径直接执行 `sakura-ai` 的测试用例。
