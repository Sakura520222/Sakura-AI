### 2. 发现的模式
- **代码模式**：开发者倾向于复用现有模式（如 `datetime.utcnow`），但忽略 Python 版本弃用警告；错误处理依赖字符串匹配，显示异常设计不足；延迟导入常用于解决循环依赖，但注释不规范。
- **架构观察**：项目采用分层架构（模型-服务-路由-UI），支付模块高度模块化，但依赖关系复杂（如 `refund_notification_service` 与 Telegram 模块循环依赖）。异步路由中同步 I/O 风险已通过 `asyncio.to_thread` 包装解决，显示架构逐步成熟。

### 3. 规范完善建议
- **新增规则**：针对支付网关，强制验证 `ensure_ascii` 规则适用性（即使 Alipay 场景特殊，也需文档化例外）；针对异常处理，新增规则要求为 `PaymentError` 添加 `error_code` 属性，避免字符串匹配。
- **修改规则**：强化延迟导入注释规范，要求必须说明具体循环依赖路径（如模块 A → 模块 B → 模块 C）；在增量审查中，强制全文件扫描支付网关的 `ensure_ascii` 使用。
