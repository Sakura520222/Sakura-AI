## 2. 发现的模式  

### 代码模式  

| 模式 | 体现 | 潜在风险 |
|------|------|----------|
| **异常捕获使用逗号式** | 多个模块仍保留 Python 2 语法 `except A, B:` | 在 Python 3 环境直接抛 `SyntaxError`，导致包不可导入，属于“致命阻断”。 |
| **异常捕获未统一** | 部分地方已改为 `except (A, B) as e:`，而其他仍旧逗号式 | 代码风格不一致，易导致遗漏。 |
| **平台特定 API 直接调用** | `os.O_DIRECTORY` 在 Windows 上不存在，测试未加 `skipif` | CI 在多平台（Linux + Windows）时会出现不必要的失败。 |
| **硬编码常量** | `TIMEOUT_START_SEC = 120` 与 `ceil(N)+30` 的组合硬编码在单元测试中验证 | 虽然已写测试，但若业务需要调低默认值，需要手动同步多处常量。 |
| **全局导入导致加载链路破坏** | `systemd.py` 在模块级直接 `from backends.daemon import …`，一旦 `daemon.py` 语法错误，所有 systemd 相关代码无法加载 | 形成 **单点故障**，建议延迟导入或在 `try/except` 包装。 |

### 架构观察  

* **单一来源契约**：`backend_cli_flags` → `systemd.render_unit` → `systemd.install_service` 的数据流保持一致，体现了良好的职责分离。  
* **依赖图呈星形**：`systemd.py` 与 `daemon.py`、`__main__`、`test_systemd_*` 多点相连，任何一处错误会波及大量入口。  
* **测试覆盖层次**：单元测试对 **渲染逻辑**、**异常路径**、**幂等性** 均有覆盖，但 **跨平台兼容性** 只在少数文件中体现，易被遗漏。

## 3. 规范完善建议  

### 审查规则层面  

1. **全库语法检查规则**  
   - 必须在 CI 中强制执行 `python -m compileall -q .` 或 `ruff`/`flake8` 的 “syntax‑only” 检查，任何 `SyntaxError` 均视为 **阻断**（fail‑closed）。  
   - 将 “逗号式 except” 列入 **禁止模式**，在 lint 配置中加入正则匹配 `except\s+\w+,\s+\w+:` 并报错。  

2. **平台兼容性检测**  
   - 对所有使用 `os`、`fcntl`、`select` 等平台特定常量的代码，要求 **显式 `skipif`** 或 **运行时特性检测**（`hasattr(os, "O_DIRECTORY")`）。  
   - 在测试文件中加入自动化检查：`pytest --maxfail=1 -m "not windows"` 之外，还要检测文件是否遗漏 `skipif`。  

3. **导入安全规则**  
   - 对 **跨模块导入**（尤其是 `systemd.py` → `daemon.py`）添加 **“延迟导入”** 检查：若导入的模块在同一 PR 中出现语法错误，必须在导入处捕获并给出友好错误提示。  

4. **文档审查**  
   - 新增 **文档变更审查** checklist：检查是否出现 **误导性说明、遗漏安全前置条件**（如 “host systemd 必须是 PID 1”），并要求对应代码实现已有验证。  

### 项目特有规范要点  

| 规范 | 目的 | 实施方式 |
|------|------|----------|
| **异常统一写法** | 防止因语法差异导致导入失败 | 所有 `except` 必须使用圆括号 `except (A, B) as e:`，并在 `pre‑commit` 中加入 `ruff` rule `E722`。 |
| **跨平台测试标签** | 保持 Windows 与 Linux CI 绿灯 | 为每个涉及系统调用的测试添加 `@pytest.mark.skipif(not hasattr(os, "O_DIRECTORY"))`，并在 CI 中运行两套矩阵。 |
| **导入容错** | 防止单点故障扩散 | 在 `systemd.py` 顶部使用 `try: from .backends.daemon import … except Exception: raise ServiceError("Daemon module broken")`。 |
| **常量集中管理** | 避免硬编码散落 | 将 `DEFAULT_STARTUP_TIMEOUT`、`TIMEOUT_START_SEC_FLOOR`、`TIMEOUT_START_SEC_PADDING` 等统一放入 `constants.py`，并在代码和文档中引用。 |

## 4. 经验教训  

1. **阻断缺陷必须先于功能审查**  
   - 任何导致 **包无法导入** 的语法错误应在 **增量审查** 前被捕获并要求 **立即修复**，否则后续功能评审失去意义。  

2. **增量审查不等于全局审查**  
   - 本次审查仅针对新增的 55 行 `systemd.py` 与 5 行 `daemon.py`，但仍需 **全库语法/导入检查** 作为必备步骤。  

3. **跨平台兼容性是测试的硬性需求**  
   - 项目明确声明 “Windows 可运行”，因此任何 POSIX‑only 调用必须有 **skipif** 或 **兼容实现**。忽视这一点会导致 CI 在 Windows runner 上直接报错。  

4. **文档与实现同步检查**  
   - PR 中大量文档更新（README、DEPLOYMENT）未被审查，导致潜在的 **误导**（如未说明系统必须是 PID 1）。文档审查应列入必检项。  

5. **异常路径的验证要完整**  
   - `fsync` 失败、`systemctl` 调用被阻断等负向路径已通过测试覆盖，说明 **负向测试的重要性**。以后在加入新异常分支时，务必同步补充对应测试。
