### 3. 规范完善建议

基于本次审查，建议在项目记忆与审查规则中补强以下标准：

1. **测试辅助代码的正则规范**：
   *   所有用于解析 HTML/XML 结构（如提取 `<script>`、`<style>` 等标签）的正则匹配，必须显式附加 `re.IGNORECASE`（或 `re.I`）标志，防止大小写不匹配与 CodeQL `Bad HTML filtering regexp` 阻断。
2. **提交前预检机制（Pre-commit Guard）**：
   *   强制要求在本地 CI 管道最前置环节运行 `python -m compileall backend updater tests`。对于 Python 语法错误（如 `SyntaxError`），无需进入复杂的 Pytest 阶段即可在 3 秒内 Fail-Fast。

### 4. 经验教训

*   **对开发者“部分修复”保持极高警惕**：当看到开发者对包含历史遗留 Bug 的文件提交了新的 Commit 时，**绝对不能假设历史 Bug 已顺带修复**。必须以文件绝对行号或 AST 分析为准进行 HEAD 直接校验。
*   **CodeQL / 静态扫描告警不区分“生产”与“测试”**：即便缺陷发生在 `tests/` 目录下的辅助脚本中，SAST 工具（CodeQL）也会计算在 PR 总 Check status 中。审查时必须提示开发者“即使测试用例跑通，SAST CI 不绿也无法合并”。
