## 4. 经验教训

### 值得未来关注的要点
- **i18n 热更新完整性**：任何新增语言类配置，必须追踪到 `t()` 函数调用链，确认每次渲染都重新获取当前语言，而非启动时快照。
- **配置分组视觉一致性**：UI 侧若依赖 icon 区分分组，审查时应强制检查 icon 唯一性。
- **PR 描述与 diff 的覆盖嗅探**：若 PR 声称“更新模板以支持中英文”，但 diff 中无任何 `.html/.js` 改动，应立即标记 major。

### 对特定技术的审查经验
- **Alpine.js + i18n**：检查 `x-text="_t('key')"` 是否全局可用；若依赖 `document.write` 则标 major。
- **动态配置 + 缓存层**：任何 `@lru_cache` 装饰器下的函数若返回可变配置对象，必须审查是否绕过热更新。
