## 3. 规范完善建议

基于本次审查，可新增或强化以下规则：

### 新增规则（建议加入项目记忆）

1. **路由前缀必须使用 `url_for` 或全局常量**  
   - **内容**：新增 WebUI 路由时，模板和重定向中禁止硬编码路径字符串，必须使用 `url_for('system_config.index')` 或定义 `WEBUI_PREFIX = "/webui"` 常量并复用。  
   - **标级**：major

2. **新增 WebUI 模块必须包含冒烟测试**  
   - **内容**：任何新增的 WebUI 页面（含前后端）必须在 PR 中附带一个简单的请求测试（如 `client.get("/webui/system-config/")` 应返回 200，且超级管理员可访问）。  
   - **标级**：major

3. **配置保存端点必须原子化**  
   - **内容**：批量保存配置时，如果任一配置校验失败，必须整体回滚，禁止部分写入。  
   - **标级**：major

4. **敏感字段脱敏必须覆盖多行文本**  
   - **内容**：`mask_sensitive_value` 应支持多行字符串（如私钥、证书），正则需含 `re.DOTALL`。  
   - **标级**：minor

### 现有规则强化提示
- **CSRF 检查**：审查中发现 JSON API 端点仍被遗漏，建议在 CI 中增加静态扫描：所有 `@router.post` 且路由不在 CSRF 豁免列表中的，必须检查参数是否包含 `Depends(require_csrf_header)`。
- **延迟导入注释**：本次仍有未注释的延迟导入，应持续强调。

## 4. 经验教训

### 值得在未来审查中关注的要点
- **新增 WebUI 模块的第一件事**：检查侧边栏链接 + 表单 action + JS fetch + 重定向 URL 四者的路径是否**与注册路由的实际前缀一致**，这四个点经常不同步。
- **配置类 PR 的“四对称性”**：范围定义（config.py）、路由校验（system_config.py 中的 if）、测试断言、写入路径，本次已做，但可更明确输出对比表。
- **Toast 重定向 + i18n 键的联动**：新增 `toast_redirect` 调用时，必须确认第一个参数（URL）和第二个参数（i18n 键前缀）是否都与实际路由和翻译文件匹配。

### 针对特定技术/模式的审查经验
- **FastAPI 路由嵌套前缀**：`app.include_router(webui_router, prefix="/webui")` + `webui_router.include_router(system_config_router, prefix="/system-config")` → 最终路径为 `/webui/system-config/`。审查时应**反向推导实际 URL**，并与模板中的硬编码对比。
- **Alpine.js 动态 Tab 初始化**：硬编码 `activeTab: 'database'` 会导致分组 ID 变化时 UI 错位，应改为从模板动态注入第一个分组 ID。
- **SVG 装饰图标可访问性**：已成为 UI 审查固定项，但本次仍遗漏了其他内联 SVG（如侧边栏的其他图标），建议在模板中全局扫描 `svg` 标签并检查 `aria-hidden`。
