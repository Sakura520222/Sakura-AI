## 深度反思

### 1. 审查质量评估

**覆盖度：存在一处关键遗漏**

审查正确识别了日志可观测性不足的问题，但对**行为变更的下游影响**缺乏验证。旧逻辑在过滤行内评论时会同步从 `issues` 字典移除对应 finding，新逻辑保留这些 finding。这是一个**面向消费者的契约变更**——所有读取 `issues` 的下游代码（摘要生成、严重程度统计、前端展示）现在会看到更多的 findings。审查断言"valid finding 不应因 inline comment 无法提交而消失"在语义上合理，但未列出 `issues` 的消费方并确认它们能正确处理"有 finding 但无对应行内评论"的状态。这属于项目记忆中"核心逻辑变更的调用方扫描强化"原则的适用场景，本轮未执行。

**准确度：合理**

`suggestion` 级别准确，评分 9/10 对一个净减 41 行且修正语义错误的干净重构而言合理。

**完整性：PR 上下文一致性未校验**

PR 描述完全关于 `PRDependencyGraphService`（删除文件过滤、文件计数回退），但本轮提交是 `ReviewWorker` 的评论同步逻辑重构。两者属于不同子系统。审查未对这种**PR 内提交主题偏离**提出疑问，违反了"PR 描述与 diff 一致性强制校验"原则。

### 2. 发现的模式

**代码模式：基于字符串匹配的关联删除是高危反模式**

旧代码用 `Counter` 对 issue 标题做匹配来同步删除，这是典型的"用弱关联替代强关联"——没有 ID 或引用将 inline comment 与 finding 显式绑定，而是依赖标题字符串相等性。这种模式在标题微小变化（如 LLM 输出随机性）时会静默失效。本次重构正确地切断了这种脆弱关联，但根本问题（inline comment 与 finding 之间缺乏显式 ID 绑定）仍作为技术债存在。

**架构观察：`issues` 字典承载了多重语义**

`issues` 同时服务于"审查摘要展示"和"行内评论关联"两个目的，旧代码将这两个语义耦合在同一个数据结构的删除操作上。本次变更实际上是对 `issues` 语义的单一化——它现在只代表"发现的 issues"，不再承担"哪些 issues 有行内评论"的职责。

### 3. 规范完善建议

**建议新增规则：解耦操作必须验证下游消费方适配**

> 当移除两个数据结构/操作之间的隐式耦合时（如过滤 A 不再同步删除 B），必须列出 B 的所有消费方，确认它们不会因 B 中出现"无对应 A 的元素"而产生错误行为（如空指针、计数不一致、展示异常）。

**建议强化规则：PR 内提交主题一致性检查**

> 当增量审查发现新增提交的主题与 PR 描述、历史提交属于不同子系统或不同问题域时，必须在审查中显式标注"提交主题偏离"，并建议作者考虑拆分 PR 或补充 PR 描述。

**建议细化规则：过滤/丢弃操作的日志规范**

> 任何过滤操作，除记录过滤数量外，必须在 debug 级别输出被过滤元素的标识信息（文件路径、行号、ID 等），不得仅记录统计数字。

### 4. 经验教训

**"正确的语义"不等于"安全的变更"**

本次重构的语义修正无可争议——finding 不应因评论过滤而消失。但正确性的提升可能暴露下游代码对旧行为的隐式依赖。未来审查中，对于"修正历史错误行为"的变更，要特别关注是否有代码依赖了那个"错误行为"。

**净减代码量的重构容易获得高分，但要警惕"删除的是逻辑还是债务"**

本次删除的 41 行中，`_inline_comment_issue_title` 方法和 `Counter` 匹配逻辑是明确的债务清除，但`SEVERITY_TO_ISSUE_KEY` 的删除需确认该映射在其他位置是否仍被需要。审查未验证这个导入是否真的在全仓无其他引用。

### 5. 增量审查反思

**新增提交与历史问题的关系**

本轮提交 `f288d56` 与历史审查提出的所有问题（依赖图裁剪测试覆盖盲区）无关，是一个独立的重构。审查正确地声明了历史问题"不在本轮变更范围内，未重新验证"，符合增量审查规范。

**增量引入的新风险**

核心风险点：`issues` 字典行为变更的下游影响未验证。这是一个**低概率但高影响**的风险——如果某个下游模块假设 `issues` 中的每个 finding 都有对应的行内评论，可能会在遍历时产生 KeyError 或展示异常。

**覆盖度下降评估**

由于只看增量 diff，审查对 `issues` 消费方的全仓扫描自然缺失。这在增量审查中是可接受的，但应在审查报告中明确声明"未验证 `issues` 字典的下游消费方是否适配新行为"作为已知盲区，而非完全忽略。
