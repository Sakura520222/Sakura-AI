|--------|------|------|
| **冲突预检** | 在自动同步 workflow 中加入 `git merge --no-commit --no-ff` 预检，若出现冲突生成临时分支并打开 Draft PR，而非直接创建 Issue。 | 能把冲突信息直接呈现在 PR 中，便于审查与复现。 |

| **合并后验证** | 合并完成后统一执行 **依赖锁校验**（`uv lock --check`）和 **完整测试套件**（`pytest -q`），并在 CI 中加入 **`git status` 检查是否有未提交的生成文件**。 | 防止因冲突手动编辑导致的依赖漂移或生成文件不一致。 |
| **文档留痕** | 在 `CONTRIBUTING.md` 中记录 **“Gitflow 同步冲突处理流程”**，并在 Issue 关闭时添加 **“解决提交 SHA: …”** 注释。 | 为新贡献者提供明确指引，形成闭环。 |
