## 4. 经验教训

### 值得未来关注的要点
- **异步 / 同步边界检查**：每次出现 `def`（同步）被 `await` 或放入 async 函数调用时，必须确认是否阻塞事件循环。
- **“分支绕过主流程”嗅探**：当主流程有 A → B → C，而某个特殊分支直接返回 C 但跳过 B，必须标记为高风险。
- **`limit` 参数传播**：检查 `limit` 是否被正确传递到所有子方法，以及是否用作数据库查询的 `LIMIT`、API 调用的分页限制。
- **monkeypatch 与延迟导入**：在测试中 patch 延迟导入的类时，建议额外注释是否需要提前触发模块加载。

### 对特定技术/模式的审查经验
- **SQLAlchemy `EXISTS` 子查询复用**：应抽取为 `def _build_existing_task_subquery()`，返回 `Exists` 对象，避免重复。
- **“fail-open”策略** （如 GitHub API 失败时返回原候选）是好的降级，但必须配套 **debug 日志**和可选的 **metrics 计数器**，否则成为静默失败。
- **去重逻辑**：保留最高分是对业务正确的，但应明确相同分数时的稳定性策略（例如保留最早或最晚）。
