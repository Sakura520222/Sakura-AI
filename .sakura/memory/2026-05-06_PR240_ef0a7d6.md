## 4. 经验教训

### 未来审查关注点
- **版本号变更时**：  
  - 验证 `__version__` 是否被所有其他文件动态引用  
  - 检查 SQL 初始化脚本 + 迁移脚本 + 默认配置是否一致  
  - 若变更影响已有数据库，必须提供 `UPDATE` 语句或回退方案  
- **服务层移除逻辑时**：  
  - 确认调用链中不存在绕过 worker 直接调用 service 的路径  
  - 验证降级标志的全生命周期（设置、重置、读取）未被破坏  
- **PR 描述与代码差异较大时**：  
  - 要求 PR 作者解释差异原因，并增量审查未列出的文件  

### 特定技术/模式审查经验
- **INSERT IGNORE + 主键冲突场景**：默认值变更不会应用到已有记录，若该值用于逻辑判断则会导致行为漂移。  
- **私有方法引用注释**：即使仅为注释，也会在代码重构（重命名方法）时产生误导，建议强制使用功能描述。  
- **版本号硬编码的频次**：该项目已出现 7 处硬编码，说明缺乏构建时变量注入机制，应建议引入 `version.py` 或环境变量注入。
