## 4. 经验教训

### 值得关注的要点
- **异步任务的可见性**：`create_task` 创建的任务若未保存到变量，在 traceback 或日志中难以关联。可考虑统一封装 `safe_create_task` 并记录任务 ID。
- **fallback 路径的测试盲区**：同步 fallback 中的异步分支很难被单元测试覆盖，应增加集成测试或强制要求 fallback 路径具有同步版本的通知方式（如直接打印日志 + metrics）。
- **内存降级结构的超限问题**：连续3轮未修，说明该问题优先级被低估。建议设置内存 fallback 上限后，超过阈值时强制转为日志告警或降级到计数丢弃，而非先插入后清理。

### 对特定技术的审查经验
- **asyncio + 同步 fallback 混合**：审查时应重点检查：
  - 是否在非 async 上下文中误用 `await`
  - 是否使用了已弃用的 `get_event_loop()`
  - 无法获取 loop 时的降级行为是否可观测（日志 / metrics）
- **fire-and-forget 模式**：必须确认调用方不依赖任务结果，且任务内部异常被完全捕获。
