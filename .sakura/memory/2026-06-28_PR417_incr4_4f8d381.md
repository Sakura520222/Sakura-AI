# 深度反思：PR #417 增量审查 (4f8d381)

## 1. 审查质量评估

**覆盖度：存在结构性盲区**

等价性分析和边界场景验证做得到位（标签内含`-->`、前导空白等），但遗漏了两个应检维度：

- **新增方法测试覆盖**：`_parse_node_line` 和 `_parse_edge_line` 是全新静态方法，项目记忆明确要求"新增未测试方法/路径评分硬上限 ≤8"。审查未讨论这两个方法是否有对应测试用例。评分恰好卡在8分，即使没有测试也未违规，但**不讨论本身是覆盖缺陷**——读者无法判断这是"检查过确认有测试"还是"忘了查"。
- **等价性的反面验证不足**：验证了"正则能匹配的输入新代码也能处理"，但未讨论"正则会拒绝的输入新代码是否也拒绝"。例如 `N1["]` 这种畸形输入，正则不匹配，新代码 `line.find('"]', start+2)` 会返回-1，`end <= 0` 为True返回None——碰巧等价，但属于未显式验证的巧合。

**准确度：无误判**

ReDoS 标记为"已彻底修复"准确，正则完全移除，不存在残留风险。

**完整性：意图理解充分，决策声明不完整**

对"用字符串查找替代正则"的意图理解到位，两遍扫描逻辑保持不变的判断正确。但存在决策流程缺陷（见第5节）。

## 2. 发现的模式

- **字符白名单校验模式**：`any(c.isspace() or c in '[]"' for c in node_id)` 用否定形式做输入净化，与原正则字符类 `[^\[\]\s"]+` 语义对齐。这是安全敏感解析的合理手法。
- **手工定界替代正则的模式**：`find(定界符) + 切片 + strip` 的三步法，在已知格式简单（无嵌套、无转义）的场景下是正则的安全替代方案。
- **两遍扫描依赖**：先全量收集节点再解析边，说明边解析依赖完整的 `node_id_to_path` 映射——这个架构约束在新旧实现间保持一致，审查正确捕捉到了。

## 3. 规范完善建议

**新增规则：正则→手工解析替换检查清单**

当用字符串操作替代正则时，须显式验证以下四项并记录：
1. 正常输入等价性（原匹配的，新也匹配）
2. 拒绝输入等价性（原不匹配的，新也不匹配）
3. 嵌套/转义场景声明（格式是否允许嵌套定界符，若不允许则注明"格式约束保证无嵌套"）
4. 性能退化边界（`str.find` 在超长行上是 O(n) 但无回溯，对比原正则的最坏情况复杂度）

**强化规则：新增方法测试覆盖必须显式声明**

将"新增未测试方法评分≤8"改为"新增方法须显式声明测试覆盖状态（有/无/待补充），无测试时须在评论中标注"。

## 4. 经验教训

- **"彻底移除"不等于"无需验证等价性"**：正则移除消除了 ReDoS，但手工解析引入了新的边界行为（`find` 返回 -1 的处理链）。审查重心应从"风险是否消除"转向"行为是否等价"。
- **安全修复的负面测试不可省**：ReDoS 修复应该有对应的恶意输入测试（如超长重复字符串 `A["AAAA...AAA"]`），验证不仅"不崩溃"还要"正确拒绝"。审查未追问这一点。
- **等价性验证的结构化**：本次审查的等价性分析是散文式的，未来应采用表格形式——左列"输入模式"，中列"原正则行为"，右列"新代码行为"，一目了然。

## 5. 增量审查反思

**前序问题解决**：ReDoS 修复闭环完整，从"正则优化"到"彻底移除正则"的演进路径清晰。

**新风险**：无显著新风险引入。手工解析在 Mermaid 图的已知格式约束下是安全的。

**覆盖度下降——三个规范违反**：

| 违反项 | 规则要求 | 实际表现 |
|--------|----------|----------|
| 决策完整性声明 | approve 时存在未解决 ≥minor 问题须**逐项声明** | 范围声明中提到两个未触及的 suggestion，但决策部分未说"尽管存在 X、Y 未解决，仍 approve 因为..." |
| quick 策略评分上限声明 | 须显式说明因 quick 策略评分受限 | 未声明，读者无法区分 8 分是"quick 天花板"还是"质量就是 8" |
| 隧道视野防范 | 正面评价越多越先做负面检查 | 四个 ✅ 正面结论，无记录负面检查过程 |

**根因推断**：本次 diff 质量确实高（纯重构、逻辑清晰、边界处理到位），导致审查者进入"确认偏误"模式——看到代码质量好就加速通过，跳过了流程性检查项。这正是"隧道视野防范"规则存在的意义：**代码越好，越要警惕流程漏检**。

**改进建议**：quick 策略增量审查应有一个**强制清单尾件**，在输出审查结果前逐项打勾：`[ ] 决策完整性声明` `[ ] quick上限声明` `[ ] 负面检查记录`，未全勾不允许输出。
