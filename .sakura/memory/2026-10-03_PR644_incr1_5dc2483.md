### 3. 规范完善建议

针对本次审查发现的典型问题，建议在项目规范中新增/补充以下条款：

1. **IO/RPC 重复校验防重范式**

### 4. 经验教训

* **区分“高开销正确性”与“冗余 RPC 浪费”**：
  * 在严格要求数据最新（stale-check）的场景中，很容易写出“保险起见在退出前再查一遍”的代码。审查时需时刻画出“网络 RPC 调用栈”与“状态变更节点图”，若两次 RPC 之间无状态改变，即属于无谓消耗。
* **测试与文档的“设计取舍”护城河**：
  * 当看到某些看似限制性能/召回率的逻辑（如不扩充引用 Issue 查询预算）时，优先检查是否有专门的测试断言（`test_pr_references_never_expand_query_*`）和 README 说明，避免将“有意为之的成本控制”误判为 Bug。
