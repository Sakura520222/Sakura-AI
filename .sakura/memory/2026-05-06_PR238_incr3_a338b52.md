## 4. 经验教训

- **增量审查的风险升温**：历史问题（注释引用私有方法）多次标记未修复，应升级为 **major** 而非归档，因为积累的文档债务会在多人协作中放大。
- **PR 描述与代码变更的对齐性**：审查必须交叉比对 PR 描述中所有声称的改动（特别是“reorganize configuration structure”），若缺失则要求更新 PR 描述或补交代码。
- **语义化版本并非强制规则**：若项目内部不严格遵循，可降级为 suggestion，但必须记录决策理由至项目记忆。
- **fallback 值的隐藏陷阱**：新旧版本混合可能导致数据库初始化时的隐式版本降级，建议升级时所有 fallback 值同步更新，否则标记 major。
