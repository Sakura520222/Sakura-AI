- **降级标志分散检查**：同一开关在不同服务中独立检查，缺乏统一的 `should_submit_inline_comments()` 门面函数。

## 4. 经验教训

**值得未来关注的要点**：
- **配置开关与既有数据库的兼容性**：新增字段后，旧记录的默认行为是否与预期一致（`NULL` vs `'true'` 处理）。
- **双重检查路径的隐式风险**：若未来某重构让 `update_review()` 重新进入调用链，则开关会生效两次（虽无副作用，但逻辑重复可能导致维护不一致）。
- **历史记忆中的“降级标志全生命周期追踪”**：本次审查已应用该规则，但遗漏了 UI 和迁移脚本环节，说明规则需更明确地列出必须检查的 7 个消费点（包括 UI、API、worker、migration、SQL、settings、log）。

- 对于 **SQL + Python 双写配置**，必须全局搜索 `enable_inline` 关键词，覆盖 `.py`、`.sql`、`.vue`/`.html`、`.js`，防止前端遗漏。
