### 新增规则

**规则：结构化数据解析防御层级**
> 处理外部 JSON 时，每个字段的类型假设都须有显式校验或独立 try/except 隔离。禁止依赖"上游 schema 已约束"跳过防御，除非有运行时强制校验机制保障。

**规则：降级链异常隔离粒度**
> 降级链中每个独立的解析阶段应有独立的异常边界。任一阶段失败不得影响下一阶段的入口状态（如中间变量污染）。

## 4. 经验教训

### 核心教训

**try/except 边界审计要点**
审查解析类代码时，须绘制异常传播路径：
1. 标记所有可能抛异常的表达式（`.get()` 对非 dict、`int()` 对非数字、`for` 对非 iterable）
2. 确认每个异常点是否在预期 try/except 范围内
3. 确认 except 捕获类型是否匹配实际可能的异常

**测试覆盖审查不可跳过**
即使是 quick 策略，新增测试文件应至少扫描：
- 是否有对应已标记问题的负面用例
- 是否有边界值用例（空列表、空字符串、类型错误）
- 用例命名是否体现场景而非实现细节

**类型假设的显式化原则**
```python
# 危险：隐式假设 issues 是列表
for issue in data["issues"]:
    issue.get("severity")

# 正确：显式校验
if not isinstance(data.get("issues"), list):
    return None
for issue in data["issues"]:
    ...
```
