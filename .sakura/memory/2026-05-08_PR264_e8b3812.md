## 2. 发现的模式

### 代码模式
- **重复的“惰性重置”调用**：在多个读取路径（`get_user`, `list_users`, `myquota`）中嵌入写操作，易导致意外性能开销和状态变更。项目知识已标记为“列表页禁止逐个调用写操作”，但未禁止“列表页调用批量写操作”——边界需明确。
- **枚举式字段映射表**：`PR_QUOTA_FIELDS` / `ISSUE_QUOTA_FIELDS` 设计良好，便于扩展，但未配套字段类型校验。
- **`setattr` 直接修改 ORM 对象**：`reset_user_quotas_if_expired` 中使用 `setattr(target, field, 0)` 绕过类型检查，若字段名拼写错误会静默失败，建议使用 `setattr` 前校验或改用 Pydantic 模型。

### 架构观察
- **Service 层职责混合**：`QuotaService` 既包含原子重置逻辑，又包含 `reset_all_expired_quotas_atomic`（批量），但后者内部不检查 session 是否属于同一事务，可能在嵌套调用中导致部分提交。
- **配置源不统一**：`pr_dependency_graph_mode` 同时存于 YAML 和 DB，但运行时优先读 DB，YAML 成为遗留冗余。建议确立“DB 为主，YAML 为初始化种子”的明确策略。
- **定时任务与 API 双重触发**：配额重置既由 scheduler 每小时执行，又在每个用户读取时触发，缺少协调机制（如分布式锁或时间窗口去重）。

## 3. 规范完善建议

### 新增审查规则

| 规则 | 严重度 | 说明 |
|------|--------|------|
| **批量 UPDATE 必须在一个事务中原子执行** | major | 若循环执行多条 UPDATE，必须使用 `begin_nested()` 或单条 CASE WHEN 语句，避免部分成功。 |
| **只读接口中禁止嵌入写操作（除非有显著性能注释）** | major | 包括批量写。例外需注释用户量上限、操作开销评估。 |
| **使用 `setattr` 修改 ORM 字段前必须校验字段存在性** | minor | 建议使用 `if hasattr(obj, field)` 或改用字典更新。 |
| **动态配置的持久化必须唯一真实源** | major | 禁止同时写入 YAML 和 DB 作为平等源，应明确主从关系。 |
| **惰性重置函数必须幂等** | major | 通过 `last_reset_at` 或条件 `WHERE quota > 0` 避免重复置零。 |

### 项目特有规范要点强化
- **延迟导入注释**：要求必须写出具体循环路径（如 `quota_scheduler → main（启动时导入）→ database → quota_service`），而非仅“避免循环依赖”。
- **返回值语义**：返回整数时必须明确“是行数”、“是用户数”还是“字段更新次数”，推荐返回 `NamedTuple` 或 dataclass。
- **静态分析降级**：必须使用 `warning` 或 `error` 级别，且降级后应更新响应头 `X-Dependency-Graph: fallback`。

## 4. 经验教训

### 值得在未来审查中关注的要点
- **事务 + 外部 IO 顺序**：始终优先提交 DB，再写外部文件，或者两者在同一异常处理中回滚。
- **批量操作的原子性与错误处理**：循环执行 SQL 时必须考虑事务边界，避免部分提交。
- **只读接口的副作用审查**：所有 GET 类接口、列表查询、状态查看，都要检查是否意外调用了 `UPDATE/INSERT/DELETE`。
- **Python 时区处理的演进**：`datetime.utcnow()` 已废弃，使用 `datetime.now(UTC).replace(tzinfo=None)` 是正确过渡，但应标注 TODO 迁移到 aware datetime。

### 对特定技术/模式的审查经验
- **SQLAlchemy 异步 session**：批量 UPDATE 后必须 `expire_all()` 或 `refresh()`，否则已加载的 ORM 对象仍是旧值。审查时需检查 `await session.execute()` 后是否有 `expire` 调用。
- **APScheduler 在 FastAPI 中的生命周期**：确保 `lifespan` 中正确启动/关闭，且使用 `AsyncIOScheduler` 与 asyncio 兼容。本次已检查 ✅。
- **静态分析 import 提取**：正则正确率有限，必须设计明确的降级路径（回退到 AI 模式或报错显示），并记录 `warning`。
