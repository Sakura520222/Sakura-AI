## 4. 经验教训

### 值得关注的要点
- **i18n 前端映射的扩展性陷阱**：当只有 1 个 key 时容易写成 `if`，但当第 2 个 key 出现时就会重复。应一开始就使用对象映射或映射函数。
- **全局异常处理器中的前端逻辑**：限流返回 `HX-Redirect` + toast message 是合理的，但需要前后端约定好 message 的语义（是 i18n key 还是原始文本）。
- **增量审查容易忽略“非本次变更但受影响”的代码**：例如本次虽然只改了 passkey 的两个模板，但未来若有第三个 passkey 页面，会重复相同函数。审查时应标注“提醒未来同步”。

### 对特定技术的审查经验
- **Jinja2 模板中的 JS 片段**：审查时应主动检查是否存在跨模板重复逻辑，尤其是事件绑定、i18n 映射、表单验证等。
- **frozenset 用于热路径判断**：性能好且不可变，但必须确认生成时机（启动时一次性）。本项目中在 `lifespan` 内生成稍有语义问题，但不影响安全性。
