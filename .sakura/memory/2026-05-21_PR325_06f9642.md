## 发现的模式

**代码模式**：
- 项目广泛使用延迟导入解决循环依赖，但注释规范执行不严。
- 路径/URL 处理中存在重复的清理逻辑，缺乏统一工具函数。
- 配置清洗采用“入口+读取时”双层防御，但未抽象为公共模式。

**架构观察**：
- 模块间依赖较紧密（如 `telegram` 依赖 `webui`），易产生循环引用。
- 配置管理分散在多个服务中，清洗逻辑不统一，增加维护成本。
- URL 生成逻辑多处重复，但缺少统一的 URL 构建器。

## 规范完善建议

1. **新增规则**：对于 `app_domain` 这类多用途配置项，应明确其语义（是否包含协议、端口等），并在不同使用场景中强制校验或转换。
2. **修改规则**：路径规范化规则应细化为“禁止使用 `lstrip/rstrip` 移除前缀/后缀，必须使用 `removeprefix/removesuffix`”，并增加对切片操作（如 `domain[len(prefix):]`）的审查，避免类似误判。
3. **新增规则**：跨文件重复逻辑（>10 行）必须抽取公共函数，并在审查中强制检查所有调用点。
4. **新增规则**：配置清洗逻辑应统一为工具函数，并在保存和读取时强制调用，避免分散实现。

## 经验教训

1. **延迟导入注释**：必须严格执行注释规范，避免因注释缺失导致循环依赖问题被忽略。
2. **URL 构造风险**：`app_domain` 在不同场景下的语义可能不同（如 `webauthn_service.py` 需要完整 URL），审查时需结合上下文分析，避免统一迁移导致逻辑错误。
3. **重复逻辑检测**：增量审查中应强制扫描关联文件，识别重复逻辑并抽取公共函数，提升代码一致性。
4. **配置清洗抽象**：配置清洗逻辑应尽早抽象为公共工具，避免多处重复实现，降低维护成本。
