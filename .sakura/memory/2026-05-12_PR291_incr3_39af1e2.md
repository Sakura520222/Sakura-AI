## 4. 经验教训

### 值得关注的要点
- **`or` 与 `get(key, default)` 不是等价的**：前者会将 falsy 值（`""`, `0`, `False`, `[]`, `None`）统一回退，后者只在 key 缺失时回退。重构时必须确认业务场景是否允许 falsy 值被覆盖。
- **配置系统的回归风险**：修改配置读取逻辑后，应至少回归测试一个“用户显式设置为空”的场景。

### 对特定技术的审查经验
- **审计日志脱敏**：多次脱敏是常见错误，最佳实践是只在“数据进入审计构造前”脱敏一次，之后只透传。
- **动态配置的 fallback 链**：DB → Settings → 硬编码默认值，必须清晰记录每一层的触发条件。
