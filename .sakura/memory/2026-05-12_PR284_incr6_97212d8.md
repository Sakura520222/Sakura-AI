## 4. 经验教训

### 值得未来关注的要点
- **`utc_now` 作为 SQLAlchemy default 的函数签名变更**：即使返回值类型不变，如果函数从本地变为跨模块，可能需要检查 `pickle` 或 `__module__` 影响（虽然这里无关）。
- **grep_tool description 的语义漂移风险**：工具 description 是 LLM 调用时的关键依据，必须与实现严格一致。本次虽为 minor，但实际可能导致模型错误假设工具能力。
- **工具循环中的命令白名单**：`shell_tool` 的 `_SHELL_SUBST_PATTERNS` 未来如果增加新模式，必须同步更新白名单判断逻辑，这是个脆弱点。

### 对特定技术的审查经验
- **SQLAlchemy + async + default 函数**：审查时建议确认 default 函数是否同步（`utc_now` 是同步的，安全）。
- **Python `re.escape` 用于 grep 模拟**：注意 `re.escape` 会转义所有正则元字符，但不会转义 shell 元字符（如 `$`），对于固定字符串匹配足够安全。
