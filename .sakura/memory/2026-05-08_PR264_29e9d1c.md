## 3. 规范完善建议

### 新增/修改规则
- **新增**：**批量重置函数必须返回明确语义的对象**（如 `ResetResult(affected_users=10, affected_fields=25)`），而非 `rowcount` 累加。标 major。
- **新增**：**定时任务注册必须验证启动钩子**：审查新增 `scheduler.add_job` 时，必须确认在 `startup_event` 或 `lifespan` 中调用。标 major。
- **加强**：**正则编译提升到模块级别**：除现有要求外，建议在 `ruff`/`flake8` 中增加自定义检查（或使用 `re.compile` 检测插件）。
- **细化**：**列表页 N+1 量化阈值**：若用户量 < 500 且操作轻量（如单字段 UPDATE），可允许，但注释中必须写明性能假设和预估用户数。标 minor。

### 项目特有规范
- **Mermaid 转义黑名单**：建议维护一个标准转义函数库 `escape_mermaid(text)`，统一处理 `&<>{}[]()#%|`，避免多处实现。
- **配额相关读路径检查清单**：已在记忆中有“惰性重置遗漏读取路径”，但可增加自动化脚本扫描所有 `SELECT ... quota` 的 SQL/ORM，提示是否调用了 `reset_if_expired`。

## 4. 经验教训

### 未来审查关注点
- **降级路径的一致性**：静态分析失败时应明确记录并对外暴露降级状态（如响应头 `X-Analysis-Fallback: true`）。
- **事务与外部写入的顺序**：`config.py` 中先提交数据库再写 YAML 的风险应作为常见反模式，审查时优先检查。
- **返回值语义的调用方扫描**：修改 `reset_all_expired_quotas_atomic` 返回值时，必须扫描所有调用方（目前仅 `quota_scheduler.py`），确保变量名与语义匹配（如 `updated = ...` vs `affected_fields = ...`）。

### 特定技术经验
- **Python 相对导入规范化**：`_normalize_import` 处理 `.utils` 和 `./utils` 的差异容易出错，建议拆分为 `normalize_python_import` 和 `normalize_js_import` 两个独立函数。
- **Mermaid 标签编码**：除转义外，可考虑使用 Base64 编码整个标签内容，彻底避免语法冲突，但会降低可读性。审查时需权衡。
- **asyncio 与批量 SQL**：`reset_all_expired_quotas_atomic` 中使用 `await session.execute(text(...))` 正确，但未检查是否在 `async with session.begin()` 内，确保自动回滚。当前实现虽无问题，但应建议显式使用 `begin()` 提高健壮性。
