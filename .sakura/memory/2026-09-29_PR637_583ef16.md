### 3. 规范完善建议

基于本次审查，建议向《项目记忆》补充以下两条核心规则：

1.  **AI 工具函数索引防御性公理**：
    *   所有涉及大模型输入/外部传入的行号、索引或切片参数（如 `min_idx`, `max_idx`, `start_line`），在进入列表切片或遍历前，**必须做物理钳制（Clamp）**：`0 <= min_idx <= max_idx <= len(sequence)`。禁止依赖 Python 切片静默容错特性，防止出现负数倒序索引切片的非预期行为。
2.  **AI Agent 重试契约（Retry Arguments）显式校验**：
    *   当 Agent 工具返回 `recovery.retry_arguments` 时，单元测试必须断言该重试参数放入工具重新执行后能够 100% 成功，防止重试参数本身依然非法导致大模型陷入 死循环（Infinite Retry Loop）。

### 4. 经验教训与总结

*   **关注切片中的负索引隐性陷阱**：在 Python 中，`lines[-1:]` 不会报错而是取最后一行。如果外部传入负数的 `min_idx` 且没有强校验，会导致搜索结果渲染出文件末尾的无关代码，引发 AI 逻辑混淆。今后审查涉及 Index/Range 相关的修改时，第一反应应校验 `min_idx < 0` 的极限场景。
*   **1-based 到 0-based 映射转换的审计意识**：文件工具在面对 LLM/用户时通常用 1-based 行号，在内部处理时用 0-based 索引。此类 PR 必须重点审查 API 边界的 `+1` / `-1` 转换逻辑是否在异常路径上依然保持一致。
