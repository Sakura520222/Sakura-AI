## 4. 经验教训

### 未来审查要点
1. **配置与消费的对称性审查**：每看到一个新增配置字段，强制扫描其唯一读取位置。
2. **CSRF + JSON API 组合**：成为固定审查项，尤其 WebUI 路由下。
3. **原子操作审查**：`GET + DELETE`、`GET + SET` 等必须优先改成 `GETDEL`、Lua 或事务。
4. **内存 fallback 的可恢复性**：审查时主动询问“重启会丢失什么状态”。

### 对特定技术的经验
- **WebAuthn**：challenge 的原子消费非常重要，重放攻击虽被 counter 缓解，但仍应严格一次性。
- **TOTP fallback**：内存字典在高并发下存在竞争，但 asyncio 单线程模型中可接受 —— 这种边界应明确记录。
- **HMAC vs 哈希**：未来类似场景（恢复码、API key 存储）应优先采用 HMAC 或带 pepper 的 KDF。
