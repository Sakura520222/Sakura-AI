### 3. 规范完善建议

基于本次审查，建议新增或强化以下审查规则：

| 规则 | 严重程度 | 说明 |
|------|---------|------|
| **读写并发必须使用行锁或原子更新** | major | 所有先查后改的计数/库存字段（如 used_count, quota）必须使用 `SELECT ... FOR UPDATE` 或一条 UPDATE 条件语句 |
| **属性注入必须使用字段白名单** | major | 任何使用 `**kwargs` + `setattr` 更新模型属性的位置，必须定义显式白名单 |
| **配置开关必须全链路追踪验证** | major | 新增 `enabled` 类开关时，必须列出所有使用点（路由注册、命令注册、调度任务），否则视为假开关 |
| **唯一约束与查询状态一致性检查** | major | 定义 `UniqueConstraint(user_id, plan_id)` 后，所有 upsert 逻辑必须覆盖所有状态（不仅仅是 ACTIVE），或约束包含 status |
| **fallback 逻辑禁止使用 `any()` 或 `bool()` 判断未记录值** | minor | 判断某字段是否“有值”应使用 `is not None`，而非隐式布尔转换；0 是有效值，不是“未记录” |
| **公共接口的整数参数必须做合法性保护** | minor | 如 page、limit、id 等直接从 request 获取的整数，必须捕获 `ValueError` 并设默认值 |
| **延迟导入必须在文件顶部统一注释说明** | suggestion | 避免多个函数内重复相同导入，提升可读性 |

### 4. 经验教训

**值得在未来审查中关注的要点：**
1. **“新增配额/奖励”字段的完整生命周期**：必须追踪 5 个阶段：发放 → 增加 → 消耗 → 扣回 → 重置。本次 `quota_bonus` 在扣回阶段就出现了 `used > quota` 的过渡态，说明生命周期设计不严谨。
2. **批量操作中的状态更新**：如兑换码批量生成、订阅批量过期，必须使用 `for update` 或乐观锁版本号，避免“幽灵更新”。
3. **第三方库废弃警告**：`datetime.utcnow` 在 Python 3.12 中已废弃，审查建议中应包含升级路径（使用 `timezone.utc` 或 `func.now()`）。
4. **浮点金额运算**：所有货币相关运算应使用整数（分）或 `Decimal`，避免 `float`，尤其是在格式化显示前。

**对特定技术/模式的审查经验：**
- **SQLAlchemy 并发模型**：务必检查 `with_for_update()` 是否在查询执行前调用，并且在同一事务中完成读-改-写。
- **Pydantic + 权限系统**：当 API 接受 `user_id` 参数时，必须与服务层鉴权返回的 `authenticated_user_id` 做比较，防止横向越权。
- **Telegram Bot 中的延迟导入**：通常是解决循环依赖的“无奈之举”，应提示作者考虑使用依赖注入容器或拆分服务模块。
