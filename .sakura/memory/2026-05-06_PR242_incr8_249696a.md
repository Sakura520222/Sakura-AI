## 2. 发现的模式

### 代码模式
- **walrus operator 滥用**：在无需赋值给外部变量的场景使用 `:=`，增加认知负担。模式重复 ≥2 次应提取函数（符合项目记忆“重复逻辑阈值判断”）。
- **函数内 import 分散**：同一文件中 `from ... import` 分散在多处，降低可读性。合理场景（避免循环依赖）应加注释说明。

### 架构观察
- **i18n 集成模式**：采用显式 `lang` 参数传递，而非依赖全局线程局部变量，较健壮。
- **动态配置的 fallback 链**：`翻译 → 预定义字典 → 原始 key`，属于安全的降级策略。
- **依赖方向**：`backend.webui.routes.config` 依赖 `backend.webui.i18n`，符合分层。但项目记忆提醒“跨层导入强制注释”，此处未违反。

### 项目特有风险
- **配置热更新验证缺失**：本次变更未检查新增的 i18n 翻译是否支持运行时语言切换（动态配置修改后页面是否立即生效）。属于项目记忆中的“配置热更新验证”高危区。
