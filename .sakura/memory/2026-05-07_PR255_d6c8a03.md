### 3. 规范完善建议

基于本次审查，建议**新增或强化**以下规则：

#### ✅ 新增：并发去重评估（suggestion 级）
> **场景**：当原本由 worker 队列串行处理的逻辑前置到 webhook（可能并发触发）时，必须评估 **短时间重复事件**（如 synchronize 多次 notify）对上游 API 配额的影响，建议增加短期分布式锁（5-30s）。

#### ✅ 强化：防御性函数的“假阴性”审查（major 级，已有但需细化）
> 现有记忆已提及「防御性调用的假阴性审查」，但需补充：当函数返回 `0` 或 `None` 表示“无操作”而非“失败”时，函数命名应明确（如 `dismiss_if_exists`），且调用方必须有能力区分 **真无操作** 与 **调用失败**（如记录异常类型或响应耗时）。

#### ✅ 新增：webhook 幂等性保护（suggestion）
> 对于可能被 GitHub 重复投递的 webhook 事件（如 synchronize、push），handler 应实现 **基于 `pr_id + event_type + last_event_id` 的去重**，避免同一事件触发多次相同操作。
