## 审查反思

### 1. 审查质量评估

**覆盖度 – 存在重大遗漏**  
PR 描述明确列出“更新 README.md 和 README_EN.md 中的版本徽章”，但实际变更文件清单中完全没有这两个文件。本次审查未识别这一 **幽灵变更**，属于严重覆盖缺失。根据项目记忆中“幽灵变更须强制 PR 描述与审查覆盖一致性校验，遗漏即标 [blocker] 并降级”的规则，此处应标记为 [blocker] 并阻塞审查。本次审查未执行该关键检查，导致信任了不完整的 diff。

**准确度 – 严重程度基本合理，但缺失阻断项**  
标记的 major 问题（静默降级无日志、fix_confidence 范围未校验、死代码常量）均合理，无过度升级或降级。但致命的幽灵变更未被发现，使整体评分（7/10）与决策（approve）过于乐观，实际上有阻断级问题。

**完整性 – 对变更意图理解充分，但一致性校验失职**  
审查者准确理解了“修复建议”功能的目标与实现路径，对配置范式、数据库兼容、格式化分流等好评到位。缺陷在于未将 PR 描述与 diff 进行逐项比对，导致前端文档缺失这一显性不一致漏出，影响完整性。

### 2. 发现的模式

**代码模式**  
- **配置“三件套”范式**：配置项同时注册 Field 定义（含校验）、UI 描述元组、范围约束和中文标签，是项目独有的强规范，值得在后续审查中作为正面模式引用。
- **双路径解析防御**：结果解析器同时覆盖 Markdown（`**建议**:`）和 JSON（`fix_suggestion`/`fix_confidence`）两种 AI 输出格式，体现了健壮的设计。
- **默认降级反模式**：`except Exception` 直接返回默认值而无日志，历史上已被列入项目记忆的“静默降级”规则，但本轮仍出现，提示该模式易反复。

**架构观察**  
- 版本号分散在 `main.py`、`auth.py`、`init.sql` 以及 README 徽章中，缺乏单一来源，未来修改极易遗漏（此次 README 或已遗漏）。
- 修复建议的置信度阈值通过配置中心动态下发，但降级路径在 `comment_service.py` 内硬编码为 0.8，与 `constants.py` 的定义形成双重来源，增加维护成本。

### 3. 规范完善建议

- **新增强制规则：PR 描述与 diff 一致性校验**  
  每次审查必须逐条对比 PR 描述中声明的变更文件与实际 diff，任何不一致均标 [blocker] 并阻塞批准，直至描述修正或 diff 补充。此规则应列入项目记忆的强制步骤，避免幽灵变更持续漏出。

- **强化静默降级检测**  
  对 `except Exception: return default` 模式自动标记，并要求日志输出或显式注释。可增强为：若无 `logger.warning` 且无 `# 降级可接受` 注释，则直接提 major。此条已在记忆中有，但需更工具化的提醒。

- **AI 输出数值范围校验规范**  
  凡从外部模型获取的数值（置信度、分数、阈值等），须在解析后立即做范围 clamping 并记录超限事件。建议在项目规范中明确为安全解析的必备步骤。

- **死代码清理策略**  
  若常量定义但无引用且无注释说明其预留意图，应建议删除或添加未来用途注释。本次 `DEFAULT_FIX_CONFIDENCE` 是典型的死代码，后续审查应主动提示。

### 4. 经验教训

- **幽灵变更检查是审查的守门员**  
  PR 描述中的 README 变更与实际 diff 不符，说明即使简单的版本号升级也可能伴随文件缺失。今后任何版本号改动都必须全文搜索所有硬编码版本号（含 README、Dockerfile、CI 配置等），形成“版本签名全量比对”的固定动作。

- **降级路径的可观测性是底线**  
  即使得分 7/10 的审查，若忽略静默降级无日志的问题，实际部署后将导致无法排查的诡异行为。此类问题应在第一轮就归档为技术债，并附带监控告警建议。

- **配置扩散风险需在审查中显式标注**  
  一个默认值在三处出现（`config.py` Field default、`constants.py` 常量、`comment_service.py` 硬编码）极易导致修改不同步。今后发现类似情况应建议抽取统一来源，至少标记为技术债。

- **审查评分应与阻断项强挂钩**  
  有幽灵变更却仍给出 7 分 approv，说明评分未与阻断项有效链接。建议在评分规则中明确：存在未关闭的 [blocker] 时，最高分不超过 4 分且决策必须为 comment 或 request changes。
