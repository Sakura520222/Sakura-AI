# 代码审查深度反思

## 1. 审查质量评估

### 覆盖度：存在明显盲区

**已覆盖**：数据库性能、数据生命周期、第三方API稳定性、PR描述一致性、测试质量

**遗漏问题**：
- **prompt注入防护深度不足**：审查认可了"不可信标记"实践，但未追问CI输出是否有实际清洗/截断逻辑。仅标记"不可信"无法防御恶意构造的CI日志对prompt的注入攻击
- **并发安全未触及**：`upsert_head_sha_pr_map`在高频webhook下是否有竞态？映射表是否需要唯一约束保护？
- **资源限制缺失**：`output_text`字段无大小限制，CI日志可能达数MB，存储和prompt构建的开销未被评估
- **索引设计空白**：`cleanup_expired`按时间过滤但未验证是否有时间索引，即使修复了全表扫描，无索引仍然是问题

### 准确度：基本合理，有一处可能偏轻

- **[major] 全表扫描**：准确，这是教科书级性能反模式
- **[minor] 映射表无清理**：**可能偏轻**。在活跃仓库中，PR事件频繁，映射表增长速度与CIFailure表相当，长期无限增长应至少是major
- **[suggestion] 私有API**：准确，但缺少"退出策略"的要求

### 完整性：架构理解到位，边界场景不足

准确识别了"webhook→DB→worker→prompt"四层架构和"异常隔离不阻断主流程"的设计意图。但对**为什么需要映射表**（GitHub CI事件的commit sha与PR关联弱）的背景理解可更深入，这能帮助判断映射表清理的优先级。

## 2. 发现的模式

### 代码模式
1. **防御性吞异常**：全链路try/except，保证辅助功能不影响核心流程——与项目既有风格一致，但缺少异常日志的完整性检查
2. **三层降级取值**：payload→映射表→API，典型的"快路径优先"模式
3. **不可信边界标记**：`=== BEGIN/END UNTRUSTED ===` 明确划定信任边界

### 架构观察
1. **弱一致性补偿设计**：映射表存在是为了弥补GitHub API不支持"commit sha反向查PR"的限制，属于典型的API能力不足补偿
2. **辅助功能与核心功能物理隔离**：CI失败分析完全独立于主审查逻辑，失败不传播
3. **事件驱动的数据清理触发点错位**：PR close事件只触发CIFailure清理，遗漏了同生命周期的映射表

## 3. 规范完善建议

### 新增审查规则

| 规则 | 触发条件 | 检查点 |
|------|----------|--------|
| **全表加载检测** | `select(Model)` 无 WHERE | 要求数据量增长评估或改为条件查询 |
| **数据生命周期闭环** | 新增写入逻辑 | 必须同步实现清理/TTL机制 |
| **辅助功能资源上限** | 非核心链路新增存储/处理 | 必须声明大小/时间限制 |
| **不可信输入双重防护** | 标记为untrusted的输入 | 仅标记不够，须验证清洗/截断逻辑 |
| **映射表清理对称性** | 存在A→B映射表 | A清理时必须同步清理映射记录 |

### 项目特有规范
- **CI输出大小限制**：`output_text`应设置硬上限（如100KB），超限截断并标记
- **私有API追踪**：使用`_`前缀API必须添加TODO并注明期望的官方API替代方案

## 4. 经验教训

### 关键教训

1. **"辅助功能"是资源泄漏的高发区**：因为不阻断主流程，往往缺少资源限制意识。本次全表扫描+无大小限制就是典型——**辅助功能更需要资源边界**

2. **映射表清理的"心智盲区"**：开发者关注业务表清理，容易遗忘"补偿性映射表"与业务表同生命周期。审查时应**显式列举所有相关表**，逐一检查清理逻辑

3. **"标记不可信"≠"防护完成"**：安全标记是意识体现，但不是防护本身。对于注入到LLM prompt的场景，必须有**截断+特殊字符转义**的实际处理

4. **测试mock脆弱性是隐性债**：`_MemoryDb`依赖参数名匹配，SQLAlchemy版本升级会导致测试静默通过但行为错误——**mock应尽可能基于行为而非实现**

5. **性能问题的"时间炸弹"特征**：全表扫描在小规模时无感知，问题爆发往往在数据积累后。审查时应问：**"这条路径被调用时，表里可能有多少数据？"**

### 未来审查聚焦点

- 事件驱动架构中，**事件触发的清理逻辑是否覆盖所有关联实体**
- 任何"内存端过滤"的代码，**默认视为性能风险**直到证明数据量有界
- LLM prompt构建链路中，**所有外部输入必须有截断和清洗**，标记不可信是加分项不是替代项
