### 3. 规范完善建议

*   **新增/修改审查规则**：
    *   **规则名称**：外部依赖版本解耦的“前缀安全”校验。
    *   **规则内容**：当测试代码试图解除对第三方依赖（如 GitHub Actions, Docker 镜像）的精确版本锁定以支持自动更新时，**禁止**使用过于宽泛的匹配（如仅 `@` 或 `:`），必须强制要求包含版本类型标识的前缀（如 `@v` 或 `:v`）。
    *   **理由**：防止因断言过松导致非生产环境引用（如 `@main`, `@dev`）被意外放行进入生产流程，违背了“允许版本动态更新但保持版本化引用”的初衷。

*   **项目特有规范**：
    *   **Workflow 测试断言规范**：建议在项目 CONTRIBUTING 或测试规范中明确，对于 Actions 的引用检查，标准写法应为 `startswith("actions/xxx@v")`，既解耦了具体版本号，又规避了分支引用风险。

*   **未来审查关注要点**：

*   **特定技术审查经验**：
