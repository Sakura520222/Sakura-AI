## 4. 经验教训

### 未来审查关注点
- **字段重命名的涟漪效应**：修改变量名时，必须检查：
  1. 该变量的所有读取位置（日志、返回值、JSON 字段）
  2. 导入该函数的所有模块
  3. API 契约（前端/客户端是否依赖旧字段名）
- **事务回滚的副作用**：审查 `rollback()` 时，追问：
  - 是否会影响同一 session 上的其他未提交操作？
  - 调用方是否依赖前序操作的中间状态？
- **异步 session 恢复的完整性**：`rollback()` 后 session 可能仍处于 `inactive`，需要 `expunge_all()` 或重新 `begin()`。建议统一使用 `async with session.begin():` 模式。

### 技术特定经验
- **SQLAlchemy 异步 session 陷阱**：捕获 `SQLAlchemyError` 后 session 自动标记为 `inactive`，仅 `rollback()` 可恢复，但 `rollback()` 会丢弃所有未提交变更。替代方案：使用 `session.begin_nested()` 实现 savepoint。
- **返回值与变量名解耦**：若函数返回“业务标识”，建议直接命名为 `task_key`，避免下游误用为 UUID。项目已做此纠正，应推广。
