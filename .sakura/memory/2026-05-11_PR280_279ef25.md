### 二、发现的模式

#### 🔁 代码模式
1. **防御性不足的字符串匹配**：
   - `_is_model_not_found_error` 依赖错误文本片段
   - `startswith` 用于路径校验（Windows 大小写问题）
   - **反模式**：应优先使用结构化字段（HTTP 状态码、错误码）而非文本匹配。

2. **短生命周期 Session 滥用**：
   - `_update_task`/`_load_task` 每次创建新 session，在 `process_task` 中创建 6-8 次
   - **改进方向**：引入 `contextlib.asynccontextmanager` 管理 session 生命周期

3. **两套执行体系的演化痕迹**：
   - 旧版硬编码 handler 映射 → 新版注册表模式
   - **经验**：重构时应先标记 `@deprecated` 并等待 1-2 个版本后再删除

#### 🏗️ 架构观察
- **插件化设计较好**：工具系统、Skill 加载、AI Client 均支持扩展
- **安全层次分明**：路径屏蔽 + Shell 命令黑名单 + 敏感字段脱敏
- **但存在"伪安全"**：
  - `.git/` 路径被文件工具屏蔽，但 `git config` 可通过 Shell 执行器修改配置 — **不一致的安全边界**
  - Skill 的路径遍历检查用 `startswith` 而非 `resolve().relative_to()` — **绕过风险**

### 三、规范完善建议

#### 📌 建议新增的审查规则

| 规则 | 级别 | 说明 |
|------|------|------|
| **错误检测优先使用结构化字段而非错误文本** | major | 如 HTTP 状态码、错误码，避免文本匹配的脆弱性 |
| **Worker 中的同步 I/O 必须用 `asyncio.to_thread` 包装** | major | 防止阻塞事件循环（已在审查中提及，但未写入规范） |
| **新增 DB 模型的字段必须明确是否可空 + 默认值语义** | minor | 避免 naive datetime 与 aware datetime 混用 |
| **两套以上相似实现必须标注 `@deprecated` 并设置删除期限** | major | 防止维护债务累积 |
| **取消/中断必须实现传播机制（非仅 DB 状态）** | major | 使用 `asyncio.Event` 或 `Task.cancel()` |

#### 🔧 项目特有规范强化
- **路径安全校验统一模板**：
  ```python
  # ✅ 推荐
  target.resolve().relative_to(base_dir.resolve())
  # ❌ 禁止
  str(target).startswith(str(base_dir))
  ```
- **审计日志的旧状态必须在修改前保存**：可作为静态检查模式（检测 `record old_status` 前是否有状态修改）
- **Session 复用检查**：在 `async with async_session() as session:` 出现超过 3 次且在同一函数内时，应警告

### 四、经验教训

#### 🎯 未来审查关注要点
1. **变更意图 vs 实际实现的偏离**：
   - PR 描述提到"增强安全措施"，但实际缺少命令白名单实现（仅配置存在未使用）
   - **应对比 PR 描述与实现的差距**

2. **"仅配置未使用"的幽灵功能**：
   - `agent_team_test_command_allowlist` 配置存在但 `shell_executor` 未实现
   - **经验**：新增配置时必须同步消费逻辑或注释为"预留"

3. **异步任务的取消链条完整性**：
   - 从 WebUI → API → Worker → AI 调用 → Shell 命令，每一层都必须支持取消
   - 本次审查只发现 DB 状态修改，未向上追溯 HTTP 连接取消是否传播

4. **增量审查中存量债务的升温机制**：
   - 本次审查发现了多处重复逻辑（fullstack_expert vs professional_reviewer）
   - **建议**：若同一债务连续 2 次 PR 未处理，应自动生成 issue 并标记优先级

#### 🔬 特定技术/模式的审查经验
- **Operator 优先级 bug 的检测**：
  - 当看到 `and`/`or` 混合且无括号时，建议运行 `pylint --py3k` 或 `ruff` 的 `W0130`（混合逻辑运算符）
  - **可推广到静态分析规则**

- **datetime 时区陷阱**：
  - 项目中已经明确禁止 `utcnow()`，但审查时仍出现在新增代码中 → 说明：
    - 开发者未遵守规范
    - 代码审查工具未自动拦截
  - **建议**：pre-commit hook 中加入 `grep -n "datetime.utcnow"` 检查

- **`or ""` 的布尔陷阱**：
  - `value or ""` 会在 `value=False` 或 `value=0` 时错误替换
  - **经验**：对于动态配置读取，统一封装 `get_dynamic_config_str` / `get_dynamic_config_int`，避免手写 `or`
