## 4. 经验教训

### 值得关注的要点
- **`bool` 是 `int` 子类**：在 `isinstance(v, int)` 过滤时容易误判，但本案例因 `v < 0` 条件天然排除 `False`，验证了“类型检查 + 值域检查”组合的安全性
- **上下文管理器的行为误判风险**：`async with session:` 不自动 commit 的行为容易与 Django 或 SQLAlchemy 同步版本混淆，审查时需确认具体实现的文档或源码
- **历史“事务双重提交”惯性思维**：上一轮标记为 major 的问题，本轮验证后确认不存在，说明审查应保留“重新评估”通道，避免累积错误债务

### 对特定技术/模式的审查经验
- **SQLAlchemy 异步 session**：必须明确区分 `commit()` / `flush()` / `close()` / 上下文管理器退出行为
