# 深度反思：PR #202

## 1. 审查质量评估

### 覆盖度：存在结构性遗漏

审查覆盖了核心逻辑路径，但**遗漏了 PR 描述中明确提到的两个改动点**：
- `get_sakura_branch` 新增公开方法——完全没有审查其接口契约、错误处理、返回值语义
- `adjust_workflow` 调用 `initialize(prepare_only=True)` 的改动——未覆盖

这违反了**"PR描述中的改动点必须逐一覆盖"**的基本原则。公开接口遗漏尤其危险，因为 `get_sakura_branch` 是新增的外部消费入口。

此外，**并发安全**完全未提及：`_find_open_sakura_branch`（查找）与 `_commit_to_branch`（提交）之间存在 TOCTOU 竞态，两个并发请求可能找到同一分支后同时追加提交。虽然实际概率低，但作为"查找-then-操作"模式应有意识地评估。

### 准确度：严重程度系统性高估

三个 `[major]` 标记全部不符合**三问法**：

| 标记点 | ①实际bug？ | ②运行时错误？ | ③安全风险？ | 应有级别 |
|--------|-----------|--------------|-------------|---------|
| `last_sha` 静默返回 | 否（边界降级） | 否 | 否 | suggestion |
| base_branch 不一致 | 边界条件触发 | 否 | 否 | suggestion |
| 30条限制 | 审查自评"风险较低" | 否 | 否 | suggestion |

审查正文已经给出了正确的定性（"小概率边界情况"、"风险较低"），却在标签上升级为 major，**正文与标签自相矛盾**。这说明三问法在标记时被跳过了。

### 格式硬违规

- **分区标签解耦**：三个 `[major]` 全部出现在 `🟡 建议（可选）` 分区下，直接违反"建议（可选）禁止 major/critical"规则
- **评论重复膨胀**：主要评论区将审查摘要的每条建议逐条复制，且部分条目被拆成两条（如 `github_write_service.py:145` 和 `:147` 是同一问题），信息增量归零
- **截断评论**：多条 `[suggestion]` 评论在"**"处截断，属于输出异常

## 2. 发现的模式

### 代码模式
- **错误处理策略分裂**：`_commit_single_file` 抛异常 vs `_commit_to_branch` 静默降级，同一服务内两种风格共存
- **布尔参数控制行为**：`prepare_only=True/False` 改变方法返回值类型（`dict | None`），这是典型的职责模糊信号

### 架构观察
- GitHub 写操作的分层：`_commit_single_file`（原子操作）→ `_commit_to_branch`（分支追加）→ `_commit_via_pr`（PR流程编排），层级清晰
- 状态管理集中在 `sakura_memory_service`，与 GitHub 操作分离，职责边界合理

## 3. 规范完善建议

### 新增规则
1. **PR描述覆盖度校验**：审查完成后，必须将 PR 描述中的每个改动点与审查评论做映射，未覆盖的点必须显式说明原因或补充审查
2. **公开接口强制审查**：新增的 public 方法/属性必须在审查中至少包含：契约定义、错误处理、返回值语义三个维度的评估
3. **TOCTOU模式识别**：发现"先查询后操作"的代码模式时，必须显式评估并发风险（即使结论是"可接受"）

### 强化规则
4. **三问法与标签绑定**：`[major]` 标签前必须内联三问法的判断结果，不通过则降级。本次三个 major 如果强制执行此规则，全部会在标记阶段被拦截
5. **自评矛盾检测**：当正文出现"风险较低""小概率""边界情况"等措辞时，自动触发标签复核——这些措辞与 major 语义冲突

## 4. 经验教训

### 策略选择失误
项目记忆明确记录了**"首次审查vs quick策略：文件复杂度应作为策略选择约束"**。本次是首次全量审查，+134/-21 行，涉及并发敏感的分支查找-提交流程，quick 策略导致覆盖度不足。**应基于变更的"风险密度"而非"代码量"选择策略**。

### 边界情况≠Major 的认知固化为行动
三问法写在了记忆里，但执行时被跳过。根本原因是**标记阶段缺乏强制检查点**。需要将三问法从"心法"升级为"检查清单"——每写一个 `[major]`，必须先写出三问的答案。

### 评论重复是信息噪音
主要评论区复制粘贴审查摘要，既不增加信息量，又稀释了真正重要的评论。**评论应只包含需要作者关注的具体行动项**，总结性内容放在摘要区即可。这与记忆中的"遗留确认式疲劳"是同一问题的不同表现形式。
