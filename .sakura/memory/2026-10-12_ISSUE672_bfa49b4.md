### 6. 经验教训与改进建议

1. **客户端与服务端职责边界的“零信任”防线（项目记忆对齐）**：
   - 需注意项目记忆中的原则：“准入零信任：计费/执行准入上下文由服务端强行覆盖，禁止信任客户端传参”。
   - 在推进 IDE 协议设计时，必须在 Service 层强制校验用户对目标 Worktree 的真实写权限与分支合法性，防止外部客户端通过定制 API 请求篡改 Agent 执行上下文。
2. **多阶段任务（Epic）的落地阻断防范**：
   - 涉及 API 重构下沉时，必须遵循“无破坏性演进”，防止破坏现有 WebUI 的正常交互。新 API 需在独立的 `/api/v1/` 空间内与 Bearer Token 鉴权一同落地，保障版本隔离。
3. **标签体系建议引入 `epic` 与模块级 Tag**：
   - 对于估算工作量在 2 周以上、跨多个阶段的 feature，后续建议优先补全 `epic` 和受影响子模块（如 `module:agent-team`）标签。
