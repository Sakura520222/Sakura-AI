## 4. 经验教训

### 未来审查关注要点
- **副本内容一致性检查**：当注释说“复制自 xxx”时，必须 diff 对比源与副本的实际代码，防止注释说谎。
- **临时方案的生命周期追踪**：TODO 必须包含 issue ID 或目标版本，否则容易永久滞留。
- **增量审查的“债务升温”检测**：同一问题在第3轮仍只被注释缓解而非修复，应主动标记为“需在下个PR强制重构”。

### 特定技术审查经验
- **Tailwind + 自定义 CSS 混合**：脆弱选择器（如 `main .bg-white`）极易被 Tailwind 类名变更破坏，建议团队优先使用 `@apply` 或统一提取为组件类。
- **backdrop-filter 双重应用**：审查时需扫描元素上是否同时存在 `.glass` 和半透明背景类（如 `bg-white/80`），两者叠加会导致滤镜双倍。
- **@supports 回退的完整性**：必须同时覆盖亮色/暗色模式，且回退背景颜色需与正常情况下的视觉权重一致。
