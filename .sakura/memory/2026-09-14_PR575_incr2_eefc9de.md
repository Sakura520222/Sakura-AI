## 3️⃣ 规范完善建议  

1. **锁文件强制同步规则**  
   - **规则名称**：`lockfile_sync_enforced`  
   - **内容**：每次修改 `pyproject.toml` 或 `requirements.txt` 必须在同一个 PR 中执行 `uv lock --output uv.lock`，CI 必须通过 `uv lock --check`。若未检测到 `uv.lock` 变更，审查自动阻断。  

2. **子项目依赖一致性检查**  
   - **规则名称**：`subproject_dependency_alignment`  
   - **内容**：根项目与所有子项目（如 `sandboxer/`, `updater/`）的关键依赖版本必须保持 **>=** 根项目的最低约束；CI 增加脚本 `scripts/check_sub_deps.py`，在 PR 合并前强制通过。  

3. **systemd 单元安全属性强制**  
   - **规则名称**：`systemd_security_hardening`  
   - **内容**：所有自定义 unit 必须显式声明 `ProtectSystem=full`、`ProtectHome=yes`、`ReadWritePaths=/var/run/...`，并在代码审查模板中提供检查清单。  

4. **Shell 脚本错误码统一**  
   - **规则名称**：`shell_exit_code_consistency`  
   - **内容**：所有 `*.sh` 脚本的函数必须 `return` 具体错误码，脚本主体统一使用 `set -euo pipefail` 并在 CI 中运行 `shellcheck`。  

5. **增量审查元数据排除**  
   - **规则名称**：`metadata_increment_exclusion`  
   - **内容**：审查工具在增量模式下自动忽略 `.sakura/memory/*`、`.sakura/knowledge/*` 等纯文档路径，只聚焦代码与关键配置文件。

## 4️⃣ 经验教训  

| 教训 | 说明 |
|------|------|
| **锁文件不可忽视** | 依赖升级后即使代码通过，锁文件过期会导致发布流水线失败。审查时必须确认 `uv.lock` 已更新并同步到仓库。 |
| **子项目版本漂移是隐形风险** | 根项目升级后，子项目仍保留旧约束会在运行时触发 `ImportError` 或兼容性错误。建议在 CI 中统一校验所有子项目的依赖树。 |
| **系统级安全细节需专门审查** | `systemd` 单元的 `PIDFile` 写入防 symlink 攻击是好实践，但还应检查 **权限、所有权、文件路径的可写性**，防止被恶意进程篡改。 |
| **增量审查的盲区** | 只审查增量提交容易遗漏 **全局性**（如锁文件、子项目依赖）的问题。结合 **全库快照审查** 能弥补此缺口。 |
| **文档与代码同步** | 本次 PR 同时更新了大量文档，说明团队对“可追溯性”有需求。建议在审查流程中加入 **文档覆盖率检查**（如 `docstr‑coverage`、`markdown‑lint`），确保文档不落后。 |
