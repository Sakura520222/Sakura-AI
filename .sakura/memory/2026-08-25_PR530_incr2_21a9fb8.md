**四、经验教训**

1. **能力驱动优于硬编码**：本次改动展示了通过显式能力集合解决功能回退的优势，后续所有功能开关建议统一迁移到能力声明层。  
2. **元数据同步是隐蔽风险点**：压缩器在回退路径未同步模型名称导致的 bug 说明，任何跨层状态（如模型名、能力集合）在多路径代码中必须保持一致。  
3. **测试是防回归的唯一保险**：新增的 74 行测试覆盖了多种边界（空字符串、覆盖能力、压缩回退），在类似功能修复时应保持此高覆盖率。  
4. **增量审查不等于全局审查**：虽然本次 PR 只改动了 7 个文件，但涉及的模型能力在全库多处被引用，审查时仍需做一次 **全库搜索**（`grep served_capabilities`）以确认无遗漏。  
5. **回退逻辑必须显式标记**：代码中仍保留 “模型名前缀匹配” 作为兼容路径，建议在注释或文档中标注 “TODO: 未来删除”，防止长期遗留导致技术债。
