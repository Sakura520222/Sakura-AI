## 4. 经验教训

### 未来审查重点关注

1. **配置系统的“对称性”三件套**：
   - 写入路径 → 缓存失效
   - 配置字段 → 唯一消费方（或明确预留注释）
   - 默认值 → 与现有行为兼容

2. **常量外迁后的“别名寿命”检查**：  
   当旧别名保留时，应确认是否所有调用方可以直接替换，否则会形成“僵尸别名”。

3. **测试隔离的脆弱性**：  
   修改全局单例的测试即使在 finally 恢复，也可能因异常中断污染后续测试。优先推荐 `monkeypatch` 或 fixture 作用域隔离。

### 对特定技术/模式的审查经验

- **Pydantic Settings + DB 动态配置并存**：必须要求 PR 描述中明确“哪个配置源优先”以及“是否支持运行时覆盖”。本次 PR 未说明，导致审查难以判断幽灵配置是否为预留设计。
- **frozenset 常量与 docstring 同步**：每当修改常量的成员集合，必须更新所有引用该常量的函数的 docstring。可以建议项目引入自动化检查（如 `pytest` 执行 docstring 示例）。
