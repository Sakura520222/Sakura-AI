# Shell/Agent工具输出与安全规则

## 输出双层限额

Shell/Agent工具的输出必须执行双层限额控制：

1. **执行阶段限额**：子进程执行时限制输出大小，防止 `capture_output` 阶段内存膨胀。仅在返回前截断不足以防止子进程输出耗尽内存。
2. **模型上下文阶段限额**：tool result 进入LLM前统一大小控制，防止token成本溢出、上下文污染和prompt injection。

## 命令日志安全

- Shell命令、URL、header、环境变量进入日志前必须：限长；对 `token`/`password`/`key`/`secret`/`Authorization` 做模式脱敏；避免 info 级别记录完整敏感内容。
- 从 `command[:60]` 改为完整 `command` 看似可观测性增强，实际可能扩大敏感信息暴露面，属于安全变更。

## Shell安全边界完整性

白名单命令名不等于整条命令安全。审查必须检查：
- 命令替换：`$()`、反引号 `` `cmd` ``
- 进程替换：`<(...)`、`>(...)`
- 控制符：`;`、`&&`、`||`、`|`、后台 `&`
- 重定向：`2>&1` 等

## 安全解析函数测试

- 安全解析辅助函数（如 `_shell_meta_block_reason`）必须有直接单测，覆盖合法、非法、边界、转义、引号组合。
- 不能仅依赖集成测试验证安全逻辑。

## 多执行路径一致性

- 同类Shell执行能力存在多条路径时（如 `ShellTool` 与 `tool_executor._handle_run_command`），必须验证安全策略和输出策略一致。
- 不同路径的截断策略、安全检查应统一，避免行为不一致。
