# Python 重构审查规则

## 1. 循环约束的等价替换验证
- **显式移除必须有等价约束**：当移除代码中的显式循环计数器（如 `for i in range(max)`）时，必须强制要求审查者验证是否存在等效的退出条件（如 `asyncio.wait_for`、`deadline` 或信号量）
- **强制检查点**：LLM Agent 调用循环、重试逻辑、长轮询
- **LLM 应用风险**：在 LLM 应用中，`while True` 配合模型自决退出极度危险，必须保留物理硬约束

## 2. 配置项活跃性强制验证
- **消费点必须明确**：新增或保留配置项时，必须提供其在非配置代码中的读取路径（即"消费点"）
- **废弃标记要求**：对于"仅用于文档"或"预留"的配置，必须有明确的 `TODO` 或废弃标记
- **工具化建议**：建议引入 lint 脚本，扫描 `Settings` 类中的属性是否在 `services/` 或 `workers/` 中被实际读取
- **僵尸配置识别**：如 `agent_team_max_runtime_minutes` 这种"只定义不使用"的配置属于僵尸配置，应明确标记或删除

## 3. 文档与代码的"单向真值"原则
- **代码为唯一依据**：文档（包括注释）不可作为代码行为的验证依据
- **验证要求**：审查时，若文档声称"由超时兜底"，必须在代码中找到对应的 `timeout` 参数实现，否则判定为 Bug
- **警惕"注释撒谎"**：注释声称有兜底机制，实际上却不存在的现象比逻辑错误更难排查

## 4. Python 版本一致性检查
- **禁止 Python 2 语法**：新引入代码不得包含 `except Exception, e:`、`print` 语句、旧式字符串格式化等
- **版本混用风险**：项目可能混用不同 Python 版本的代码片段，需警惕
- **扫描范围**：对于任何 Python 代码变更，审查时应扫描是否存在已废弃的 Python 2 语法

## 5. 基础模块导入链验证
- **强制验证要求**：对于定义了被广泛依赖的基类、抽象层、工具函数的 PR，审查时必须强制进行导入链的静态或简单动态验证
- **验证内容**：
  - 基础模块本身能否被正常导入
  - 1-2 个直接依赖该模块的关键上层模块能否正常导入
- **理由**：基础模块的缺陷会产生放射性影响，阻断整个功能链

## 6. 复杂逻辑表达式可读性
- **括号强制要求**：在"代码清晰度"相关审查要点中，明确增加：**当 `and`、`or` 与 `not` 等运算符混合使用超过两级时，必须使用括号明确运算分组**
- **防御性编程**：即使运算符优先级可以确保结果正确，显式括号可提升可维护性

## 7. "消失的守卫"模式识别
- **重构陷阱**：在简化配置时，倾向于移除"显式的计数器/边界"（如 `max_tool_iterations`），将其替换为"隐式的全局约束"（如 `timeout`），但在实施过程中往往只完成了移除，而遗漏了新约束的实现
- **审查重点**：警惕那些打着"简化/重构"旗号移除关键安全检查的变更

## 8. 重构安全边界保护
- **安全边界不可移除**：重构的副作用可能是破坏了安全边界。审查者需要警惕移除关键安全检查的变更
- **控制流边界条件优先**：在 AI Agent 类项目中，控制流的边界条件审查应置于最高优先级
