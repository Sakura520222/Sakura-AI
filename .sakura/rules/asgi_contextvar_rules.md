# ASGI ContextVar 生命周期规则

## 核心问题

ContextVar 在 ASGI 并发模型下的隐式依赖传播会导致行为难以预测和调试。

## 强制规则

### 显式依赖声明
- **禁止隐式依赖**：核心服务不得通过隐式传播的上下文变量获取依赖（如数据库连接、认证信息）
- **依赖注入优先**：必须通过函数参数显式传递所需依赖，使依赖关系清晰可追踪

### Supervisor 管理
- **单一守护者原则**：后台任务的创建和生命周期管理必须通过中心化的 supervisor 实例
- **禁止多头管理**：不得绕过中心化守护者直接创建或管理后台任务，避免状态不一致

### 关闭路径安全
- **关键操作保护**：DROP TABLE、DELETE 等破坏性操作前必须验证所有相关任务已完全停止
- **关闭顺序验证**：必须按依赖关系逆序关闭资源（子任务 → 父任务 → 主流程）
- **强制一致性检查**：关闭前必须验证系统状态，避免部分任务仍在写入导致数据损坏

### 并发安全性
- **线程隔离**：在同步上下文中使用 `get_running_loop()` 创建任务时必须评估线程安全性
- **上下文拷贝**：跨任务传递 ContextVar 时必须显式调用 `copy_context()`，避免意外共享

## 审查清单

- [ ] 核心服务是否显式声明所有依赖
- [ ] 后台任务创建是否通过统一 supervisor
- [ ] 破坏性操作前是否有任务停止验证
- [ ] ContextVar 使用是否有文档说明传播范围
- [ ] 跨任务传递是否处理了上下文隔离
