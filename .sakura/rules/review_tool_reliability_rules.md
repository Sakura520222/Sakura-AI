# 审查工具可靠性规则

> 来源：PR454、PR456 审查反思，2026年8月

## 一、工具失效模式

近期审查中两次出现审查工具完全无法产出有效输出的情况（`AI review output could not be validated: expected <SUGGESTION>` / `expected <FINDINGS>`），导致审查质量归零。

### 失败根因
- 输出格式校验失败（规则引擎未触发或输出格式转换错误）
- 结构化输出中核心元素缺失（FINDINGS、评分、决策理由）
- quick策略下的最小输出集未被生成

## 二、降级输出强制规范

当主审查路径因内部错误失败时：
1. **必须产出降级结果**：包含唯一错误码（如`REVIEW_FAILED_<timestamp>`）、失败原因声明、"需人工复核"标记。
2. **禁止静默错误**：不可让系统陷入"输出验证失败"的无输出状态。
3. **最小降级输出集**：评分`N/A`、决策`COMMENT`（需人工复核）、声明"因[具体原因]审查未完成"。

## 三、审查工具自检清单

每次输出前必须执行：
- [ ] FINDINGS是否为空？若空则说明检查了什么、确认了什么
- [ ] 评分是否在策略允许范围内（quick≤8/10）
- [ ] 决策（approve/comment/request_changes）是否与发现的风险等级一致
- [ ] 负面检查是否已执行（即使结论是"无问题"）
- [ ] 证据链是否完整（grep命令+结果、CHANGELOG核对记录）

## 四、核心原则

- 审查工具是"助手"不是"替代者"，工具自身出错时引入的成本高于简单人工审查
- 规则执行的强制性优于规则数量的丰富性——现有规则被100%执行比新增规则更重要
- 审查系统的输出本身也是质量指标，需要监控和持续改进
