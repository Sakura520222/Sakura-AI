# 异步上下文与生命周期规则（PR#479教训）

## ContextVar 使用规范
- **显式注入优先于隐式传播**：在需要实现"静默停止"、"优雅关闭"等功能时，必须通过显式注入（参数传递）或绑定全局且明确的 supervisor 实例（如 `app.state`），禁止在关键路径中依赖隐式的 `ContextVar` 传播
- **ContextVar 全上下文审计**：对于使用 ContextVar 传递服务依赖的代码，必须审查其所有可能的调用上下文（lifespan、HTTP请求任务、后台线程/任务），明确标注依赖来源并验证一致性
- **后台任务 supervisor 一致性**：所有后台任务的创建必须使用统一的 supervisor 实例，禁止出现"多头管理"（即不同任务使用不同的 supervisor 实例）

## 关键操作排他性规则
- **资源清理/重置操作的全路径覆盖**：涉及 DROP TABLE、状态重置等关键操作时，必须审查所有并发访问或操作目标资源的路径，确保所有相关任务都被统一管理和监控
- **"停止"比"启动"更难**：审查必须格外关注资源的清理和关闭路径。启动错误通常导致服务不可用，但关闭错误（如任务未停止就删表）可能导致**数据损坏**

## ASGI 并发模型审查要点
- **执行上下文意识**：审查时必须主动思考"这段代码会在哪个执行上下文中运行？它依赖的上下文从哪里来？"
- **架构意图必须显式实现**：PR描述中的架构意图（如"受控的重置流程"）必须映射到代码的**显式控制结构**上，隐式假设在大规模重构中极易被打破
- **增量审查的影响范围扩散分析**：涉及核心并发机制的变更，强制进行影响范围扩散分析，不仅限于 diff 本身
