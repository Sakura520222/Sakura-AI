# 大规模工具链更新审查规则

## 适用场景

当 ruff.toml、.pre-commit-config.yaml、CI 工作流、Python 版本等工具配置发生重大变更时。

## 强制审查项

### 配置合理性审计
- **规则白名单审计**：新增/忽略的规则是否与项目架构匹配
  - 异步代码（BLE、TRY 类规则）
  - 日期时间处理（DTZ 规则）
  - 代码简化（SIM 规则）
- **与设计文档对齐**：配置须逐项验证与设计文档中的决策和验证标准一致
- **规则冲突检查**：评估与 mypy、black 等其他工具是否存在规则冲突

### 变更等价性验证
- **非纯格式化变更**：引入 `asyncio.to_thread()` 等有运行时影响的修改须提供行为不变证据
  - 性能影响说明
  - 错误处理变更
  - 并发行为差异
- **禁止仅依赖测试**："测试通过"不等于语义等价，须提供独立的验证说明

### 依赖兼容性验证
- **Python 版本升级**：3.11 → 3.14 等跳跃升级须验证所有核心依赖（SQLAlchemy、FastAPI、Pydantic）的官方支持状态
- **工具大版本升级**：ruff v0.15 → v0.16 等须逐条核对 Breaking Changes
- **CI 依赖检查**：GitHub Actions、Docker 等升级须验证废弃参数未被使用

### 忽略规则决策记录
- **强制理由说明**：任何被加入 `ignore` 列表的规则必须附带简短理由
- **临时标记**：暂时忽略的规则须标注预期解决时间

## 审查层次

1. **配置层**：ruff.toml、CI 配置是否正确、合理、完备
2. **变更层**：批量修复是否引入语义改变
3. **影响层**：依赖兼容性、开发环境、文档一致性

## 常见陷阱

- 确认偏误：高评分 + 全部通过测试 → 忽略配置合理性
- 工具盲区：只验证规则执行，不验证规则选择
- 兼容性遗漏：CI 通过不代表所有依赖已支持新版本
