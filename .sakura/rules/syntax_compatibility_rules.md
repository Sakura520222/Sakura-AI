# Python 版本兼容性与基础正确性规则（PR#477教训）

## Python 2/3 语法扫描
- **变更必须扫描废弃语法**：任何 Python 代码变更，审查时应扫描是否存在已废弃的 Python 2 语法：
  - `except Exception, e:` 逗号语法 → 必须使用 `except Exception as e:`
  - `print` 语句 → 必须使用 `print()` 函数
  - 旧式字符串格式化 `%` → 推荐 f-string 或 `.format()`
  - `unicode`、`long` 等内置类型引用
- **新引入代码零容忍**：新代码中出现 Python 2 语法属于 critical 级别，必须阻断合并

## 基础模块导入链验证
- **被广泛依赖的基类/抽象层必须验证导入**：对于定义了被多个模块依赖的基类、抽象层、工具函数的 PR，审查必须强制进行导入链验证：
  1. 基础模块本身能否被正常导入
  2. 1-2 个直接依赖该模块的关键上层模块能否正常导入
- **语法错误的放射性影响**：基础模块的语法错误会阻断整个功能链，审查对"基础模块"应给予最高优先级

## 可读性规范强化
- **复杂逻辑表达式必须使用括号**：当 `and`、`or` 与 `not` 等运算符混合使用超过两级时，必须使用括号明确运算分组，即使运算符优先级可以确保结果正确
- **防御性编程推广**：代码首先是写给人看的，即使编译器/解释器能正确理解，也应使用显式括号提升可维护性

## 大规模变更审查策略
- **优先聚焦基础框架**：对于首次全量审查的巨型 PR，审查者应优先聚焦于基础框架、核心抽象层和关键配置
- **不轻信测试结果**：对于包含大规模新增代码的 PR，审查者不应完全采信其自述的测试结果，应追问测试环境与本地开发环境的一致性
