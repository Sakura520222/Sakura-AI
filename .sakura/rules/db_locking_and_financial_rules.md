# 数据库探测锁与财务事务边界规则

## 一、行级写锁探测防线 (Locking Probe on Indexed Columns Only)

### 1.1 显式索引要求与范围锁放大防御
1. **外键与过滤列索引强校验**：任何在事务中执行 `SELECT ... FOR UPDATE` 或 `EXISTS(...) FOR UPDATE` 的防删探活或引用校验查询，其过滤列（如 `user_id`）**必须具备显式单列或前缀索引**。
2. **严禁无索引列直接行级加锁**：若关联模型外键无索引，严禁直接使用 `with_for_update()` 探测。无索引扫描在 MySQL 等引擎下会退化为全表扫描并施加全表 Next-Key 锁，导致核心业务并发事务严重阻塞。
3. **安全替代方案**：若未建立索引，须优先改用只读快照读探测（非锁定读），或在同一 PR 中补齐数据库迁移索引后再施加行级排他锁。

## 二、网关交互与财务计算零副作用硬防御

### 2.1 财务与配额操作入口短路 (Zero-Side-Effect Guard)
1. **预检与换算前置于写操作**：涉及外部支付网关、钱包扣费、积分消耗、退款差额等有副作用的操作，必须在**生成意图记录、扣减 Credits、占用幂等键之前**完成精度换算、边界校验与可用性预检。
2. **校验失败即刻 Fail-Closed**：若输入或计算结果非法（如 `gateway_delta <= 0`），必须在入口处即刻 Fail-Closed 返回，严禁产生持久化脏单据或无效的幂等流水记录。
3. **未决状态补偿释放一致性**：对长周期调度任务，必须在未执行中断分支处显式执行配额/资金预留释放，确保资金账实相符。

## 三、长链路异步 Worker 持久化派单双栅栏原则

### 3.1 消费抢占与防重入设计
1. **DB 行锁条件更新 (第 1 道栅栏)**：长链路异步 Worker 消费持久化派单载体（Carrier）时，必须通过 DB 事务内的行锁与条件更新（如 `state == 'pending' -> 'processing'`）抢占任务状态，防止多实例并发重复拉取。
2. **本地内存句柄验伪 (第 2 道栅栏)**：抢占成功后，须在当前进程执行内存判重或令牌校验，防范同进程重复调度与重入污染。
